## 1.1 一句话定位

**OpenSquilla 是一个 token 高效的微内核 AI 代理运行时**——它像一个"AI 管家"，能在终端、网页、飞书/Slack/Telegram 等各种聊天工具里帮你干活，并且自动选择最便宜的 AI 模型来省钱。

> 来源：pyproject.toml L5, README.md L3, README.product.md L1-L3

## 1.4 核心价值（解决 7 个痛点）

| 痛点 | OpenSquilla 的方案 | 大白话解释 | 关键模块 |
|------|-------------------|-----------|---------|
| AI 模型太贵 | SquillaRouter 本地路由：简单问题用便宜模型 | 近距离骑共享单车，远距离才叫专车 | SquillaRouter |
| 每次都要重新教 AI | 持久化记忆系统：记住偏好、项目上下文 | 私人助理，不用每次都重新介绍 | Memory |
| 多个 AI 工具来回切换 | 统一入口：CLI / Web / 飞书 / Slack | 同一个管家，多种联系渠道 | Gateway + Channels |
| 重复劳动太多 | 技能系统 + 定时任务：多步操作打包 | 手机快捷指令，一键完成 | Skills + Scheduler |
| AI 操作不安全 | 分级沙箱 + 审批机制：危险操作需确认 | 银行转账需要密码确认 | Sandbox + Approval |
| AI 提供商不稳定 | FallbackPolicy：自动切换备用模型 | 一家餐厅关门，自动去隔壁 | FallbackPolicy |
| 长对话消耗太多 token | Compaction：上下文压缩，保留关键信息 | 会议纪要只记重点，不记废话 | Compaction |

## 1.5.1 成本对比（量化估算）

SquillaRouter 的核心价值是降低 API 费用。以下基于典型使用场景的估算：

**假设场景：** 每天 100 次对话，其中 60% 为简单任务（闲聊、简单问答），25% 为中等任务（代码编写、文档生成），10% 为困难任务（复杂算法），5% 为极难任务。

| 方案 | 简单任务(60次) | 中等任务(25次) | 困难任务(10次) | 极难任务(5次) | 日均成本 |
|------|--------------|--------------|--------------|-------------|---------|
| **无路由（全用高端模型）** | 高端模型 ×60 | 高端模型 ×25 | 高端模型 ×10 | 高端模型 ×5 | 100% (基准) |
| **OpenSquilla（SquillaRouter）** | C0 便宜模型 ×60 | C1 中端模型 ×25 | C2 代码模型 ×10 | C3 高端模型 ×5 | **约 30-40%** |

**节省原理：** 简单任务（60%）使用 C0 层级模型，其 API 价格约为 C3 层级模型的 1/10 ~ 1/20。仅此一项即可节省约 54% 的总费用。

> 来源：UsageTracker 记录每个会话的 billed_cost（engine/usage.py:538），ModelUsage 包含 lookup_price() 和 estimate_cost() 函数（codegraph 验证）。实际节省取决于模型定价和任务分布。

## 1.9 健康监控体系

OpenSquilla 有贯穿多层级的健康监控：

| 层级 | 组件 | 文件 | 说明 |
|------|------|------|------|
| 网关 | /health, /ready | gateway/app.py:133-139 | HTTP 健康检查端点 |
| 提供商 | ProviderHealthLedger | engine/routing/health.py:76 | 提供商故障追踪（3 次失败→bench） |
| 通道 | health() | channels/types.py:96 | ManagedChannel 健康检查 |
| 心跳 | HeartbeatLoop | gateway/boot.py | 网关心跳循环 |

ProviderHealthLedger 故障追踪规则：
- DEFAULT_FAILURE_THRESHOLD = 3：连续 3 次失败→触发 cooldown
- DEFAULT_COOLDOWN_S = 60s：冷却 60 秒
- DEFAULT_MAX_COOLDOWN_S = 300s：最大冷却 300 秒
- 按 deployment_key 分组追踪

> 来源：engine/routing/health.py:76-120, codegraph explore health heartbeat

## 1.10 路由器控制 (Router Control)

用户可通过 router_control 工具手动切换模型层级：

```
router_control {
  action: "set_hold" | "clear_hold"
  target_id: "tier:c0" | "tier:c1" | "tier:c2" | "tier:c3"
  evidence: "用户说'用最强的模型'"
  reason: "用户要求使用高端模型"
}
```

层级映射：
- tier:c0 → deepseek-v4-flash（简单任务）
- tier:c1 → deepseek-v4-pro（中等任务）
- tier:c2 → kimi-k2.7-code（编码任务）
- tier:c3 → glm-5.2（最强推理）

> 来源：tools/builtin/router_control.py:16-52, router_control.py set_hold()
