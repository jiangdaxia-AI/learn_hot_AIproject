## 1.1 一句话定位

**OpenSquilla 是一个省钱的、轻量级的 AI 智能助手运行时**——它像一个"AI 管家"，能在终端、网页、飞书/Slack/Telegram 等各种聊天工具里帮你干活，并且自动选择最便宜的 AI 模型来省钱。

> 打个比方：OpenSquilla 就像你雇了一个聪明的管家，他不仅能在各种渠道（电话、微信、当面）接你的指令，还会自己判断任务难度——简单跑腿找便宜的临时工，复杂决策才请专家，帮你省下大笔开销。

## 1.5.1 成本对比（量化估算）

智能路由的核心价值是降低 API 费用。以下基于典型使用场景的估算：

**假设场景：** 每天 100 次对话，其中 60% 为简单任务（闲聊、简单问答），25% 为中等任务（代码编写、文档生成），10% 为困难任务（复杂算法），5% 为极难任务。

| 方案 | 简单任务(60次) | 中等任务(25次) | 困难任务(10次) | 极难任务(5次) | 日均成本 |
|------|--------------|--------------|--------------|-------------|---------|
| **无路由（全用高端模型）** | 高端模型 x60 | 高端模型 x25 | 高端模型 x10 | 高端模型 x5 | 100% (基准) |
| **OpenSquilla（智能路由）** | 便宜模型 x60 | 中端模型 x25 | 代码模型 x10 | 高端模型 x5 | **约 30-40%** |

**节省原理：** 简单任务（60%）使用最便宜的模型层级，其 API 价格约为高端模型层级的 1/10 ~ 1/20。仅此一项即可节省约 54% 的总费用。

> 实际节省取决于模型定价和任务分布。

## 1.8 桌面端

| 组成部分 | 说明 |
|------|------|
| 主程序 | 控制桌面应用的核心逻辑 |
| 脚本 | 辅助构建和配置脚本 |
| 网关管理 | 管理本地 OpenSquilla 网关进程的启动和停止 |
| 单实例锁 | 防止同时打开多个应用窗口 |
| 更新检查 | 自动检测并提示新版本 |

桌面端核心功能：
- 一键启动本地网关进程
- 管理网关生命周期（启动/停止/重启）
- 单实例锁防止多开
- 自动更新检查

## 1.9 健康监控体系

OpenSquilla 有贯穿多层级的健康监控：

| 层级 | 功能 | 说明 |
|------|------|------|
| 网关 | 健康检查接口 | 外部系统可定期访问检查网关是否正常运行 |
| AI 厂商 | 厂商故障追踪 | 连续 3 次调用失败 → 暂停使用 60 秒，最大暂停 300 秒 |
| 通道 | 通道健康检查 | 检查各聊天平台连接是否正常 |
| 心跳 | 心跳循环 | 网关定期自检，确保服务存活 |

厂商故障追踪规则（像熔断器一样保护系统）：
- 连续失败 3 次 → 触发冷却（暂停使用该厂商）
- 冷却时间 60 秒
- 最大冷却时间 300 秒（5 分钟）
- 按厂商+模型组合分别追踪

## 1.10 路由器控制

用户可手动切换模型层级，比如对 AI 说"用最强的模型"：

| 操作 | 说明 |
|------|------|
| 设置固定路由 | 临时锁定某个模型层级 |
| 清除固定路由 | 恢复自动智能选择 |

层级说明：
- 便宜模型 → 简单任务（闲聊、简单问答）
- 中端模型 → 中等任务（内容生成）
- 代码模型 → 编程任务
- 高端模型 → 最强推理能力

## 1.12 记忆整理流程（"梦境"管道）

OpenSquilla 记忆系统独有的"梦境"管道——模拟人脑睡眠时的记忆整理过程：

| 组件 | 说明 |
|------|------|
| 梦境运行器 | 负责执行记忆整理任务 |
| 整理进度游标 | 记录整理到了哪里，确保不重复整理 |
| 整理结果 | 整理后的记忆摘要 |
| 梦境构建工厂 | 根据配置生成梦境任务 |
| 定时触发 | 由调度系统定时触发梦境整理 |
| 梦境配置 | 控制梦境整理的频率和范围 |

"梦境"管道通过 AI 对碎片化记忆做归纳巩固，合并相似记忆、去除冗余，生成结构化的记忆摘要——就像人睡觉时大脑把白天的经历整理成长期记忆。

> 这个比喻特别贴切：白天你的 AI 助手接收了大量零散信息（"老板喜欢简约风格"、"项目截止日期是周五"、"上次用的是蓝色主题"），到了晚上"做梦"时，系统会把这些碎片合并成一条清晰的记忆："老板偏好简约风格，常用蓝色主题，当前项目周五截止"。
