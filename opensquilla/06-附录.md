## 6.1 术语表（中英对照）

| 术语 | 英文 | 白话解释 |
|------|------|---------|
| 机器人 | Agent | 一个 AI 对话实体，有自己的配置和记忆，就像一个"AI 员工" |
| 会话 | Session | 一次完整的对话，包含所有消息轮次，就像一个"聊天包厢" |
| 轮次 | Turn | 用户发一次消息 + AI 回复一次 = 一个 turn，就像"一问一答" |
| 工具 | Tool | AI 可以调用的函数（如执行命令、搜索网页），就像 AI 的"工具箱" |
| 技能 | Skill | 多个工具调用的组合，可复用的工作流，就像 AI 的"操作手册" |
| 网关 | Gateway | 系统的 HTTP 入口，所有请求先到这里，就像餐厅的"前台" |
| 引擎 | Engine | AI 的大脑，控制思考→行动的循环，就像餐厅的"后厨" |
| 服务商 | Provider | AI 模型的服务商（OpenAI/Anthropic 等），就像"食材供应商" |
| 路由器 | Router | 判断任务难度，选择最合适的模型，就像"领班分配厨师" |
| 通道 | Channel | 消息平台（飞书/Slack/Telegram 等），就像"外卖平台" |
| 沙箱 | Sandbox | 隔离执行环境，防止 AI 搞破坏，就像"安全围栏" |
| 压缩 | Compaction | 把长对话压缩成摘要，节省 token，就像"把小说缩成简介" |
| 记忆 | Memory | AI 的长期记忆，跨对话的持久化信息，就像 AI 的"备忘录" |
| 审批 | Approval | 危险操作需要人工确认，就像"需要老板签字" |
| 回退 | Fallback | 主模型挂了，自动切换到备用模型，就像"替补队员上场" |
| 定时任务 | Cron Job | 按时间表自动执行的任务，就像"手机闹钟" |
| 子任务 | Subagent | Agent 生成的子 Agent，处理子任务，就像"帮厨" |
| 向量嵌入 | Embedding | 把文本转成数字向量，用于语义搜索，就像"给文字打标签方便检索" |
| 上下文 | Context | 发给 AI 的完整信息（提示词+历史+工具），就像"菜单" |
| 令牌 | Token | AI 处理文本的最小单位（约 0.75 个英文单词），就像"字数" |
| 事件 | Event | AI 状态变化时发出的通知，就像"门铃提示音" |
| 中间件 | Middleware | 请求处理管道中的拦截器，就像"安检门" |
| 路由 | Route | 请求路径到处理函数的映射，就像"餐厅菜单→对应厨师" |
| 依赖注入 | Dependency Injection | 把组件需要的依赖从外部传入，就像"餐厅统一采购食材分给各厨师" |
| 数据飞轮 | Data Flywheel | 从使用数据中学习，越用越好的闭环，就像"老厨师越做越熟练" |
| 代码图谱 | Codegraph | OpenSquilla 内置的代码调用关系分析工具，用于探索源码中的调用链 |
| 指数退避 | Exponential Backoff | 重试间隔越来越长（1s→2s→4s→...），就像"敲门越来越用力" |
| 门控 | Gate | 操作前/后的安全检查点，就像"安检关卡" |
| 协议 | Protocol | 组件之间约定的接口规范，就像"菜品的标准做法" |
| 适配器 | Adapter | 把一种格式转换成另一种格式的转换器，就像"翻译官" |
| 注册表 | Registry | 管理所有已注册组件的中央目录，就像"花名册" |
| 管线 | Pipeline | 多个处理步骤串起来的流程，就像"流水线" |

## 6.4 复刻指南（如果你想做一个类似的产品）

### 功能优先级

| 优先级 | 功能模块 | 原因 |
|--------|------|------|
| 最高优先级 | 网关 + 引擎 + AI 服务商 | 核心对话能力，缺了就没法用 |
| 最高优先级 | 基础工具（执行命令、读写文件、搜索网页） | AI 需要工具才能做事 |
| 高优先级 | 智能路由器 | 根据任务难度自动选模型，省钱 |
| 高优先级 | 通道接入（1-2 个平台） | 让用户从飞书/Slack 等平台使用 |
| 中等优先级 | 长期记忆 | 让 AI 记住用户偏好和历史 |
| 中等优先级 | 安全沙箱 | 隔离 AI 的操作，防止误操作 |
| 中等优先级 | 技能系统 | 可复用的工作流，提高效率 |
| 低优先级 | 定时任务 | 按时间表自动执行 |
| 低优先级 | 更多通道 | 接入更多平台 |
| 低优先级 | 多模型组合 | 同时调用多个模型汇总结果 |

### 推荐技术选型

| 层面 | 推荐 | 原因 |
|------|------|------|
| 后端语言 | Python 3.12+ | 异步支持好，AI 生态丰富 |
| 后端框架 | Starlette（轻量级 Python Web 框架） | 性能好，异步支持 |
| AI 模型调用 | 统一的服务商抽象层 | 切换模型零成本 |
| 数据库 | SQLite（嵌入式数据库，零配置） | 不需要单独安装数据库服务 |
| 向量搜索 | sqlite-vec（SQLite 向量扩展） | 本地实现语义搜索，无需外部服务 |
| 前端框架 | Vue 3 + TypeScript + Vite | 组件化开发，效率高 |
| 桌面应用 | Electron（跨平台桌面框架） | 用 Web 技术构建桌面应用 |
| 路由模型 | LightGBM（轻量级机器学习算法） | 轻量、快速，适合做分类决策 |
| 安全隔离 | Bubblewrap(Linux) / Seatbelt(macOS) | 操作系统原生安全机制 |
| 包管理 | uv（Python）/ npm（前端） | 快速依赖管理 |
