## 2.3 核心设计理念（5 个）

| 理念 | 说明 | 体现 |
|------|------|------|
| **微内核** | 核心循环 <500 行，复杂功能通过插件组合 | engine/agent.py L5 |
| **协议驱动** | 每层定义统一接口，实现可替换 | LLMProvider, ManagedChannel, Backend |
| **显式状态机** | Agent 状态显式编码，无隐式转换 | 6 状态枚举 |
| **防御性深度** | 多层安全检查，不信任任何单一防护 | 3 层防御 + 5 种沙箱 |
| **本地优先** | 路由、搜索、向量化均在本地完成 | LightGBM + sqlite-vec |

**解读：**
- Gateway 是依赖最重的模块——它依赖 11 个其他模块，因为它是所有组件的组装点和入口
- Provider、Memory、Router、Channels、Sandbox、Scheduler、Session、Observability、MCP 是**独立模块**——它们不依赖其他模块，只被上层调用
- Engine 依赖 Provider、Tools、Skills、Memory、Router、Sandbox、Session、Observability——它是核心编排层
- 如果你想替换某个模块（如换一个 Router），只需修改 Engine 和 Gateway 的依赖注入，其他模块不受影响
