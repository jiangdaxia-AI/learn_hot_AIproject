## 2.2 层间调用关系

```
用户交互层 ──网页请求──▶ 网关层 ──内部调用──▶ 引擎层 ──▶ 能力层 ──▶ 基础设施层
                                      │
                                      ├──▶ AI 厂商层 (调用 AI 模型)
                                      ├──▶ 工具层 (执行具体操作)
                                      ├──▶ 技能层 (运行工作流)
                                      └──▶ 路由层 (选择模型)
                                              │
                                              ▼
                                         基础设施层
                                         ├── 记忆 (长期存储)
                                         ├── 会话 (对话管理)
                                         ├── 调度 (定时任务)
                                         └── 沙箱 (安全执行)
```

> 就像餐厅：用户点菜（交互层）→ 前台接单（网关层）→ 厨师长分派（引擎层）→ 厨师选食材（能力层）→ 厨房设备支撑（基础设施层）→ 食材仓库（存储层）

## 2.3 核心设计理念（5 个）

| 理念 | 说明 | 体现 |
|------|------|------|
| **微内核** | 核心循环精简（<500 行），复杂功能通过插件组合 | 引擎核心代码 |
| **协议驱动** | 每层定义统一接口，实现可替换 | AI 厂商接口、通道接口、沙箱接口 |
| **显式状态机** | AI 智能体状态明确编码，无隐藏转换 | 6 个状态 |
| **防御性深度** | 多层安全检查，不信任任何单一防护 | 3 层防御 + 5 种沙箱 |
| **本地优先** | 路由、搜索、语义检索均在本地完成 | 本地算法 + 本地搜索引擎 |

- 网关是依赖最重的模块——它依赖 11 个其他模块，因为它是所有组件的组装点和入口

- 如果你想替换某个模块（如换一个路由方案），只需修改引擎和网关的依赖注入，其他模块不受影响

## 2.7 层间协议（接口合约）

| 层间边界 | 协议/接口 | 核心功能 |
|----------|----------|---------|
| 用户 → 网关 | 网页请求 + 实时通信 | 发送消息、接收回复 |
| 网关 → 引擎 | 核心调度器 | 启动一次对话回合 |
| 引擎 → AI厂商 | AI 厂商接口 | 发送消息 → 逐字接收回复 |
| 引擎 → 工具 | 工具注册中心 | 按名称调用工具 |
| 引擎 → 路由 | 智能路由 | 输入文本 → 推荐模型层级 |
| 引擎 → 沙箱 | 沙箱运行时 | 在隔离环境中执行代码 |
| 网关 → 通道 | 通道管理器 | 启动、停止、发送、健康检查 |
| 网关 → 调度 | 调度引擎 | 添加、删除、查看定时任务 |
| 网关 → 会话 | 会话管理器 | 获取、创建、压缩会话 |
| 网关 → 初始化 | 配置引导引擎 | 引导用户完成首次配置 |
| 工具 → 沙箱 | 沙箱后端 | 在隔离环境中运行工具 |
| 记忆 → AI厂商 | 向量化接口 | 文本转向量、批量向量化 |
