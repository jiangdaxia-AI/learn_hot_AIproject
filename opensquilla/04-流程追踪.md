## 场景 1：用户通过 Web UI 发送聊天消息

**用户视角：** 你在浏览器里打开 OpenSquilla 控制台，输入"帮我写一个 Python 排序函数"，点击发送。不到 1 秒，屏幕上开始逐字出现代码，代码写完后 AI 还贴心地附上了使用说明。整个过程你只做了一件事：打字 + 回车。

### 逐步详解（12 步）

**步骤 1：Web UI 发送请求**  
前端 (Vue 3) → HTTP POST /api/chat → Starlette 网关  
源码：gateway/app.py L170 api_chat()  
耗时：<1ms（本地回环）

**步骤 2：5 层中间件管道**  
SecurityHeaders → RateLimit → Auth → CORS → OriginGuard  
源码：gateway/middleware.py + gateway/origin_guard.py  
耗时：<1ms

**步骤 3：RPC 调度**  
解析 method → 参数校验 → 查找 handler → 分发到 chat handler  
源码：gateway/rpc.py get_dispatcher()

**步骤 4：SessionManager 查找/创建会话**  
按 session_key 查找 → 无则创建新会话 → 加载历史对话  
源码：session/manager.py:201 SessionManager

**步骤 5：TurnRunner 启动**  
AgentBootstrapStage → 构建 Agent 实例 → 注入工具定义 → 设置上下文  
源码：engine/turn_runner/agent_bootstrap_stage.py:539 AgentBootstrapStage  
codegraph 验证：AgentBootstrapStage 有 5 个 callers

**步骤 6：ContextAssembly 组装上下文**  
收集：系统提示词 + 用户消息 + 历史对话 + 记忆注入 + 工具定义 → 拼成完整消息数组  
源码：engine/context.py ContextAssembly

**步骤 7：SquillaRouter 路由决策**  
FeatureExtractor 5 通道提取特征 → LightGBM 预测 4 类概率 → 后处理 → 选择 tier  
源码：squilla_router/.../predictor.py:286 predict()  
耗时：<5ms（本地推理）

**步骤 8：ContextBudgetGovernor 预算检查**  
计算 usable_tokens → 检查 threshold → 必要时触发 Compaction  
源码：context_budget.py:69 ContextBudgetGovernor

**步骤 9：LLM 调用 (Pipeline)**  
Agent.run() → provider.chat(messages) → 流式接收 ContentBlockText  
源码：engine/agent.py run() → provider/protocol.py:181 LLMProvider.chat()  
耗时：1-3s（取决于模型和任务复杂度）

**步骤 10：WebSocket 实时推送**  
TextDeltaEvent 逐字推送 → 前端渲染  
源码：gateway/websocket.py handle_ws_connection()

**步骤 11：FinalizeEvidenceGate 检查**  
如果写了文件 → 验证写入 → 可能触发挑战消息  
源码：engine/finalize_evidence_gate.py:887 FinalizeEvidenceTracker

**步骤 12：TurnFinalizerStage 收尾**  
保存会话到 SQLite → 记录 UsageTracker 用量（tokens + cost）→ 发送 DoneEvent 到 WebSocket  
源码：engine/turn_runner/turn_finalizer_stage.py:530 TurnFinalizerStage

## 场景 2：飞书机器人响应群聊消息

**用户视角：** 你在飞书项目群里 @ 了 OpenSquilla 机器人，说"帮我总结上周的周报"。几秒钟后，机器人回复了一段完整的周报总结，还附了一个表格。你不需要离开飞书，也不需要知道 AI 在后台做了什么。

### 完整时序图

```
飞书用户             飞书服务器           OpenSquilla网关      引擎+Agent
   │                    │                    │                    │
   │ @机器人 "总结周报" │                    │                    │
   │───────────────────▶│                    │                    │
   │                    │ POST Webhook       │                    │
   │                    │───────────────────▶│                    │
   │                    │                    │ 飞书适配器         │
   │                    │                    │ 1.验证签名(HMAC)   │
   │                    │                    │ 2.解析消息体       │
   │                    │                    │ 3.提取文本+@提及   │
   │                    │                    │ 4.构建 session key │
   │                    │                    │ build_group_key()  │
   │                    │                    │ ChannelManager     │
   │                    │                    │ run_channel_dispatch│
   │                    │                    │───────────────────▶│
   │                    │                    │                    │ TurnRunner.run()
   │                    │                    │                    │ (同场景1步骤5-12)
   │                    │                    │◀───────────────────│ response text
   │                    │ feishu.send()      │                    │
   │                    │◀───────────────────│                    │
   │◀─── 飞书消息 ──────│                    │                    │
   │  "这是上周的周报总结..."              │                    │
```

### 逐步详解（10 步）

**步骤 1：飞书服务器推送 Webhook**  
飞书用户 @机器人 → 飞书服务器 POST → OpenSquilla 网关  
源码：channels/feishu.py webhook 处理函数  
飞书适配器 FeishuChannel (channels/feishu.py:658, 31 callers)

**步骤 2：签名验证**  
飞书适配器使用 app_secret 对请求体做 HMAC-SHA256 签名验证，确保消息来自飞书官方  
源码：channels/feishu.py 签名验证逻辑

**步骤 3：消息解析**  
解析飞书 JSON 消息体 → 提取：文本内容、图片/文件附件、@提及的用户、消息类型（群聊/私聊）  
源码：channels/feishu.py _parse_message()

**步骤 4：Session Key 构建**  
群聊消息 → build_group_key(chat_id, agent_id) → 生成唯一的 session key  
源码：session/keys.py build_group_key()  
codegraph 验证：共 6 种 session key 构建函数

**步骤 5：ChannelManager 调度**  
ChannelManager (channels/manager.py:38) 的 run_channel_dispatch() 接收消息 → 构建 TurnRunner 输入 → 调用引擎  
源码：channels/manager.py run_channel_dispatch()

**步骤 6-9：引擎处理**  
同场景 1 的步骤 5-12：TurnRunner → ContextAssembly → Router → LLM 调用 → 生成回复  
codegraph 验证调用链：ChannelManager → TurnRunner → AgentBootstrapStage → PromptAssemblerStage → Pipeline → TurnFinalizerStage

**步骤 10：回复发送**  
Agent 生成回复后 → feishu.send(target, text) → 飞书 API 发送消息到群聊  
源码：channels/feishu.py send() 方法  
支持：文本消息、Markdown 卡片、文件附件

## 场景 3：定时任务自动执行

**用户视角：** 你设置了一个定时任务："每天早上 9 点，用飞书发送昨天的项目进展总结"。第二天早上 9 点，你准时在飞书群里收到了总结。你什么也没做——它在后台自动完成了。

### 完整时序图

```
SchedulerEngine       CronJob触发         引擎+Agent          飞书通道
    │                    │                    │                    │
    │ APScheduler        │                    │                    │
    │ 触发 cron 任务     │                    │                    │
    │───────────────────▶│                    │                    │
    │                    │ JobStore 查询      │                    │
    │                    │ 构建 session key   │                    │
    │                    │ (build_cron_key)   │                    │
    │                    │───────────────────▶│                    │
    │                    │                    │ TurnRunner.run()   │
    │                    │                    │ (同场景1步骤5-12)  │
    │                    │                    │ 生成总结文本       │
    │                    │                    │───────────────────▶│
    │                    │                    │                    │ feishu.send()
    │                    │                    │                    │ 发送到群聊
    │                    │◀───────────────────│ 完成               │
    │                    │ JobStore 记录      │                    │
    │                    │ 执行结果+耗时      │                    │
```

### 逐步详解（8 步）

**步骤 1：APScheduler 触发**  
APScheduler 按照 cron 表达式触发任务  
源码：scheduler/engine.py:46 SchedulerEngine  
codegraph 验证：SchedulerEngine 有 5 个 callers

**步骤 2：JobStore 查询**  
从 SQLite 读取任务详情 → 验证任务是否启用 → 检查上次执行结果  
源码：scheduler/persistence.py JobStore

**步骤 3：Stagger 错峰**  
compute_jitter() 计算随机偏移 → 避免大量任务同时触发  
源码：scheduler/stagger.py compute_jitter()

**步骤 4：Session Key 构建**  
定时任务 → build_cron_key(job_id) → 独立会话  
源码：session/keys.py build_cron_key()

**步骤 5-7：引擎处理**  
同场景 1 步骤 5-12：TurnRunner → Agent → 生成回复  
任务类型为 agent_turn → 创建独立 Agent 会话 → 执行 prompt → 生成结果

**步骤 8：结果投递**  
Agent 回复 → 通过指定通道发送（飞书/Slack 等）→ JobStore 记录执行结果  
源码：scheduler/engine.py 执行完成回调
