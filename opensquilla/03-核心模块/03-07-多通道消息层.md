# 03-07 · 多通道消息层 — 大白话教材

> **面向读者**：产品经理、运营人员 | **难度**：⭐ 入门 | **阅读时间**：约 12 分钟

---

## 一句话说清楚

多通道消息层是 OpenSquilla 的"社交网络接入层"。它让 AI 能同时接入飞书、Slack、Telegram、钉钉、Discord、QQ 等 9 种聊天平台，在不同平台上回答用户问题、执行命令、定时汇报。

---

## 生活化比喻

> 通道层就像一个人同时登录了微信、QQ、钉钉、飞书、Telegram。无论你在哪个 App 上找他，他都能回复你，而且记住你们在哪个 App 上聊过什么。每个 App 有自己的消息格式，通道层负责把各种格式翻译成统一的"内部语言"。

---

## 一、支持的聊天平台（9 种）

| 平台 | 接入方式 | 特色功能 |
|------|---------|---------|
| **飞书** | Webhook 回调 / WebSocket 长连接（两种方式） | 文档操作、表格操作、云盘上传、权限管理、知识库 |
| **Telegram** | 轮询模式 / Webhook 回调 | Bot API，支持话题回复 |
| **Slack** | Socket 模式 / Webhook 回调 | 话题回复、表情反馈 |
| **钉钉** | WebSocket 长连接 | 企业消息、群聊、审批卡片 |
| **Discord** | Bot API | 服务器/频道消息 |
| **QQ** | QQ Bot API | 国内 IM 集成 |
| **MS Teams** | Microsoft Bot Framework | 企业协作 |
| **Matrix** | 去中心化协议 | 联邦制，支持跨服务器通信 |
| **终端** | 本地命令行 | 无需网络，直接在终端里对话 |

---

## 二、统一协议——"万能接口"

所有平台共用一个"万能接口"，无论底层是什么平台，对上层的 AI 来说都是一样的：

| 能力 | 说明 |
|------|------|
| 启动连接 | 建立与平台的通道（飞书初始化、Telegram 启动 Bot 等等） |
| 停止连接 | 断开连接，清理资源 |
| 发送消息 | 发文本到群聊/私聊/话题，自动适配各平台格式 |
| 发送文件 | 上传附件到对应平台 |
| 健康检查 | 心跳检测，故障自动告警和重连 |
| 接收消息 | 各平台的消息格式 → 翻译成统一内部格式 |
| 下载附件 | 把图片/文件下载到本地供 AI 处理 |

## 三、一条消息的完整旅程——以飞书为例

用户在飞书群发了一条"@Bot 帮我查一下天气"，这条消息经历了什么？

```
用户在飞书群发消息
    │
    ▼
步骤 1：飞书服务器检测到消息，打包成数据包，POST 到 OpenSquilla
    │
    ▼
步骤 2：网关收到数据包
    │
    ▼
步骤 3：验证签名（确认"这确实是飞书发来的，不是伪造的"）
    ├─ 签名不对 → 拒绝（401）
    │
    ▼
步骤 4：解密消息（飞书安全模式下消息是加密的）
    │
    ▼
步骤 5：去重检查（同一个消息不处理两次，防止网络重试导致的重复）
    ├─ 是重复消息 → 直接忽略
    │
    ▼
步骤 6：格式转换（飞书格式 → 统一的内部格式）
    ├─ 提取发送者 ID、群聊 ID、消息文本
    ├─ 提取图片/文件附件
    ├─ 去掉 @机器人 的前缀
    │
    ▼
步骤 7：分配到正确的 Agent 会话
    ├─ 群聊 → 分配群聊专属会话（不跟其他群串台）
    ├─ 私聊 → 分配私聊专属会话
    ├─ 话题回复 → 分配话题专属会话
    │
    ▼
步骤 8：AI 处理消息（理解问题、调用工具、生成回复）
    │
    ▼
步骤 9：回复消息
    ├─ 如果是群聊里的回复 → 用飞书原生"回复"功能
    ├─ 如果是新消息 → 直接发送到群聊
    └─ 调用飞书 API 把消息投递到群里
```

## 四、会话隔离——怎么保证不串台？

想象一下：你同时在飞书群 A、飞书群 B、和机器人的私聊里问了三个问题。AI 需要记住每个聊天窗口的上下文，不能让群 A 的回答跑到群 B 去。

**解决方案：给每个聊天窗口分配一个唯一"房间号"。**

| 聊天场景 | 房间号格式 | 举例 |
|---------|-----------|------|
| 默认会话 | 主会话 | agent:main:main |
| 群聊 | 按"通道名+群ID"隔离 | agent:main:feishu:group:群A的ID |
| 私聊 | 按"通道名+用户ID"隔离 | agent:main:feishu:direct:你的ID |
| 话题回复 | 在群聊房间号上加话题ID | agent:main:feishu:group:群ID:thread:话题ID |
| 定时任务 | 按任务名隔离 | cron:日报任务 |
| 子代理 | 在父会话下新建 | 父会话/sub:任务ID |

> **大白话**：就像酒店给每个房间分配一个房间号，AI 进了哪个房间，就用哪个房间的记忆，不会串门。

### 隐私保护

群聊中**不会**注入用户的私人记忆（比如个人偏好文件），防止群成员看到不该看的内容。只有私聊才会注入。

## 五、通道健康管理

通道管理器（大管家）负责所有通道的"生老病死"：

| 阶段 | 做什么 |
|------|--------|
| 启动 | 扫描配置，同时启动所有已启用的通道（单个失败不影响其他） |
| 运行 | 监听消息、分发到 Agent、回复用户 |
| 健康检查 | 定期心跳检测，分三档：健康 / 降级（部分功能坏了）/ 不可用 |
| 故障恢复 | 自动重连（指数退避：1秒→2秒→4秒...最多60秒），最多重试 5 次 |
| 停止 | 网关关闭时，同时优雅断开所有通道，清理资源 |

## 六、飞书通道的额外能力

飞书是接入最深、功能最全的平台，除了基础的消息收发，还支持：

| 功能 | 说明 |
|------|------|
| 文档操作 | 创建、读取飞书文档 |
| 表格操作 | 读写飞书电子表格 |
| 云盘上传 | 把 AI 生成的文件上传到飞书云盘 |
| 权限管理 | 授予/收回文档权限 |
| 知识库 | 浏览、搜索飞书知识库 |
| 消息编辑 | 修改已发送的消息 |
| 媒体上传 | 上传图片/文件到飞书会话 |

---

## 七、对产品/运营同学的一句话总结

> 多通道消息层让 AI 像一个"全平台客服"，同时登录飞书、Slack、Telegram、钉钉、QQ 等 9 个平台，一对一私聊、多人群聊、话题回复全支持。每个聊天窗口独立管理，不会串台。群聊中自动保护用户隐私，不会泄露个人信息。
