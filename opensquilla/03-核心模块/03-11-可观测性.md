## 定位

可观测性是 OpenSquilla 的"黑匣子"。它记录 Agent 运行时的关键事件，帮助开发者理解"AI 为什么这么做"、"哪里出了问题"、"怎么优化"。不记录用户对话内容，只记录系统行为。

---

## 生活化比喻

> 可观测性像飞机的**飞行数据记录器**。飞机正常飞行时你不看它，但一旦出问题（引擎故障、偏离航线），黑匣子告诉你每一秒发生了什么。OpenSquilla 的黑匣子记录：哪个模型被调用了、工具执行了几次、有没有重复写入同一个文件。

## 一、RuntimeDiagnosticsObserver — 运行时诊断观察器

RuntimeDiagnosticsObserver (engine/runtime_diagnostics.py:148) 是核心诊断组件，有 7 个 callers：

### 四种诊断模式

| 模式 | 触发条件 | 阈值 | 诊断内容 |
|------|---------|------|---------|
| 重复失败锚点 | 同一个工具调用连续失败 | 默认 3 次 | 提取失败锚点 hash，生成诊断事件 |
| 重复源文件读取 | 写入后反复读取同一文件 | 默认 5 次 | 检测"写完检查"循环 |
| 验证无变更 | 执行验证但 diff 无变化 | 默认 3 次 | 检测"空验证"循环 |
| 非空 diff 结束 | Agent 在仍有未提交变更时结束 | 任何次 | 检测"未完成工作" |

### 诊断事件生成流程

```
Agent 执行工具调用
  │
  ▼
RuntimeDiagnosticsObserver.observe_tool_results()
  ├─ _unique_paths_from_records()     → 提取唯一文件路径
  ├─ classify_path()                  → 分类路径类型
  ├─ failure_anchor_hash()            → 计算失败锚点
  ├─ _record_relative_path()          → 记录相对路径
  ├─ command_looks_like_focused_verification() → 判断是否为验证命令
  ├─ _compact_record()                → 压缩记录
  └─ _event()                         → 发出诊断事件
```

## 二、诊断事件类型

| 事件类型 | 含义 | 触发模块 |

## 三、日志系统 (structlog)

OpenSquilla 使用 structlog 作为结构化日志框架：

| 日志级别 | 用途 | 示例 |
|----------|------|------|
| DEBUG | 开发调试信息 | 工具调用参数、特征提取结果 |
| INFO | 正常运行信息 | 通道启动/停止、任务执行 |
| WARNING | 潜在问题 | 接近预算上限、提供商慢响应 |
| ERROR | 错误事件 | 工具执行失败、提供商不可用 |

日志输出格式：JSON 结构化日志，每条包含 timestamp、logger、event、level 等字段。

## 五、DiagnosticsState — 诊断状态管理

DiagnosticsState 管理诊断的开关状态和配置：

| 字段 | 说明 |
|------|------|
| enabled | 诊断是否启用 |
| level | 诊断级别 |
| observers | 已注册的观察器列表 |

在网关启动时通过 DiagnosticsState.from_config(config) 初始化。
