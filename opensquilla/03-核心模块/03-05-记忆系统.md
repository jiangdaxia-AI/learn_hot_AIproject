# 03-05 · 记忆系统 — 大白话教材

> **面向读者**：产品经理、运营人员 | **难度**：⭐ 入门 | **阅读时间**：约 10 分钟

---

## 一句话说清楚

记忆系统就是 OpenSquilla 的"长期记忆"。它让 AI 记住你的偏好、项目背景、历史经验，下次聊天时自动想起来，不需要你每次都重复说一遍。

---

## 生活化比喻

> 记忆系统像你的**私人笔记本**。每次你跟 AI 说"我喜欢用 Python"、"公司项目用 FastAPI"，AI 就记在本子上。下次你问新问题，AI 先翻本子——"哦，他喜欢 Python，用 FastAPI"，直接给出对口的答案，不用你再说一遍。

> 此外，AI 还会像人脑一样在**空闲时整理记忆**（这个功能叫 Dream 管道），把白天碎片化的信息归纳巩固——就像你睡觉时大脑整理白天的经历一样。

---

## 一、整体架构

记忆系统由四个核心组件组成，像一个分工明确的团队：

```
┌──────────────────────────────────────────────────────┐
│               记忆系统总管家（统一入口）                │
│       负责对外提供"写入记忆"和"检索记忆"两个服务        │
├──────────────────────────────────────────────────────┤
│                                                      │
│  ┌──────────────┐  ┌──────────────┐  ┌────────────┐ │
│  │  存储引擎     │  │  检索引擎     │  │  同步管理   │ │
│  │(像仓库管理员)  │  │(像图书管理员)  │  │(像物流调度) │ │
│  │              │  │              │  │            │ │
│  │ 把记忆存进    │  │ 按关键词+语义 │  │ 确保多会话  │ │
│  │ 本地数据库    │  │ 搜索最相关的  │  │ 记忆同步    │ │
│  │              │  │ 记忆条目      │  │            │ │
│  └──────┬───────┘  └──────┬───────┘  └─────┬──────┘ │
│         │                 │                 │        │
│  ┌──────┴─────────────────┴─────────────────┴──────┐ │
│  │              "翻译官"（文字→数字向量）             │ │
│  │  把文字内容翻译成 AI 能理解的数字向量，             │ │
│  │  支持 3 种方式：本地运行、云端调用、开源模型         │ │
│  └─────────────────────────────────────────────────┘ │
│                                                      │
│  ┌─────────────────────────────────────────────────┐ │
│  │           Dream 管道（记忆整理功能）              │ │
│  │  • 空闲时自动运行，整理碎片化记忆                  │ │
│  │  • 合并相似内容、去除重复、生成简洁摘要            │ │
│  └─────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────┘
```

**大白话翻译：**

| 组件 | 比喻 | 干什么 |
|------|------|-------|
| 记忆系统总管家 | 私人助理 | 别人说"记下这个"或"帮我回忆一下"，他统一处理 |
| 存储引擎 | 仓库管理员 | 把记忆存进数据库，分类贴标签，方便以后找 |
| 检索引擎 | 图书管理员 | 你问一个问题，他帮你从记忆库里找到最相关的几条 |
| 同步管理 | 物流调度 | 确保你在不同聊天窗口记的东西，下次都能找到 |
| 翻译官 | 文字翻译器 | 把文字信息转成 AI 能理解的数字形式 |
| Dream 管道 | 大脑整理 | 空闲时自动整理记忆，去掉重复的，合并相似的 |

## 二、记忆怎么写进去？（7 步）

```
步骤 1：判断要不要记
  总管家判断：用户说了重要信息吗？说了偏好吗？还是只是闲聊？

步骤 2：把长文本切成小块
  太长的内容切成小段，方便后续检索（就像把一本书拆成章节）

步骤 3：翻译成数字向量
  翻译官把每段文字转成数字向量（一串数字），语义相近的文字向量也相近

步骤 4：存进数据库
  仓库管理员把原文+向量+标签一起存进本地数据库

步骤 5：同步到各会话
  物流调度确保新记忆在所有聊天窗口都能被检索到

步骤 6：打标签
  记录写入时间、来源（是用户说的还是系统自动记的）、类型

步骤 7：通知总管家
  告诉总管家"有新记忆入库了"，下次检索时自动包含
```

---

## 三、记忆怎么找出来？（6 步）

```
步骤 1：把问题翻译成数字向量
  用户问的问题 → 翻译官翻译 → 一串数字（向量）

步骤 2：在记忆库里找相似的
  图书管理员在数据库中搜索"数字串最接近"的记忆条目
  相似度越高，说明语义越相关

步骤 3：混合搜索（关键词+语义）
  不仅看语义相似度，还看关键词是否匹配
  两种方式结合，结果更准（默认按 7:3 的权重合并）

步骤 4：按条件过滤
  按时间、类型、来源过滤——比如只找"最近一周的"、"用户偏好类的"

步骤 5：返回结果
  输出最相关的几条记忆，附带相似度分数和来源

步骤 6：注入到 AI 上下文中
  把找到的记忆自动加进 AI 的"参考材料"里，AI 回答时会参考这些内容
```

## 四、三种"翻译官"（文字→数字向量的方式）

| 方式 | 特点 | 隐私 | 速度 | 适合场景 |
|------|------|------|------|---------|
| 本地翻译 | 在用户电脑上运行，不联网 | ⭐⭐⭐ 完全本地 | 快 | 隐私敏感的场景 |
| 云端翻译 | 调用 OpenAI 云端服务 | ⭐ 数据上传云端 | 快 | 追求高质量向量的场景 |
| 开源翻译 | 本地运行开源模型 | ⭐⭐⭐ 完全本地 | 中等 | 想用开源方案的场景 |

> 系统支持按需切换，也可以禁用向量搜索，退化为纯关键词搜索。

## 五、Dream 管道 — 记忆的"夜间整理"

Dream 管道是 OpenSquilla 记忆系统最独特的设计，灵感来自人脑睡眠时的记忆整理过程。

### 工作原理

```
步骤 1：定时触发
  系统在空闲时（用户不活跃时）自动启动 Dream 任务

步骤 2：扫描新增记忆
  找到上次整理后新产生的记忆条目

步骤 3：AI 辅助整理
  用 AI 分析碎片化记忆，判断哪些可以合并、哪些可以删除
  比如："用户喜欢 Python" 和 "用户用 Python 开发" 可以合并为 "用户是 Python 开发者"

步骤 4：生成简洁摘要
  把相似记忆合并成一条精炼的总结

步骤 5：写回数据库
  把整理后的结果存回记忆库，更新索引
```

### 大白话总结

> Dream 就像**你睡觉时大脑做的事**。白天你经历了很多碎片信息（"这个人叫张三"、"张三在字节跳动工作"、"张三喜欢喝咖啡"），晚上睡觉时大脑自动整理——把碎片串成一条："张三，字节跳动员工，喜欢喝咖啡"。Dream 管道做的就是这个。

## 七、核心术语速查

| 术语 | 大白话解释 |
|------|-----------|
| **记忆向量** | 把文字转成一串数字，语义相近的文字，数字也相近。就像给每句话一个"坐标"，相似的话在坐标上离得近 |
| **向量搜索** | 在"坐标空间"里找离得最近的记忆条目 |
| **混合搜索** | 向量搜索 + 关键词搜索一起用，结果更准 |
| **文本分块** | 把长文本切成小段，方便存和搜 |
| **记忆刷新** | 把内存中暂存的记忆正式写入磁盘（持久化保存） |
| **Dream** | 记忆整理功能，空闲时自动运行，合并相似、去除冗余 |
| **游标** | Dream 管道的"书签"，标记上次整理到哪了，下次从这继续 |
| **降级模式** | 当翻译官不可用时，自动退回到纯关键词搜索，保证基本功能可用 |

## 九、记忆的完整生命周期

前面讲了记忆系统的四个组件分别做什么，但你可能还有一个问题：**一条记忆到底是怎么从"用户说了一句话"到"AI 下次自动想起来"的？** 下面用 7 个步骤串起整个流程，每一步标注了源码位置，方便技术同学查阅。

### 整体流程图

```
                     ┌─────────── 写入阶段 ───────────┐
                     │                                  │
  用户对话 ──→ ① 触发写入 ──→ ② 文本→向量 ──→ ③ 存储到 SQLite
  (Agent 对话中)  (flush/memory/  (EmbeddingProvider)  (LongTermStore
                 session_source)                        chunks + vec + fts)
                     │                                  │
                     ▼                                  ▼
              ┌──────┴──────────────────────────────────┴──────┐
              │              MemorySyncManager                  │
              │  (文件监听 + 会话增量 + 定时器 → 触发索引同步)    │
              └──────────────────────────────────┬──────────────┘
                                                 │
                     ┌─────────── 检索阶段 ───────┴──────────┐
                     │                                       │
  新对话开始 ──→ ④ 触发检索 ──→ ⑤ 语义搜索 ──→ ⑥ 结果排序 ──→ ⑦ 注入上下文
  (session-start /   (MemoryRetriever  (混合搜索: 向量+关键词)  (Top-K 截断)  (memory_md 注入
   search 理由)       .search())                                   系统提示词)
```

### 步骤详解

#### ① 触发写入 — 记忆怎么产生的？

记忆写入有三种触发方式：

**A. Agent 对话中自动触发（Flush 机制）**

当对话上下文接近 Token 上限时，系统自动触发"记忆冲刷"（Memory Flush）：

- 源码: `opensquilla/memory/flush.py` — `should_flush()` 判断是否触发，`resolve_flush_plan()` 生成写入计划
- 流程: 取对话末尾摘要 → 调起一个子 Agent → 子 Agent 判断"哪些内容值得记住" → 写入 `memory/YYYY-MM-DD.md`
- 写入目标: `memory/` 目录下按日期组织的 Markdown 文件（如 `memory/2026-07-22.md`）

**B. 用户显式保存**

- 用户直接编辑 `MEMORY.md` 或 `memory/` 目录下的 `.md` 文件
- 源码: `opensquilla/memory/sync_manager.py` — `MemorySyncManager._poll_loop()` 每秒轮询文件变化，`_do_file_sync()` 将变更文件送入索引

**C. 会话历史自动采集**

- 源码: `opensquilla/memory/turn_capture.py` — `TurnCaptureService.capture_turn()` 在每轮对话后记录用户消息到 `.opensquilla/turns/` 目录
- 采集的对话数据通过 `SessionSourceIndexer`（`opensquilla/memory/session_source.py`）以增量方式同步到记忆库，按"消息累积字节数"或"消息条数"阈值触发

#### ② 文本 → 向量 — 文字怎么变成数字？

写入记忆库的文本需要先被"翻译"成数字向量，才能进行语义搜索。

- 源码: `opensquilla/memory/embedding.py` — `EmbeddingProvider` 协议定义了 `embed_query()` 和 `embed_batch()` 两个接口
- 三种实现:
  - `OpenAIEmbeddingProvider` — 调用 OpenAI 云端 API（默认 `text-embedding-3-small`）
  - `OllamaEmbeddingProvider` — 本地 Ollama 服务（默认 `nomic-embed-text`）
  - `LocalEmbeddingProvider` — 完全本地 ONNX 运行时（默认 `BAAI/bge-small-zh-v1.5`）
- 降级: 如果没有任何 Embedding 可用，系统使用 `NullEmbeddingProvider`（`provider_id="none"`），退化为纯关键词搜索（FTS-only 模式）

**文本分块（Chunking）**：

- 源码: `opensquilla/memory/embedding.py` — `chunk_text()` 函数
- 长文本按约 400 Token 切块，块间重叠 50 Token（避免语义断裂）
- 中文按字估算（1 字 ≈ 1 Token），英文按 4 字符 ≈ 1 Token 估算

#### ③ 存储到 SQLite — 记忆持久化

转换后的向量 + 原文一起存入 SQLite 数据库。

- 源码: `opensquilla/memory/store.py` — `LongTermMemoryStore.index_file()`
- 数据库位置: `{agent_data_dir}/memory.db`
- 三张核心表:

| 表名 | 存储内容 | 说明 |
|------|---------|------|
| `chunks` | 文本块 + 向量（JSON）+ 元数据 | 主存储，含 `path`、`source`、`start_line`、`end_line`、`hash`、`model`、`embedding` 等字段 |
| `chunks_fts` | FTS5 全文索引 | 用于关键词搜索，支持 CJK 分词（jieba） |
| `chunks_vec` | sqlite-vec 向量索引 | 用于语义相似度搜索（可选，需加载 sqlite-vec 扩展） |

- 附加表: `files`（文件元数据）、`embedding_cache`（向量缓存，避免重复计算）、`meta`（Schema 版本和配置指纹）
- 写入是事务性的（`BEGIN IMMEDIATE` → 写所有表 → `COMMIT`），保证一致性

#### ④ 触发检索 — 什么时候需要"回忆"？

记忆检索由 `MemorySyncManager.sync()` 统一入口触发，触发理由（reason）有以下几种：

- 源码: `opensquilla/memory/sync_manager.py` — `MemorySyncManager.sync()` 方法
- 源码: `opensquilla/memory/manager.py` — `MemoryManager` 门面类

| 触发理由 | 说明 | 触发时机 |
|---------|------|---------|
| `session-start` | 新会话首次访问 | 首次使用某个 session_key 时 |
| `search` / `search:tool` / `search:prompt` | 检索前同步 | Agent 调用 `memory_search` 工具或系统注入记忆前 |
| `watch` | 文件变化 | 轮询检测到 `memory/` 目录文件增删改 |
| `timer` | 定时同步 | 可选，按配置间隔（默认关闭） |
| `session-delta` | 会话增量 | 累积消息达到字节/条数阈值 |

上层检索入口: `MemoryRetriever.search()`（`opensquilla/memory/retrieval.py`），在搜索前会先调用 `sync_manager.sync(reason="search:...")` 确保索引最新。

#### ⑤ 语义搜索 — 怎么找到最相关的记忆？

混合搜索（Hybrid Search）是记忆检索的核心算法：

- 源码: `opensquilla/memory/store.py` — `LongTermMemoryStore.search()` 方法
- 默认权重: **向量搜索 70% + 关键词搜索 30%**（`vector_weight=0.7, text_weight=0.3`）

**向量搜索路径**（`_vector_search()`）：

```
用户查询 → EmbeddingProvider.embed_query() → 查询向量
→ sqlite-vec MATCH (L2 距离) → 按距离排序 → 距离转分数 (1 - distance/2)
```

**关键词搜索路径**（`_fts_search()`）：

```
用户查询 → jieba 分词 + FTS5 查询构造 → chunks_fts MATCH → BM25 排序 → 分数归一化
```

**混合合并**（`_hybrid_search()`）：

```
两个搜索路径的结果按 chunk_id 合并 → combined_score = 0.7×vector_score + 0.3×text_score
→ 词汇保证: 关键词高匹配但向量分低的条目也可入选（Lexical Guarantee）
```

降级策略: 如果向量搜索失败（sqlite-vec 不可用 / 查询嵌入失败），自动退回到纯 FTS 关键词搜索。

#### ⑥ 结果排序 — 选出最相关的 Top-K

检索结果经过多层排序和过滤：

- 源码: `opensquilla/memory/retrieval.py` — `MemoryRetriever.search()` 方法

**排序管道**:

```
原始结果 (最多 200 条)
  → 可选: 时间衰减 (temporal_decay) — 旧记忆按半衰期降低分数
  → 过滤: 按 min_score 阈值 + 词法保证标记 (relaxed/lexical_guaranteed)
  → 排序: 按 source 加权 (sessions 源默认权重 0.92，memory 源权重 1.0)
  → 可选: MMR 重排 (Maximal Marginal Relevance) — 增加结果多样性
  → 截断: Top-K (默认 10 条)
```

**时间衰减公式**（可选，默认关闭）:
```
decayed_score = score × e^(-λ × age_days)
其中 λ = ln(2) / half_life_days
```
- 永久文件（`MEMORY.md`、不包含日期的 `memory/` 文件）不做衰减

#### ⑦ 注入上下文 — 记忆怎么进入 AI 的"参考材料"？

- 源码: `opensquilla/engine/runtime.py` — `_load_memory_md()` 和 `MemorySnapshot` 类
- 源码: `opensquilla/engine/turn_runner/agent_bootstrap_stage.py` — `AgentBootstrapStage` 在每次对话启动时加载记忆

**注入流程**:

```
每次对话开始
  → AgentBootstrapStage 调用 warm_and_capture()
  → 加载 memory_snapshot（MemorySnapshot 对象，含 memory_md + daily_notes）
  → 构建系统提示词时注入 memory_md 内容
  → Agent 看到「你之前说过……」「用户偏好……」等上下文信息
```

**注入控制**:

- `private_memory_allowed` 标志控制是否注入记忆（stateless 会话不注入）
- 记忆快照（`MemorySnapshot`）在会话生命周期内缓存，避免重复读取磁盘
- 记忆源文件变更后，通过 `MemorySnapshotRefreshPort` 刷新快照

### 生命周期总结

```
写入: 用户对话 → Flush 子Agent / TurnCapture → memory/*.md 文件
  ↓
索引: MemorySyncManager 检测文件变化 → chunk_text() 分块 → EmbeddingProvider 生成向量
  ↓
存储: LongTermMemoryStore.index_file() → chunks + chunks_fts + chunks_vec 三表写入
  ↓
检索: MemoryRetriever.search() → 混合搜索 (向量 70% + 关键词 30%) → 排序/过滤/截断
  ↓
注入: MemorySnapshot.memory_md → 拼入系统提示词 → Agent 获得上下文
```

> **一句话**: 记忆系统像一个"自动化的私人档案馆"——你说话时自动归档，你需要时自动调取，全程不需要你手动操作。写入、索引、检索、注入四个环节环环相扣，让 AI 越来越懂你。
