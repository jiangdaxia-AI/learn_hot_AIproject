# 03-05 · 记忆系统 (Memory) — 深度剖析

> **文件数**：22 个 Python 文件 | **核心类**：`MemoryManager`（`memory/manager.py:278`） | **技术栈**：sqlite-vec 本地向量搜索 + SQLite 元数据 | **Embedding 提供商**：3 种

---

## 定位

记忆系统是 OpenSquilla 的"长期记忆"。它让 AI 能记住你的偏好、项目上下文、历史经验，而不需要每次把整个对话历史塞进提示词（那会非常费 token）。核心设计是**写入时自动触发、检索时按需加载**。

---

## 生活化比喻

> 记忆系统像你的**私人笔记本**。每次你跟 AI 说"我喜欢用 Python"、"公司项目用 FastAPI"，AI 就记在本子上。下次你问新问题，AI 先翻本子——"哦，他喜欢 Python，用 FastAPI"，直接给出对口的答案，不用你再说一遍。

## 三、记忆写入流程（7 步）

```
步骤 1：触发条件判断
  MemoryManager 判断是否需要写入
  - 用户明确说了偏好信息
  - 对话中出现了重要上下文
  - 手动触发（/memory add）

步骤 2：文本分块 (chunk_text)
  将长文本分割成适合向量化的块
  每块大小可配置

步骤 3：向量化 (EmbeddingProvider)
  将文本块转换为向量
  根据配置选择 Local/OpenAI/Ollama embedding

步骤 4：存储 (LongTermMemoryStore)
  向量 → sqlite-vec 索引
  文本 + 元数据 → SQLite 表
  关联 source 信息

步骤 5：同步 (MemorySyncManager)
  增量同步到磁盘
  多会话共享

步骤 6：元数据索引
  记录写入时间、来源、类型
  支持按类型/时间过滤

步骤 7：代理通知
  通知 MemoryManager 有新记忆可用
  下次检索时自动包含
```

---

## 四、记忆检索流程（6 步）

```
步骤 1：查询向量化
  用户问题 → 文本 → Embedding → 向量

步骤 2：向量相似搜索 (sqlite-vec)
  在向量索引中搜索最相似的 top-K 结果
  相似度阈值过滤

步骤 3：混合搜索 (hybrid mode)
  向量搜索 + 关键词搜索
  合并排序

步骤 4：元数据过滤
  按时间、类型、来源过滤

步骤 5：结果返回
  MemorySearchResult 列表（含分数和来源）

步骤 6：上下文注入
  将检索到的记忆注入到 Agent 的上下文中
```

## 五、Embedding 提供商对比

| 提供商 | 类 | 隐私 | 速度 | 适用场景 |
|--------|---|------|------|---------|
| LocalEmbedding | `LocalEmbeddingProvider` | 完全本地 | 快 | 隐私敏感场景 |
| OpenAIEmbedding | `OpenAIEmbeddingProvider` | 云端 | 快 | 高质量向量 |
| OllamaEmbedding | `OllamaEmbeddingProvider` | 本地 | 中 | 开源模型 |
| NullEmbedding | `NullEmbeddingProvider` | - | - | 禁用向量搜索 |

## 六、核心术语

| 术语 | 含义 |
|------|------|
| **Embedding** | 文本→向量转换，让语义相近的文本在向量空间中靠近 |
| **sqlite-vec** | SQLite 扩展，支持向量存储和相似搜索 |
| **chunk** | 文本分块，将长文本分成适合向量化的小段 |
| **hybrid search** | 向量搜索 + 关键词搜索混合 |
| **semantic search** | 纯语义向量搜索 |
| **flush** | 将内存中的记忆写入磁盘 |
