# 03-08 · 安全与沙箱 — 大白话教材

> **面向读者**：产品经理、运营人员 | **难度**：⭐⭐ 进阶 | **阅读时间**：约 12 分钟

---

## 一句话说清楚

安全层是 OpenSquilla 的保险丝。AI 执行命令、读写文件时，安全层确保它不会删掉你的重要文件、访问不该访问的网站、消耗太多资源。

---

## 生活化比喻

> 安全层像**银行的安保系统**。你让 AI 去金库（文件系统）取东西，安保系统会逐层检查：你有没有权限？取的是不是你的东西？有没有人签字同意（审批）？如果 AI 想直接把金库搬走（危险操作），安保系统直接拒绝。

---

## 一、三层防御体系（逐层递进）

第一层：权限策略 — 你能做什么？
  任何操作都要先过这一关，决定操作的安全等级
  读文件 -> 标准级，写文件 -> 严格级

第二层：审批门控 — 谁同意你做？
  危险操作需要人工审批，审批通过后限时有效
  连续拒绝 3 次 -> 暂停会话

第三层：沙箱隔离 — 怎么安全地做？
  AI 的操作在隔离环境里执行
  限制文件访问、网络访问、CPU/内存/时间
---

## 二、一次工具调用的 8 道安检

每次 AI 想调一个工具（比如执行命令、写文件），不是直接执行的，而是先过 8 道安检：

步骤 1：声明权限
  工具告诉系统：我要读文件/写文件/执行命令/访问网络
  系统分配对应的权限矩阵

步骤 2：确定安全等级
  - 读文件 -> 标准级（无需审批）
  - 写文件（工作区内）-> 标准级
  - 写文件（工作区外）-> 严格级（需要审批）
  - 执行代码 -> 严格级（需要审批）
  - 网络访问 -> 严格级到锁定级（取决于来源是否可信）

步骤 3：路径检查（有没有碰敏感文件？）
  - 命中了敏感路径（如 SSH 密钥、AWS 凭据、系统密码文件）-> 直接拦截
  - 没命中 -> 进入下一步

步骤 4：网络检查（能不能访问这个网站？）
  - 在白名单里 -> 放行
  - 不在白名单 -> 需要审批
  - 在黑名单里 -> 拒绝

步骤 5：审批判断
  - 不需要审批 -> 直接执行
  - 需要审批 -> 加入审批队列，等待用户确认
    - 用户同意 -> 执行
    - 用户拒绝 -> 记录拒绝
      - 连续拒绝 3 次 -> 暂停整个会话
  - 拒绝后重试同一操作 -> 直接拒绝（防止死循环）

步骤 6：选择隔离环境
  - Linux -> 用 Linux 容器技术隔离
  - macOS -> 用 macOS 原生沙箱隔离
  - Windows -> 用 Windows 权限控制隔离
  - 沙箱不可用 -> 拒绝执行（绝不偷偷回退到不安全模式）

步骤 7：执行操作
  - 文件系统隔离：只能看到被允许的目录
  - 网络隔离：按配置断网/只允许白名单/全开
  - 资源限制：限制 CPU 时间、内存上限、最大进程数、超时时间
  - 环境变量过滤：只传递被允许的环境变量

步骤 8：返回结果
  成功 -> 返回执行结果
  超时 -> 强制终止
  被拒绝 -> 返回拒绝原因

## 三、安全等级说明

| 等级 | 含义 | 网络 | 文件写入 | 需要审批 |
|------|------|------|---------|---------|
| 标准级 | 日常操作 | 仅本地回环 | 仅工作区 | 不需要 |
| 严格级 | 危险操作 | 白名单网站 | 需要审批 | 需要 |
| 锁定级 | 最高风险 | 完全断网 | 需要审批 | 需要 |

---

## 四、5 种隔离环境

| 环境 | 适用系统 | 隔离方式 | 比喻 |
|------|---------|---------|------|
| Linux 容器 | Linux | 轻量级容器技术，隔离文件/网络/进程 | 全封闭集装箱 |
| macOS 沙箱 | macOS | 系统原生沙箱，默认拒绝一切、按白名单放行 | 电子围栏 |
| Windows 沙箱 | Windows | 权限控制 + 防火墙规则 | 门禁系统 |
| 无隔离 | 测试/禁用 | 不做隔离，但保留资源限制 | 不设防 |
| 拒绝执行 | 兜底安全 | 找不到沙箱时拒绝所有操作 | 紧急熔断 |

> 所有平台自动选择最优隔离方案，用户无需关心。找不到真正沙箱时绝不偷偷回退到不安全模式。

| 类别 | 示例 |

| 系统密码 | Linux 系统密码文件、sudo 权限配置 |

## 七、对产品/运营同学的一句话总结

> 安全层是 AI 的安全带——三层防御（权限策略 -> 审批门控 -> 沙箱隔离），8 道安检，覆盖了文件读写、命令执行、网络访问的所有风险。敏感文件（密钥、密码）直接拦截，危险操作需要人工审批，所有操作在隔离环境中执行。即使用户不小心让 AI 做了危险操作，安全层也会拦住。

## 八、沙箱环境变量过滤（seatbelt env override）

### 是什么

macOS 沙箱（Seatbelt）在每次工具执行时，会过滤环境变量——只允许 `env_allowlist`（白名单）中的环境变量传入沙箱，其他一律拒绝。

### 实际运行数据

从实际日志中，环境变量拒绝事件发生了 **50,325 次**，主要被拒绝的变量是：

| 被拒绝的变量 | 原因 |
|------------|------|
| `TMPDIR` | Seatbelt 自己管理临时目录，不允许外部覆盖 |
| `OSLogRateLimit` | 系统日志速率限制，不在白名单中 |

### 源码逻辑

```python
# seatbelt.py 第 252-255 行
for key, value in override_env.items():
    if key not in allowlist:          # TMPDIR 不在白名单里
        log.debug("拒绝: key=%s", key)  # 打一条 DEBUG 日志
        continue                       # 跳过，用 seatbelt 自己管理的 TMPDIR
```

### 这是正常行为

`TMPDIR` 被拒绝是**设计如此**——Seatbelt 自己管理沙箱的临时目录，不允许外部覆盖。50,325 次是 DEBUG 级别日志，不影响功能，但日志量较大。

### 优化建议

在 `seatbelt_env_for_policy()` 函数开头预过滤 `TMPDIR` 和 `OSLogRateLimit` 等已知会被拒绝的 key，减少无意义的日志输出。
