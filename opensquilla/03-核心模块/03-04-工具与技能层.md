# 03-04 · 工具与技能层 (Tools & Skills) — 深度剖析

> **文件数**：工具 24 + 技能 9 + 91 个 SKILL.md | **核心类**：`ToolRegistry`（`tools/registry.py`） | **工具数量**：30+ 内置工具 | **技能层数**：6 层优先级

---

## 定位

工具层是 OpenSquilla 的"手脚"——AI 能思考，但不能实际操作。工具层赋予 AI 执行代码、读写文件、搜索网页、发送消息等能力。技能层是"打包好的组合拳"——把多个工具调用组合成可复用的工作流。

> 来源：`tools/__init__.py`、`tools/builtin/` 目录、`skills/__init__.py` L1 "Six-layer architecture"

---

## 生活化比喻

> 工具就像**瑞士军刀上的各种配件**——螺丝刀、剪刀、开瓶器，每样一个功能。技能就像**手机快捷指令**——"回家模式"一键关灯+锁门+开空调，把多个动作打包执行。

## 一、ToolRegistry — 工具注册表

`ToolRegistry`（`tools/registry.py`）是工具的统一注册中心：

```python
class ToolRegistry:
    def register(tool: RegisteredTool)  # 注册工具
    def get(name: str) -> ToolSpec       # 查找工具
    def list_all() -> list[ToolSpec]     # 列出所有工具
    def get_definitions() -> list[ToolDefinition]  # 获取 LLM 可用的工具定义
```

每个工具注册为 `RegisteredTool`，包含：
- `name`: 工具名称（如 `exec_command`）
- `description`: 工具描述（LLM 看到的功能说明）
- `parameters`: JSON Schema 参数定义
- `handler`: 实际执行函数
- `permission`: 权限要求

> 来源：`tools/registry.py` ToolRegistry 类

## 三、ToolContext — 工具执行上下文

每个工具调用时，都会传入 `ToolContext`（`tools/types.py`）：

| 字段 | 类型 | 含义 |
|------|------|------|
| `session_key` | str | 当前会话标识 |
| `caller_kind` | CallerKind | 调用者类型（user/channel/cron/subagent） |
| `workspace_dir` | str | 工作目录 |
| `sandbox_policy` | SandboxPolicy | 沙箱安全策略 |
| `approval_callback` | callable | 审批回调函数 |
| `on_runtime_event` | callable | 运行时事件回调 |
| `usage_tracker` | UsageTracker | 用量追踪器 |

> 来源：`tools/types.py` ToolContext 类

## 四、技能系统 — 6 层架构

技能分为 6 层，优先级从低到高（`skills/__init__.py` L1）：

```
优先级从低到高：
┌──────────────────────────────────────────────────────┐
│ 6. Workspace 层  ({workspace}/skills/)  ← 最高优先级 │
│    项目级自定义技能，覆盖所有下层                       │
├──────────────────────────────────────────────────────┤
│ 5. Project 层    ({workspace}/.agents/skills/)       │
│    项目级技能                                         │
├──────────────────────────────────────────────────────┤
│ 4. Personal 层   (~/.agents/skills/)                │
│    用户个人技能                                       │
├──────────────────────────────────────────────────────┤
│ 3. Managed 层    ($OPENSQUILLA_STATE_DIR/skills/)    │
│    本地安装的社区技能                                  │
├──────────────────────────────────────────────────────┤
│ 2. Bundled 层    (src/opensquilla/skills/bundled/)   │
│    随 OpenSquilla 发布的官方技能（91 个 SKILL.md）      │
├──────────────────────────────────────────────────────┤
│ 1. Extra 层      配置指定的额外目录                    │
│    扩展技能目录                                       │
└──────────────────────────────────────────────────────┘
```

### 技能的生命周期

```
步骤 1：加载 (SkillLoader)
  扫描 6 层目录 → 解析 SKILL.md → 构建 SkillSpec

步骤 2：资格检查 (check_eligibility)
  检查运行环境是否满足技能要求
  如：需要特定工具、API 密钥、操作系统

步骤 3：注入 (SkillInjector)
  将技能的提示词注入到 Agent 的上下文中
  在合适的时机激活技能

步骤 4：资源加载 (SkillResources)
  加载技能需要的额外资源（脚本、模板、参考文件）

步骤 5：执行
  Agent 根据技能定义的工作流执行工具调用

步骤 6：卸载
  技能不再需要时从上下文中移除
```

### SkillSpec 数据结构

| 字段 | 含义 |
|------|------|
| `name` | 技能名称 |
| `description` | 技能描述 |
| `triggers` | 自动激活的触发词 |
| `requires` | 依赖要求（Python 包、系统工具） |
| `install` | 安装指令列表 |
| `layer` | 所属层级（bundled/managed/personal/project/workspace） |

> 来源：`skills/types.py` SkillSpec, `skills/loader.py` SkillLoader, `skills/eligibility.py` check_eligibility
