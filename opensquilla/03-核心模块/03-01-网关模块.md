# 03-01 · 网关模块（Gateway）— 大白话版

> **模块规模**：77 个核心代码文件 | **核心入口**：应用工厂函数（接收 20+ 个组件参数） | **代码分析工具扫描**：57 个关键符号（跨 2 个文件） | **依赖注入**：20+ 个参数

---

## 定位

网关是整个 OpenSquilla 的**唯一入口**。所有外部请求——无论是命令行命令、网页控制台点击、还是飞书（字节跳动旗下的企业协作平台，类似 Slack/Teams，OpenSquilla 支持通过飞书收发消息）消息——都必须经过网关。它不是简单的网页请求转发器，而是一个完整的"应用工厂"，接收 20+ 个组件参数来组装整个服务。

> 说明：应用工厂函数的核心代码位于网关模块，接收会话管理器、AI 提供商选择器、工具注册表、频道管理器、定时任务调度器、对话回合执行器等 20+ 个组件。

---

## 生活化比喻

> 网关像一个**五星级酒店的前台大堂**。每个客人的请求都要经过 5 道安检（中间件管道），然后大堂经理（请求调度器）根据需求分派到不同的服务员。如果要动保险箱（危险操作），前台会让你签字确认（审批队列）。

## 二、中间件管道（5 层安检）

每个请求到达后，先经过 5 层"安检"：

```
请求 →
  1. 安全头检查（强制加密连接、限制可加载的资源来源、禁止被嵌套到其他网站）
  2. 限流检查（防止某个用户请求太快太多）
  3. 身份认证（验证"你是谁"，通过密钥或 Token 确认身份）
  4. 跨域检查（控制哪些外部网站可以访问我们的服务）
  5. 同源校验（防止伪造请求攻击）
→ 业务处理
```

| 安检层 | 大白话 | 作用 |
|--------|------|------|
| 安全头 | 给网页加防护罩 | 强制加密、防止恶意脚本注入、防止被嵌入钓鱼网站 |
| 限流 | 流量控制阀门 | 限制每个用户/IP 的请求频率，防止滥用 |
| 身份认证 | 门禁刷卡 | 验证请求者的密钥或身份令牌是否有效 |
| 跨域 | 访客白名单 | 控制哪些外部网站可以调用我们的服务 |
| 同源校验 | 防冒充检查 | 确保请求来源是可信的，不是伪造的 |

## 四、请求调度器 — 统一请求分发

请求调度器是网关的"大堂经理"，负责把每个请求分配给对应的处理人员：

```
POST /api/rpc {method: "chat.send", params: {...}}
│
▼
┌─ 请求调度器 ────────────────────────────────────────┐
│ 1. 解析请求类型（"你要干什么？"）                    │
│ 2. 查找对应的处理人员                                │
│ 3. 参数校验（参数格式对不对？）                       │
│ 4. 调用处理人员                                      │
│ 5. 返回标准格式的响应                                │
│                                                      │
│ 错误码对照：                                          │
│   请求格式错误 → 400（"你的请求格式不对"）             │
│   未授权 → 403（"你没有权限"）                        │
│   找不到 → 404（"你要的东西不存在"）                   │
│   会话冲突 → 409（"这个会话正在被占用"）               │
│   队列满了 → 429（"太多请求了，请稍等"）               │
│   服务不可用 → 503（"服务暂时挂了"）                   │
└──────────────────────────────────────────────────────┘
```

## 五、实时通信（WebSocket）

网关支持实时推送的长连接，用于向用户端实时推送消息：

| 事件类型 | 内容 | 方向 |
|---------|------|------|

| 工具调用 | AI 调用工具的通知 | 服务端→客户端 |
| 工具结果 | 工具执行结果 | 服务端→客户端 |
| 需要审批 | 需要用户确认的操作 | 服务端→客户端 |
| 会话更新 | 对话状态变更 | 服务端→客户端 |
| 心跳 | 连接保活信号 | 双向 |

## 六、审批队列系统

危险操作进入审批队列，等待人工确认：

```
┌─ 审批流程 ───────────────────────────────────────┐
│ 1. AI 请求执行危险操作（如写文件、执行命令）        │
│ 2. 工具处理器检查权限策略                           │
│ 3. 如需审批 → 加入审批队列                         │
│ 4. 通知用户（实时推送）                             │
│ 5. 用户确认/拒绝                                   │
│ 6. 确认后执行，拒绝后返回错误                       │
│                                                    │
│ 审批项包含：                                        │
│   - 操作类型（执行命令/写文件/网络请求）              │
│   - 操作详情（完整命令/文件路径/网址）               │
│   - 风险等级（低/中/高）                            │
│   - 时间戳                                         │
└────────────────────────────────────────────────────┘
```
