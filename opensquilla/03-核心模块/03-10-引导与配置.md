# 03-10 · 引导与配置 — 通俗教材

> **文件数**：21 个文件 | **核心模块**：引导引擎（负责编排 6 步配置向导，帮用户一步步完成初始设置） | **影响范围**：被 23 处代码调用 | **网页端配套**：配置目录页面（从后端拉取AI服务商、消息通道、路由器等配置选项）

---

## 定位

引导模块是 OpenSquilla 的**一键安装向导**。用户首次使用时，引导模块一步步帮用户配置 AI 服务商（即提供 AI 模型服务的公司，如 OpenAI、DeepSeek 等）、选择模型、设置消息通道，把复杂的配置过程变成交互式问答。

---

## 生活化比喻

> 引导模块像**新手机的开机向导**。你拿到新手机，它一步步带你选语言、连 Wi-Fi、登录账号、设置指纹。你不用知道背后的技术细节，跟着点就行。

---

## 一、引导引擎架构（6 步引导流程）

引导引擎的完整引导流程，像一个贴心的导购员。整个流程由 `flow.py` 中的 `run_interactive_onboard` 函数编排，经过「迁移检测 → 服务商选择 → 路由器配置 → 可选配置 → 持久化」的线性流程。每个步骤完成后自动持久化，按 Esc 取消不会丢失已保存的配置。

---

### 步骤 1：AI 服务商选择（6 个子步骤）

这是引导流程的核心入口，由 `flow.py` 中的 `_ask_provider_choice` 和 `_ask_provider_fields` 函数驱动。

#### 子步骤 1.1：展示服务商列表，用户用关键词筛选

**你看到什么**：终端里弹出一个带搜索过滤功能的选择列表。列表列出了所有运行时支持的 AI 服务商，TokenRhythm 排在首位作为推荐，其次是 OpenRouter，其余按字母排序。总共支持 40+ 个提供商，包括 OpenAI、Anthropic、DeepSeek、Ollama（本地）、Google Gemini、阿里云 DashScope、Moonshot AI、MiniMax、Zhipu（智谱）、Baidu Qianfan、SiliconFlow、Volcengine Ark 等。

**你做什么**：直接输入关键词（比如 "deep"）就能实时过滤列表，不需要用方向键一条条翻。过滤后回车选中。

**系统做了什么**：`_ask_provider_choice` 调用 `list_provider_setup_specs()`（`provider_specs.py`）拉取所有服务商的 `ProviderSetupSpec`。每个 spec 包含 `provider_id`、`label`、`runtime_supported`（是否可运行时）、`verification`（verified / experimental）等字段。列表按 `_CATALOG_RANK` 排序，TokenRhythm 排第 0、OpenRouter 排第 1。`use_search_filter=True` 打开 questionary 的搜索过滤模式。

**如果失败怎么办**：如果用户按 Esc 取消，抛出 `UserCancelledError(section="provider")`，引导流程终止——因为服务商是必选步骤，还没有任何配置被保存。

**源码位置**：`flow.py` → `_ask_provider_choice()`，`provider_specs.py` → `list_provider_setup_specs()`、`_CATALOG_RANK`

#### 子步骤 1.2：选择 API Key 的来源方式

**你看到什么**：选中服务商后，系统询问「API Key 从哪来？」。显示两个选项：① "Paste API key"（粘贴密钥）② "Use environment variable OPENAI_API_KEY"（使用环境变量）。如果环境变量已经设置了（比如 `OPENAI_API_KEY` 已有值），第二个选项后面会标注 "(detected)"。

**你做什么**：如果你已经设了环境变量，选第二个直接跳过输入。否则选第一个，下一步粘贴密钥。

**系统做了什么**：`_ask_provider_fields` 调用 `_api_key_source_choices(env_key)` 生成选项列表。如果 `spec.requires_api_key` 为 True（绝大多数云服务商），先检查 `os.environ.get(env_key)` 是否已有值，有则给第二个选项加上 `(detected)` 后缀。默认选中逻辑：如果环境变量已设置，默认选环境变量；否则默认选粘贴密钥。

**如果失败怎么办**：这一步只是选择方式，不会失败。如果用户 Esc 取消，同 1.1 一样终止引导。

**源码位置**：`flow.py` → `_ask_provider_fields()`、`_api_key_source_choices()`、`_api_key_env_choice()`

#### 子步骤 1.3：粘贴 API Key 或确认环境变量

**你看到什么**：如果选了「粘贴 API Key」，终端出现一个密码输入框——输入时显示为星号掩码，什么都看不到。如果选了「使用环境变量」，系统直接跳过这一步。

**你做什么**：粘贴或手动输入 API Key，回车。如果选了环境变量，什么都不用做。

**系统做了什么**：`questionary.password("API key", validate=_secret_value_validator("API key"))` 创建密码输入框。`_secret_value_validator` 先检查非空（`_required_value`），再检查粘贴内容是否包含终端转义序列（`_secret_paste_error`），比如某些终端右键粘贴会带乱码，这时提示"用右键、Shift+Insert 或环境变量方式"。如果选了环境变量，`answers["api_key_env"]` 被设为环境变量名，`answers["api_key"]` 留空。

**如果失败怎么办**：粘贴内容包含乱码 → 显示红色提示，要求重新输入。输入为空 → 显示 "API key is required"。

**源码位置**：`flow.py` → `_secret_value_validator()`、`_secret_paste_error()`、`redaction.py`

#### 子步骤 1.4：填写 Base URL 和代理（条件触发）

**你看到什么**：如果服务商需要自定义 Base URL（如 Ollama 默认 `http://localhost:11434`、vLLM、LM Studio、自定义 OpenAI 兼容端点），终端会额外显示两个输入框——Base URL 和 HTTP 代理地址。本地服务商（Ollama）的 Base URL 是必填的，且有默认值。云端服务商（OpenAI 等）的 Base URL 可留空，留空则用官方默认地址。

**你做什么**：本地服务商：确认或修改默认的 Base URL（如 `http://localhost:11434`）。云端服务商：通常直接回车跳过。HTTP 代理：如果你需要代理翻墙，填 `http://127.0.0.1:7890`，否则直接回车跳过。

**系统做了什么**：`spec.requires_base_url` 决定 Base URL 是否必填。如果必填，`_base_url_validator` 检查输入是否以 `http://` 或 `https://` 开头。如果重新运行引导（更新已有配置），`_stored_llm_entry` 从 config 中读取已保存的 base_url 和 proxy 作为默认值，这样用户直接回车不会覆盖掉之前的自定义地址。

**如果失败怎么办**：Base URL 必填但用户没填 → 提示 "Base URL is required for this provider"。Base URL 不以 http:// 或 https:// 开头 → 提示 "Base URL must start with http:// or https://"。Esc 取消 → 终止引导。

**源码位置**：`flow.py` → `_base_url_validator()`、`_stored_llm_entry()`、`provider_specs.py` → `ProviderSetupSpec.requires_base_url`

#### 子步骤 1.5：连接探测（自动验证 API Key 是否有效）

**你看到什么**：终端短暂显示 "Checking the connection…"，然后显示结果。如果成功：显示 "◆ connection verified"。如果失败：弹出一个警告面板，里面显示脱敏后的错误信息（比如 "401 Unauthorized"），然后问 "Save anyway?"，默认选项是「是」。

**你做什么**：验证成功：什么都不用做，自动继续。验证失败：如果你确认 API Key 是对的（比如网络问题导致临时失败），回车选「是」继续保存。如果 API Key 确实错了，选「否」回到输入步骤重新填。

**系统做了什么**：对于标记为 `can_probe=True` 的服务商，`_run_provider_probe` 调用 `probe_llm_provider`（`probe.py`）发送一条轻量级请求（`max_tokens=1`，消息内容为 "ping"），30 秒超时。探测结果返回 `ProviderProbeResult`，包含 `ok`、`failure_kind`、`message`、`latency_ms` 等字段。失败时 `_confirm_save_after_failed_check` 显示脱敏后的错误详情（`redact_error_text` 过滤掉密钥等敏感信息），默认选项为「是」——验证失败绝不阻塞配置保存。对于支持路由器的服务商，额外调用 `_verify_router_provider_connection` 使用默认 tier 的模型来探活。Ctrl+C 在探测等待期间只会跳过探测，不会终止整个引导（`except KeyboardInterrupt` 被捕获）。

**如果失败怎么办**：探测本身失败（网络不可达等）→ 静默跳过，不阻塞配置。探测返回错误 → 显示红色警告面板 + 脱敏错误信息，默认「是」继续保存，用户选「否」则回到输入步骤。

**源码位置**：`flow.py` → `_run_provider_probe()`、`_probe_and_confirm()`、`_confirm_save_after_failed_check()`、`_verify_router_provider_connection()`；`probe.py` → `probe_llm_provider()`

#### 子步骤 1.6：写入内存配置对象

**你看到什么**：终端没有额外输出（这一步在后台静默完成）。

**你做什么**：什么都不用做。

**系统做了什么**：`upsert_llm_provider`（`mutations.py`）将所有收集到的字段——`provider_id`、`model`、`api_key`、`api_key_env`、`base_url`、`proxy`——写入内存中的 `GatewayConfig` 对象。model 字段的写入策略：如果是路由型服务商且首次保存，`model` 设为 `""`（空字符串），由 mutation 层使用服务商的默认模型；如果是重新运行引导（已有配置），`model` 设为 `None`（mutation 层保持当前值不变），防止用户一路回车覆盖掉手动设置的模型。

**如果失败怎么办**：mutation 层的验证失败（如必填字段缺失）→ 抛出异常，引导终止。但此时 API Key 等敏感信息尚未写入磁盘。

**源码位置**：`flow.py` → `_ask_provider_fields()` 末尾；`mutations.py` → `upsert_llm_provider()`

### 步骤 2：模型配置（6 个子步骤）

模型配置与服务商选择紧密耦合，由 `flow.py` 中的 `_ask_provider_fields` 和 `_ask_direct_provider_model` 函数处理，分为「路由型」和「直接型」两种路径。

#### C0/C1/C2/C3 四个层级是什么？

> 这是 SquillaRouter 的核心概念，请先理解再往下看：
>
> | 层级 | 目标 | 类比 | 典型模型 |
> |------|------|------|---------|
> | **C0** | 最简单/最便宜/最快的任务 | 简单问答、闲聊、格式转换 | 轻量模型，如 `gpt-4o-mini` |
> | **C1** | 中等复杂度任务 | 一般编程、文档总结、翻译 | 中等模型，如 `gpt-4o` |
> | **C2** | 较强推理任务 | 复杂代码、逻辑推理、多步分析 | 强模型，如 `claude-sonnet-4-20250514` |
> | **C3** | 最强/最贵/最深度任务 | 深度分析、学术研究、大型重构 | 顶级模型，如 `claude-opus-4-20250514` |
>
> 路由器会根据任务难度自动选择对应层级的模型。你不需要手动指定用哪个模型——系统自己判断"这个问题该用 C1 还是 C3"。默认文本层级一般为 C1。

#### 子步骤 2.1：判断服务商是否支持路由器

**你看到什么**：终端没有额外输出（这一步在后台静默完成）。

**你做什么**：什么都不用做。

**系统做了什么**：`_ask_provider_fields` 检查 `spec.router_supported`。这个字段由 `provider_specs.py` 中的 `_is_router_supported_provider` 函数决定：如果服务商在 `_INLINE_ROUTER_SUPPORTED_PROVIDER_IDS` 集合中（如 qianfan、volcengine_coding_plan、kimi_coding_openai 等），或者有预置的 curated router ladder（`_has_curated_router_ladder` 返回 True），则 `router_supported=True`。TokenRhythm、OpenRouter、DeepSeek、DashScope、OpenAI、Anthropic 等主流服务商都支持路由器。

**如果失败怎么办**：这一步是纯判断逻辑，不会失败。

**源码位置**：`flow.py` → `_ask_provider_fields()` 中 `getattr(spec, 'router_supported', False)` 分支；`provider_specs.py` → `_is_router_supported_provider()`、`_has_curated_router_ladder()`

#### 子步骤 2.2（路由型）：显示自动管理提示，无需手动输入

**你看到什么**：终端不显示模型 ID 输入框。系统直接进入步骤 1.5 的连接验证，然后自动进入步骤 3（路由器配置）。

**你做什么**：什么都不用做。

**系统做了什么**：对于路由型服务商，`_ask_provider_fields` 跳过模型输入，直接调用 `_verify_router_provider_connection` 用路由器默认 tier 的模型来探活。然后 `answers["model"]` 设为 `None`（已有配置时保持当前值）或 `""`（首次配置时由 mutation 层自动推导默认模型）。

**如果失败怎么办**：连接验证失败的处理同步骤 1.5——显示 "Save anyway?" 确认框，默认「是」继续。

**源码位置**：`flow.py` → `_ask_provider_fields()` 路由型分支；`_verify_router_provider_connection()`

#### 子步骤 2.3（直接型）：尝试模型发现，展示下拉列表

**你看到什么**：终端短暂显示 "Checking the connection…"，然后（如果发现成功）弹出一个可选择的下拉列表。每行显示模型 ID 和上下文窗口大小，如 `gpt-4o  ·  128,000 ctx`。列表底部有一个「Type a model id…」选项，供你手动输入列表中没有的模型。

**你做什么**：用方向键浏览列表，回车选中。如果你想用的模型不在列表里，选「Type a model id…」进入下一步手动输入。

**系统做了什么**：`_ask_direct_provider_model` 先调用 `_probe_and_confirm` 用 `spec.default_direct_model`（如 OpenAI 的 `gpt-4o`）探活。然后调用 `_run_provider_discovery` → `discover_selectable_provider_models`（`probe.py`）拉取该服务商的实时模型列表。每个模型行由 `_discovered_model_label` 格式化：如果 `context_window > 0`，显示 `model_id  ·  NNN ctx`。如果服务商有已保存的模型（重新运行引导），`stored_model` 作为默认选项预选中。

**如果失败怎么办**：探活失败 → 显示 "Save anyway?" 确认框，选「否」则回到手动输入。模型发现失败（网络不通 / 服务商不支持 list models）→ 自动降级为手动输入模型 ID。如果探活和发现都失败，先显示确认框，用户选「是」后再进入手动输入。

**源码位置**：`flow.py` → `_ask_direct_provider_model()`、`_run_provider_discovery()`、`_discovered_model_label()`；`probe.py` → `discover_selectable_provider_models()`

#### 子步骤 2.4（直接型）：手动输入模型 ID

**你看到什么**：一个文本输入框，提示 "Model id"。如果之前配置过模型（重新运行引导），默认值已填好，回车即可保持。

**你做什么**：输入模型 ID（如 `gpt-4o`、`claude-sonnet-4-20250514`），回车。

**系统做了什么**：`_prompt_free_text_model` 调用 `questionary.text("Model id", validate=_required_value("Model id"))`。如果非空验证失败（用户直接回车没填），会重新提示 "Model id is required"。如果 `stored_model` 有值（重新运行引导），用它作为默认值。

**如果失败怎么办**：输入为空 → 重新提示 "Model id is required"。如果步骤 2.3 的探活还没做过（`needs_typed_probe=True`），输入完模型 ID 后系统会用这个 ID 再跑一次 `_probe_and_confirm` 探活。

**源码位置**：`flow.py` → `_prompt_free_text_model()`

#### 子步骤 2.5：连接验证（直接型）

**你看到什么**：终端显示 "Checking the connection…"，成功则显示 "◆ connection verified"。失败则显示 "Save anyway?" 确认框。

**系统做了什么**：同步骤 1.5 的 `_probe_and_confirm` 流程。用用户选择或输入的模型 ID 发送一条轻量级请求验证连接。`_probe_and_confirm` 返回三种状态：`"no_model"`（没有可用的探活模型，跳过）、`"verified"`（成功）、`"failed"`（失败但用户选择继续保存）。

**如果失败怎么办**：同步骤 1.5——验证失败不阻塞配置，默认「是」继续保存。

**源码位置**：`flow.py` → `_probe_and_confirm()`、`_confirm_save_after_failed_check()`

#### 子步骤 2.6：写入模型配置

**你看到什么**：终端没有额外输出。

**系统做了什么**：`upsert_llm_provider`（`mutations.py`）将 model 字段写入内存中的 `GatewayConfig`。路由型服务商：`model=""` 或 `model=None`，由 mutation 层推导默认值。直接型服务商：`model="gpt-4o"` 等用户输入的值。

**如果失败怎么办**：mutation 层验证失败 → 抛出异常。

**源码位置**：`flow.py` → `_ask_provider_fields()` 末尾；`mutations.py` → `upsert_llm_provider()`

---

### 步骤 3：路由器配置（4 个子步骤）

路由器配置紧随服务商选择之后，由 `flow.py` 中的 `_ask_router_fields` 和 `_apply_router_section` 函数处理。这个步骤在服务商选择完成后自动触发，用户也可以 Esc 取消——取消不会丢失前面已输入的服务商凭证。

#### 子步骤 3.1：选择启用或禁用路由器

**你看到什么**：终端显示两个选项：① "SquillaRouter"（启用路由器）② "Disabled"（禁用路由器）。默认选中 "SquillaRouter"。

**你做什么**：回车启用路由器，或选 "Disabled" 关闭路由器。

**系统做了什么**：`_ask_router_fields` 调用 `_router_mode_choices` 生成两个选项。`_router_mode_default` 决定默认值：如果之前的配置中路由器是启用的，默认选 "SquillaRouter"；如果之前的配置中路由器是禁用的，默认选 "Disabled"。用户选择后通过 `_router_mode_to_internal` 转换为内部模式名：`"recommended"` 或 `"disabled"`。

**如果失败怎么办**：Esc 取消 → `_apply_router_section` 中的 `except UserCancelledError` 捕获，显示黄色提示 "router setup cancelled — keeping current router settings"，然后继续引导流程，不丢失已填的 API Key。

**源码位置**：`flow.py` → `_ask_router_fields()`、`_router_mode_choices()`、`_router_mode_to_internal()`、`_apply_router_section()`

#### 子步骤 3.2：查看路由器预览 + 选择默认文本层级

**你看到什么**：如果启用了路由器，终端显示当前路由器的默认配置预览。预览列出了四个层级的绑定关系，默认层级前用 ● 标记，其余用 ○ 标记：

```
◆ router default c1 → openai/gpt-4o
  ● c1          openai/gpt-4o
  ○ c0          openai/gpt-4o-mini
  ○ c2          openai/gpt-4o
  ○ c3          openai/gpt-4o
  ○ image_model openai/dall-e-3
```

然后显示 "Default text model" 选择框，列出 C0、C1、C2、C3 四个选项。

**你做什么**：查看预览确认配置正确。选择默认文本层级（一般选 C1），回车。

**系统做了什么**：`upsert_router(config, mode=mode)` 先用当前模式生成预览配置，`_print_router_defaults` 遍历 `_EXPOSED_ROUTER_TIERS`（C0、C1、C2、C3、image_model）和 `config.squilla_router.tiers` 打印每个层级的 provider/model。默认层级来自 `config.squilla_router.default_tier`（默认 C1）。然后 `_ask_or_cancel` 显示 "Default text model" 选择框，默认值为当前默认层级。

**如果失败怎么办**：Esc 取消 → 同 3.1，保持当前路由器设置不变。

**源码位置**：`flow.py` → `_print_router_defaults()`、`_text_tier_label()`、`_ask_router_fields()`

### 步骤 6：持久化配置（4 个子步骤）

持久化是整个引导流程的最后一步，但不是在最后才执行的——它在每一步完成后自动触发。由 `config_store.py` 中的 `persist_config` 函数处理。

#### 子步骤 6.1：检查目录可写

**你看到什么**：终端没有额外输出（这一步在后台静默完成）。如果目录不可写，在引导开始前就报错。

**你做什么**：什么都不用做。

**系统做了什么**：`_ensure_config_dir_writable` 在 `run_interactive_onboard` 开始时被调用，在第一个 prompt 出现之前。它用 `resolve_config_path` 解析目标路径，在目标目录中创建临时文件（`tempfile.mkstemp`）并立即删除，以验证目录可写。如果失败（权限不足），显示警告面板并 `raise SystemExit(2)` 退出——避免用户在输入完所有信息（包括 API Key）后才因权限不足而失败。

**如果失败怎么办**：目录不可写 → 显示红色警告面板 "Cannot write the configuration directory"，提示用户修改权限或通过 `--config` 参数 / `OPENSQUILLA_GATEWAY_CONFIG_PATH` 环境变量指定其他路径，然后退出（exit code 2）。

**源码位置**：`config_store.py` → `_ensure_config_dir_writable()`；`flow.py` → `run_interactive_onboard()` 开头

#### 子步骤 6.2：稀疏差异对比 + 合并写入

**你看到什么**：终端显示保存路径。例如 "Config saved to ~/.opensquilla/config.toml"。

**你做什么**：什么都不用做。

**系统做了什么**：`persist_config` 采用「稀疏差异写入」策略，不重写整个配置文件。具体流程：① `_persist_plan` 获取基线快照（`_persist_baseline`，在 `load_config` 时或上次 persist 时保存）和当前磁盘上的 TOML 数据（`merge_base`）。② `_diff_payload` 递归对比当前模型 dump 和基线快照，生成差异字典。差异叶子节点是 `_SetValue`（替换值）或 `_REMOVED`（删除键）。顶层 `_NON_PERSISTED_TOP_LEVEL_FIELDS`（如 `config_path`）被排除。③ `_merge_diff` 将差异合并到 `merge_base` 上——磁盘上未被此次变更涉及的字段保持不变。④ `restore_runtime_overrides` 回退环境变量覆盖的值（如 `OPENSQUILLA_LLM_PROXY`），防止环境变量被错误地写入配置文件。⑤ `GatewayConfig.model_validate` 重新验证合并后的配置，确保写入的内容合法。⑥ 如果 `force_persist_path_segments` 有值，强制写入指定路径。

**如果失败怎么办**：重新验证失败 → 抛出异常，配置不写入。磁盘上已有外部修改的非冲突字段 → 被保留（差异写入不会覆盖它们）。

**源码位置**：`config_store.py` → `persist_config()`、`_persist_plan()`、`_diff_payload()`、`_merge_diff()`、`restore_runtime_overrides()`

#### 子步骤 6.3：写临时文件 → 原子替换 + 文件锁

**你看到什么**：终端没有额外输出。

**你做什么**：什么都不用做。

**系统做了什么**：写入过程使用文件锁和原子替换保证安全性：① `_config_write_lock` 上下文管理器获取文件锁。Linux 使用 `fcntl.flock`（与 `_config_write_lock` 中的 `.lock` 文件配合），Windows 使用 `msvcrt.locking`。多个进程同时保存时，只有一个能拿到锁。② `tempfile.mkstemp` 在目标目录创建临时文件（前缀 `.config.toml.`，后缀 `.tmp`）。③ `tomli_w.dump` 将合并后的配置写入临时文件，然后 `fh.flush()` + `os.fsync(fh.fileno())` 强制刷到磁盘。④ `os.chmod(tmp_name, 0o600)` 设置文件权限为仅所有者可读写。⑤ `os.replace(tmp_name, target)` 原子替换——在 POSIX 系统上是原子操作，不会出现"写了一半文件被读到"的情况。如果符号链接指向目标文件，`persist_config` 会先 `target.resolve()` 拿到真实路径，写入真实文件，保留符号链接。

**如果失败怎么办**：临时文件写入失败 → 删除临时文件，抛出异常。原子替换失败 → 原配置文件保持不变，备份未被删除。并发写入冲突 → 文件锁阻塞等待，超时取决于操作系统默认行为。

**源码位置**：`config_store.py` → `persist_config()` 写入部分、`_config_write_lock()`

#### 子步骤 6.4：刷新基线 + 返回结果

**你看到什么**：全部配置完成后，终端显示引导完成提示和推荐的下一步操作。

**你做什么**：按照提示运行下一步操作，如 `opensquilla gateway run` 启动网关、`opensquilla chat` 测试对话。

**系统做了什么**：① `persist_config` 写入成功后，刷新 `config._persist_baseline` 和 `config._persist_raw_base`，这样下次 save 时 diff 基于最新写入的状态。② 返回 `PersistResult`，包含 `path`（写入路径）、`backup_path`（备份路径，如果启用了备份）、`restart_required`（是否需要重启网关）、`warnings`（警告列表）。③ `run_interactive_onboard` 汇总所有步骤的 `PersistResult`，通过 `_fold_persist_result` / `_merge_persist_results` 合并多个 `restart_required` 标志。④ 配置文件默认路径为 `~/.opensquilla/config.toml`，可通过 `--config` 参数或 `OPENSQUILLA_GATEWAY_CONFIG_PATH` 环境变量指定其他路径。路径解析优先级：`--config` 参数 > `OPENSQUILLA_GATEWAY_CONFIG_PATH` 环境变量 > 当前目录的 `opensquilla.toml` > `~/.opensquilla/config.toml`。

**如果失败怎么办**：如果用户中途取消（Esc），`except UserCancelledError` 在 `run_interactive_onboard` 中被捕获。但已完成的步骤配置已经通过 `persist_config` 保存到磁盘，不会丢失。用户可以通过 `opensquilla onboard --if-needed` 恢复未完成的配置。

**源码位置**：`config_store.py` → `persist_config()` 末尾、`resolve_config_path()`；`flow.py` → `run_interactive_onboard()` 末尾、`_fold_persist_result()`、`_merge_persist_results()`

## 五、环境探测
