## 一句话说明

题目评分系统是 DeepTutor 教学闭环的"判官"——学生提交答案后，它根据题型用不同策略判定对错，对错误答案进行分类，并把结果反馈给学生和掌握度系统。

## 业务价值

没有评分，学生不知道自己学得怎么样；有了评分，系统才能：
1. 即时反馈：学生答题后立刻知道对错
2. 错误分类：不只是"错了"，而是告诉你"错在哪类"
3. 驱动掌握度：评分结果是掌握度计算的核心输入
4. 个性化学习：错误类型决定下一步学什么

典型的使用场景：
1. 学生在 Book 里做一道选择题 -> 提交答案 -> 评分系统判定 -> 显示结果
2. 学生在 Mastery Path 做练习 -> 评分 -> 掌握度更新 -> 学习路径调整
3. AI 出题后自动评分 -> 记录答题历史 -> 生成学情报告

## 评分函数详解

### grade_answer() (grading.py:13)

**业务含义**：判定学生答案是否正确。

**参数**：
- user_answer: 学生提交的答案
- expected_answer: 标准答案
- question_type: 题型（choice/short/open）

**返回**：True（正确）/ False（错误）

**关键逻辑**（按题型分策略）：

1. **选择题（choice）**：
   - 去除所有空格后精确匹配
   - 为什么去空格：选择题答案是 A/B/C/D，用户可能输入"A "或" A "，去空格避免误判
   - 白话：选择题就是"完全一样才算对"

2. **填空题（short）**：
   - 先尝试精确匹配
   - 如果不精确匹配，且标准答案<=30字，用 SequenceMatcher 模糊匹配
   - 模糊匹配阈值：0.85（85%相似度算对）
   - 白话：填空题允许"差不多对"，比如"北京"和"北京市"算对
   - 生活化比喻：像老师批填空题，写了"大约10"和标准答案"10"也能给分

3. **开放题（open）**：
   - 将标准答案按逗号/分号/句号/换行分割成关键词
   - 计算学生答案中命中了多少关键词
   - 命中率>=60%算正确
   - 白话：开放题不要求"一字不差"，关键点说到了就行
   - 生活化比喻：像作文评分，老师看几个得分点有没有提到

4. **空答案**：如果标准答案为空，直接返回 False（没标准答案没法判）

### classify_error() (grading.py:52)

**业务含义**：对错误答案进行粗分类。

**参数**：user_answer: 学生的错误答案

**返回**：ErrorType 枚举

**关键逻辑**（只有两层粗分类）：

1. 如果学生答案是空白 -> ErrorType.METACOGNITIVE（元认知错误）
   - 含义：学生根本不知道答案，不是答错了，而是"不会"
   - 白话：交白卷说明你压根没掌握

2. 如果学生答案非空 -> ErrorType.APPLICATION_ERROR（应用错误）
   - 含义：学生知道一些但用错了
   - 白话：写了答案但写错了

**注意**：这只是粗分类。更细致的四分类（结构性/偏差型/应用型/元认知型）由 LLM 在后续的 error-diagnosis 阶段完成。

### ErrorType 四分类（models.py）

| 类型 | 英文 | 含义 | 白话解释 |
|------|------|------|---------|
| 知识结构性 | structural | 知识体系有漏洞 | 你根本没学过这个知识点 |
| 理解偏差型 | deviation | 理解有偏差 | 你学过但理解错了 |
| 应用错误 | application | 知道但用错了 | 你理解对了但用错了 |
| 元认知型 | metacognitive | 不知道自己不会 | 交白卷，压根没掌握 |

### KnowledgeType 四分类（models.py）

| 类型 | 英文 | 含义 | 例子 |
|------|------|------|------|
| 记忆型 | memory | 需要记忆的知识 | 历史年代、公式 |
| 概念型 | concept | 需要理解的概念 | 什么是函数 |
| 程序型 | procedure | 操作流程 | 解题步骤 |
| 设计型 | design | 创造性应用 | 设计实验方案 |

## 掌握度计算详解

### compute_mastery() (mastery.py:24)

**业务含义**：根据一个知识点的答题历史，计算掌握度分数（0~1）。

**参数**：correctness: 按时间排列的答题正确/错误列表

**返回**：0.0~1.0 的掌握度分数

**关键逻辑**：

1. **递进权重**：最近5次的权重是 (0.5, 0.7, 0.85, 0.95, 1.0)
   - 越近的答题权重越高
   - 含义：最近的表现比早期的更重要
   - 白话：你上周答对5道题，但今天答错了，掌握度会下降

2. **加权平均**：score = sum(权重 * 对错) / sum(权重)
   - 比如：最近5次是 [对,错,对,对,对]
   - score = (0.5*1 + 0.7*0 + 0.85*1 + 0.95*1 + 1.0*1) / (0.5+0.7+0.85+0.95+1.0)
   - score = (0.5+0+0.85+0.95+1.0) / 4.0 = 3.3/4.0 = 0.825

3. **置信度上限**：
   - 只答1次 -> 最高 0.5（一次答对不能算"掌握了"）
   - 只答2次 -> 最高 0.8（两次答对也不够）
   - 答3次以上 -> 最高 1.0（足够证据才算真正掌握）
   - 白话：一次蒙对了不算数，得多答几次才能确认

**生活化比喻**：
掌握度就像信用评分。一次按时还款不能给你满分，需要长期的良好记录才能积累高信用。同样，一次答对不能说"掌握了"，需要多次答对才算。

## LearningService 学习服务编排 (service.py)

### LearningService 类

**业务含义**：学习服务的总编排器，连接评分、掌握度、存储、调度。

**核心方法**：

1. get_or_create(book_id) -> 获取或创建学习进度
   - 先从存储加载，没有就创建新的
   - 白话：打开课本的学习记录

2. init_modules(progress, modules) -> 初始化可运行模块
   - 替换语义：新模块列表完全覆盖旧的
   - 白话：设置这节课要学哪些模块

3. record_attempt(progress, question_id, user_answer, correct) -> 记录答题
   - 调用 grade_answer 评分
   - 调用 classify_error 分类
   - 调用 compute_mastery 更新掌握度
   - 白话：记下这次答题结果，更新掌握度

4. calculate_mastery(progress, knowledge_point) -> 计算某知识点掌握度
   - 调用 mastery.compute_mastery
   - 白话：算一下这个知识点学生掌握得怎么样

## LearningStore 数据持久化 (storage.py)

**业务含义**：把学习进度、答题记录、掌握度数据存到磁盘。

**存储方式**：
- JSON 文件存储在用户数据目录
- 每本书一个学习进度文件
- 原子写入：先写临时文件，成功后重命名

**数据结构**：
- LearningProgress: 一本书的学习进度
  - modules: 模块列表
  - attempts: 答题记录列表
  - mastery_scores: 各知识点掌握度
  - pending_questions: 待回答的题目

## 间隔重复调度 (scheduler.py)

**业务含义**：基于掌握度和遗忘曲线，决定下次复习时间。

**调度策略**：
- 掌握度高的知识点 -> 间隔拉长
- 掌握度低的知识点 -> 间隔缩短
- 刚答错的知识点 -> 尽快复习
- 长时间没复习的 -> 触发复习提醒

## 总结

DeepTutor 的题目评分系统是一个多层次的评估引擎：
1. **评分层**：grade_answer 根据题型用不同策略评分
2. **分类层**：classify_error 对错误答案粗分类
3. **掌握度层**：compute_mastery 用递进权重+置信度上限计算掌握度
4. **编排层**：LearningService 串联评分、分类、掌握度、存储
5. **调度层**：scheduler 基于掌握度安排下次复习

核心设计理念：
1. 简单题用规则，复杂题用 AI
2. 评分不是终点，而是学习优化的起点
3. 错误分类比简单"对/错"更有价值
4. 每一次评分都在为个性化学习积累数据
5. 掌握度需要"足够证据"才能确认，防止虚假掌握

## 评分流程完整示例

### 场景：学生在 Mastery Path 做一道填空题

1. 题目："中国的首都是___"
2. 标准答案："北京"
3. 学生提交："beijing"
4. 评分过程：
   - 类型判定：short（填空题）
   - 精确匹配："beijing" != "北京" -> 不匹配
   - 模糊匹配：len("北京")==2 <= 30 -> 启动模糊匹配
   - SequenceMatcher("beijing", "北京").ratio() -> 由于中英文不同，相似度可能 < 0.85
   - 结果：False（错误）
5. 错误分类：答案非空 -> APPLICATION_ERROR
6. 掌握度更新：
   - 该知识点历史：[对, 对, 错]
   - 最近3次：[对, 对, 错]
   - 权重取最后3个：(0.85, 0.95, 1.0)
   - score = (0.85*1 + 0.95*1 + 1.0*0) / (0.85+0.95+1.0) = 1.8/2.8 = 0.643
   - 置信度上限：3次 -> 1.0，不限制
   - 最终掌握度：0.643
7. 调度器决策：掌握度 < 0.8 -> 明天复习

### 场景：学生做一道选择题

1. 题目："1+1=? A) 1 B) 2 C) 3 D) 4"
2. 标准答案："B"
3. 学生提交："B"
4. 评分过程：
   - 类型判定：choice（选择题）
   - 去空格："B" == "B" -> True
5. 结果：正确
6. 掌握度更新：
   - 历史：[对, 对, 对, 对]
   - 最近4次全对
   - score = (0.7*1 + 0.85*1 + 0.95*1 + 1.0*1) / (0.7+0.85+0.95+1.0) = 3.5/3.5 = 1.0
   - 置信度上限：4次 -> 1.0
   - 最终掌握度：1.0
7. 调度器决策：掌握度 = 1.0 -> 7天后再复习

## 与 LLM 评分的配合

规则评分（grading.py）只做确定性判定。对于需要深度理解的题目，
DeepTutor 还有一个 LLM 评分阶段：
1. 规则评分先判定：能确定的（选择题/填空题）直接判
2. 不确定的（开放题/编程题）交给 LLM 评分
3. LLM 评分会给出：分数 + 理由 + 改进建议
4. LLM 还会做更细致的错误分类（四分类）

## 评分系统的可扩展性

评分系统设计为可插拔：
- grade_answer 是纯函数，可以单独测试
- compute_mastery 注释里写了：要换更复杂的模型（如 IRT/BKT），
  只需替换 compute_mastery 一个函数，调用方不用改
- ErrorType 是枚举，可以扩展新的错误类型
- KnowledgeType 同样可扩展

## 总结

DeepTutor 的题目评分系统是一个多层次的评估引擎。它从简单的选择题精确匹配，到填空题的模糊匹配，再到简答题的关键词匹配和开放题的 LLM 评估，形成了一个完整的评分体系。评分结果不仅反馈给学生，还驱动掌握度计算和学习路径调整，是教学闭环的关键一环。


核心设计理念：简单题用规则、复杂题用 AI，评分是学习优化的起点，不是终点。
