## 3. 知识体系：AI 的课本和笔记

### 3.1 KnowledgeResource — 知识库资源

> 源码：deeptutor/multi_user/models.py 第 68-80 行

知识库是 DeepTutor 的课本——用户上传 PDF、文档等，系统将其向量化后存入知识库，AI 就能基于这些内容回答问题。

| 字段 | 说明 |
|------|------|
| id | 知识库唯一 ID |
| name | 知识库名称 |
| base_dir | 文件存储目录 |
| source | 创建者（admin 或 user） |
| assigned | 是否已分配给用户 |
| read_only | 是否只读 |

### 3.2 Notebook — 笔记本

> 源码：deeptutor/services/notebook/service.py 第 47-57 行

如果把知识库比作课本，那笔记本就是学生的课堂笔记——记录学习过程中的收获、错题、解题思路。

| 字段 | 说明 |
|------|------|
| id | 笔记本唯一 ID |
| name | 笔记本名称，如"数学错题集" |
| description | 描述 |
| records | 笔记记录列表（NotebookRecord） |
| color | 颜色标记 |
| icon | 图标 |

### 3.3 NotebookRecord — 笔记记录

> 源码：deeptutor/services/notebook/service.py 第 33-44 行

每条记录都保存了用户问了什么和 AI 答了什么，可以回顾、搜索、导出。

| 字段 | 说明 |
|------|------|
| type | 记录类型：solve / question / research / chat / co_writer / tutorbot |
| user_query | 用户原始提问 |
| output | AI 的回答 |
| kb_name | 关联的知识库名称（可选） |

---

### 3.4 Book — 互动教材

> 源码：deeptutor/book/models.py 第 426-445 行

Book 是 DeepTutor 的互动教材引擎。它能把知识库、聊天记录、笔记本内容自动编译成一本有章节、有习题、有插图的互动教材。

Book 的层级结构：Book -> Spine（书脊）-> Chapter（章节）-> Page（页面）-> Block（内容块）

Block 支持多种类型（BlockType，第 55-79 行）：
text（文字）、callout（提示框）、quiz（测验）、figure（插图）、interactive（交互组件）、
animation（动画）、code（代码块）、timeline（时间线）、flash_cards（闪卡）、
deep_dive（深度探索）、diagnostic/pretest/retrieval_practice/error_diagnosis/module_test（学习评估）

## 4. 对话体系：一次对话的完整记录

### 4.1 Session — 会话

> 协议定义：deeptutor/services/session/protocol.py 第 14-82 行

Session 是对话的容器。一个 Session 包含多轮对话（Turn），每轮对话包含多条消息（Message）。

```
Session（会话）
 ├── Turn 1（第1轮对话）
 │    ├── Message: user（用户消息）
 │    ├── Message: assistant（AI 回复）
 │    └── Events: [tool_call, rag_retrieval, ...]
 ├── Turn 2
 └── Summary（对话摘要，长对话自动压缩）
```

Session 存储支持两种后端：SQLite（本地）和 PocketBase（远程）。

### 4.2 UnifiedContext — 统一上下文

> 源码：deeptutor/core/context.py 第 33-84 行

UnifiedContext 是贯穿整个 Pipeline 的数据总线。它把一次请求所需的所有信息打成一个包：

| 字段 | 说明 |
|------|------|
| session_id | 会话 ID |
| user_message | 当前用户输入 |
| conversation_history | 历史消息 |
| enabled_tools | 用户启用的工具列表 |
| active_capability | 当前激活的能力 |
| knowledge_bases | 挂载的知识库列表 |
| attachments | 附件（图片/文件） |
| language | 语言（en/zh） |
| memory_context | 记忆上下文 |
| persona_context | 人设上下文 |
| skills_manifest | 技能清单 |
| metadata | 扩展元数据 |

为什么叫统一上下文？因为在 DeepTutor 中，无论是聊天、解题、出题还是学习评估，所有的能力、工具、服务都通过这一个对象获取信息。

## 5. 记忆体系：AI 的长期记忆

### 5.1 三层记忆架构

> 源码：deeptutor/services/memory/__init__.py 第 1-42 行

DeepTutor 的记忆系统分为三层，就像人类记忆的感觉记忆 -> 短期记忆 -> 长期记忆：

```
L1（Trace 层）           L2（Document 层）         L3（Slot 层）
原始事件记录              结构化文档                核心摘要
─────────────────       ─────────────────       ─────────────────
每次对话的原始日志         LLM 整理后的笔记         用户画像、偏好、
追加写入 JSONL            按话题分组                长期知识
                         Markdown 格式             固定槽位（7个）
```

| 层级 | 作用 | 存储格式 | 典型内容 |
|------|------|---------|---------|
| L1 Trace | 原始事件记录 | JSONL 文件 | 用户在 2024-01-15 问了微积分问题 |
| L2 Document | 结构化笔记 | Markdown 文件 | 用户正在学习微积分，已掌握求导 |
| L3 Slot | 核心摘要 | 固定槽位 | 数学水平：高中；偏好：图形化解释 |

L3 有 7 个固定槽位：用户画像（profile）、学习风格（learning_style）、知识水平（knowledge_level）、
兴趣爱好（interests）、当前目标（goals）、偏好设置（preferences）、重要事件（key_events）。

### 5.2 MemoryStore — 记忆存储门面

> 源码：deeptutor/services/memory/store.py

MemoryStore 是记忆系统的统一入口，提供记录追踪事件（record_trace）、整理记忆（consolidate）、
读取记忆（read）、搜索记忆（search）等功能。

## 6. 学习体系：AI 如何评估和追踪学习

### 6.1 LearningProgress — 学习进度

> 源码：deeptutor/learning/models.py 第 185-213 行

这是整个学习体系的总账本，记录了用户在某本教材上的所有学习状态。

核心字段：
- book_id：教材 ID
- diagnostic：诊断结果
- modules：学习模块列表
- current_stage：当前阶段
- mastery_levels：掌握度 {知识点ID: 0.0~1.0}
- quiz_attempts：测验记录
- error_records：错题记录
- review_queue：复习队列
- pending_question：待回答的问题

### 6.2 学习阶段（LearningStage）

> 源码：deeptutor/learning/models.py 第 61-77 行

7 个阶段：diagnostic -> explain -> feynman_check -> practice -> error_diagnosis -> review -> completed

| 阶段 | 做什么 | 典型交互 |
|------|--------|---------|
| diagnostic | 诊断学生水平 | 出几道题测试基础 |
| explain | 讲解知识点 | AI 讲解概念，配合示例 |
| feynman_check | 费曼检查 | 让学生用自己的话解释一遍 |
| practice | 练习 | 出题让学生做 |
| error_diagnosis | 错误诊断 | 分析错题原因 |
| review | 间隔复习 | 根据遗忘曲线安排复习 |
| completed | 完成 | 本模块学习结束 |

### 数据实体关系图



### 数据实体详细说明

**User（用户）**
- 代表一个 DeepTutor 用户（学生/教师/管理员）
- 关联：拥有多个 Session、Notebook、MemoryStore
- 存储：通过 PathService 隔离不同用户的数据目录

**KnowledgeBase（知识库）**
- 代表一组教材/文档的集合
- 关联：包含多个 Document，可被多个 Session 引用
- 状态：empty → processing → ready / error
- 提供者：llamaindex / lightrag / graphrag / pageindex

**Session（会话）**
- 代表一次对话的上下文
- 关联：属于一个 User，包含多个 Message，可引用一个 KnowledgeBase
- 生命周期：创建 → 活跃 → 归档

**Question（题目）**
- 代表一道练习题
- 关联：属于一个 KnowledgeBase，关联多个 KnowledgePoint
- 类型：choice（选择）/ short（填空）/ open（开放）/ programming（编程）
- 难度：1-5 级

**Notebook（笔记本）**
- 代表学生的学习记录集合
- 关联：属于一个 User，包含多个 Record
- 用途：记录错题、学习要点、研究笔记

**MemoryStore（记忆存储）**
- 代表用户的三级记忆系统
- L1：原始事件流（TraceEvent）
- L2：按会话分组的摘要（Surface）
- L3：跨会话的长期偏好（Slot）

### 总结

DeepTutor 的数据模型以 User 为中心，辐射出 Session、KnowledgeBase、Memory、Notebook、Question 五大实体。这些实体通过明确的关联关系形成了一个完整的教学数据闭环：用户上传教材（KnowledgeBase），在对话中提问（Session），系统生成题目（Question），学生答题后记录到笔记本（Notebook），掌握度数据更新到记忆（Memory），驱动后续的个性化学习。

### 6.3 KnowledgePoint — 知识点

> 源码：deeptutor/learning/models.py 第 80-86 行

知识点有 4 种类型（KnowledgeType，第 24-28 行）：
- memory（记忆型）：需要记住的事实，如公式、定义
- concept（概念型）：需要理解的概念，如导数的几何意义
- procedure（程序型）：需要掌握的步骤，如求导的步骤
- design（设计型）：需要创造性应用，如用微积分解决实际问题

### 6.4 QuizAttempt — 测验记录

> 源码：deeptutor/learning/models.py 第 107-118 行

记录每次测验的详细信息：题目ID、是否正确、用户答案、错误类型、自评、掌握度估计值。

### 6.5 ErrorRecord — 错题记录

> 源码：deeptutor/learning/models.py 第 129-141 行

错题有 4 种错误类型（ErrorType，第 36-40 行）：
- structural（知识结构性）：根本不知道这个知识点
- deviation（理解偏差型）：理解有偏差，概念混淆
- application（应用错误）：知道概念但不会用
- metacognitive（元认知型）：不知道自己不知道

### 6.6 ReviewTask — 复习任务

> 源码：deeptutor/learning/models.py 第 153-161 行

使用间隔重复算法（RepetitionState，第 144-151 行），根据连续正确/错误次数自动调整复习间隔。

### 6.7 PendingQuestion — 待回答的问题

> 源码：deeptutor/learning/models.py 第 164-182 行

特别注意：expected_answer 保存在服务端，永远不会发给 LLM。这保证了评分的客观性——AI 不能看到答案再打分。

## 10. 总结

DeepTutor 的数据模型围绕 4 个核心体系展开：

1. **用户体系**：管理身份、权限、数据隔离
2. **知识体系**：知识库（课本）、笔记本（笔记）、Book（互动教材）
3. **对话体系**：Session -> Turn -> Message 的完整对话记录
4. **学习体系**：从诊断到复习的 7 阶段掌握度路径

这些数据实体通过 UnifiedContext 统一上下文串联起来，在一次请求中流转，让 AI 能够看到用户的知识背景、历史对话、学习进度，从而给出个性化的回答。

## 12.2 核心实体详解

### 实体 1：User（用户）

**源码位置**：`deeptutor/services/auth.py`

**定位**：系统的顶层实体，所有数据最终归属于某个用户。

**关键属性**：

| 属性 | 类型 | 说明 |
|:---|:---|:---|
| user_id | string | 唯一标识 |
| username | string | 用户名 |
| password_hash | string | 密码哈希（bcrypt） |
| is_admin | boolean | 是否管理员 |
| created_at | datetime | 创建时间 |

**生命周期**：
- 创建：注册（`/register`）或管理员添加
- 活跃：登录后使用系统
- 删除：管理员删除

**关联**：
- 拥有多个 Session、KnowledgeBase、Partner、Skill
- 拥有一套 Memory（三层记忆）
- 在多用户模式下，admin 用户管理其他用户的权限

> 类比：User 就像"图书馆的读者证"——一张证对应一个人，所有借阅记录、笔记、偏好都挂在这张证下面。

---

### 实体 2：Session（会话）

**源码位置**：`deeptutor/agents/chat/session_manager.py`、`deeptutor/services/session/`

**定位**：一次连续的 AI 对话。是用户与 DeepTutor 交互的最基本单位。

**关键属性**：

| 属性 | 类型 | 说明 |
|:---|:---|:---|
| session_id | string | 唯一标识（如 `chat_abc123`） |
| title | string | 会话标题（通常是第一条用户消息） |
| messages | list[Message] | 消息列表 |
| settings | dict | 会话设置（KB、工具开关等） |
| created_at | datetime | 创建时间 |
| updated_at | datetime | 最后更新时间 |

**Message 子结构**：

| 属性 | 类型 | 说明 |
|:---|:---|:---|
| role | string | user / assistant / tool |
| content | string | 消息内容 |
| sources | list | 引用的知识源 |
| timestamp | datetime | 消息时间戳 |
| tool_calls | list | 工具调用记录（如有） |

**生命周期**：
- 创建：用户发送第一条消息
- 活跃：持续对话
- 归档：不再活跃（保留在历史中）
- 删除：用户手动删除

**存储方式**：aiosqlite（SQLite 异步数据库），存储在 `data/user/workspace/chat/` 下。

> 类比：Session 就像"一次上课"——有开始、有过程、有结束。每节课的内容（Messages）被记录下来，下次可以继续。---

### 实体 3：KnowledgeBase（知识库）

**源码位置**：`deeptutor/services/rag/`

**定位**：用户上传的文档集合，经过索引后可供 AI 检索。是 DeepTutor 的"第二大脑"。

**关键属性**：

| 属性 | 类型 | 说明 |
|:---|:---|:---|
| kb_id | string | 唯一标识（如 `kb_xyz789`） |
| name | string | 知识库名称 |
| description | string | 描述 |
| engine | string | 检索引擎类型（llamaindex / pageindex / graphrag / lightrag / lightrag_server / obsidian） |
| documents | list[Document] | 文档列表 |
| index_version | int | 索引版本号 |
| index_path | string | 索引存储路径 |
| is_default | boolean | 是否默认知识库 |
| created_at | datetime | 创建时间 |
| updated_at | datetime | 最后更新时间 |

**Document 子结构**：

| 属性 | 类型 | 说明 |
|:---|:---|:---|
| doc_id | string | 文档唯一标识 |
| filename | string | 原始文件名 |
| file_type | string | 文件类型（pdf / docx / pptx / xlsx / md / txt） |
| file_size | int | 文件大小（字节） |
| parse_engine | string | 解析引擎（text / mineru / docling / markitdown / pymupdf4llm） |
| status | string | 状态（pending / indexing / ready / error） |
| chunks | int | 分块数量 |
| error_message | string | 错误信息（如有） |

**六种检索引擎对比**：

| 引擎 | 检索方式 | 优势 | 适用场景 |
|:---|:---|:---|:---|
| LlamaIndex | 向量 + BM25 混合 | 成熟稳定、本地运行 | 通用场景 |
| PageIndex | 页面级推理检索 | 跨文档推理、带页码引用 | 需要精确引用 |
| GraphRAG | 知识图谱检索 | 实体关系发现 | 复杂知识网络 |
| LightRAG | 轻量图谱检索 | 快速、轻量 | 中小规模知识库 |
| LightRAG Server | 外部服务检索 | 检索卸载到独立服务 | 大规模部署 |
| Obsidian | 直接读写 Obsidian Vault | 与笔记工具联动 | Obsidian 用户 |

**生命周期**：
- 创建：用户选择引擎、上传文档
- 索引：文档解析 + 分块 + 向量化（可耗时数分钟）
- 活跃：在对话中被引用
- 更新：添加/删除文档、重新索引（版本号递增）
- 删除：删除整个知识库

**存储方式**：索引存储在 `data/user/workspace/knowledge/<kb_name>/`，支持版本化（`version-1/`, `version-2/` 等）。

> 类比：KnowledgeBase 就像"图书馆的一个书架"——你把书（文档）放上去，图书馆员（检索引擎）给每本书贴上标签（索引），之后找书时根据标签快速定位。---

### 实体 4：Memory（记忆）

**源码位置**：`deeptutor/services/memory/`

**定位**：三层记忆系统，让 AI 能"记住"用户。这是 DeepTutor 区别于通用 AI 聊天的最关键特性之一。

#### 三层架构

```
L3 综合画像 (Synthesis)
  data/user/workspace/memory/L3/
  ├── profile.md      # 用户画像（偏好、风格、背景）
  ├── recent.md       # 近期关注（最近在学什么、关注什么）
  ├── scope.md        # 领域知识（在哪些领域有积累）
  └── preferences.md  # 偏好设置（喜欢的回答风格等）
        ^
        | 引用
        v
L2 提炼摘要 (Curated Facts)
  data/user/workspace/memory/L2/
  ├── chat.md         # 从聊天中提炼的关键信息
  ├── notebook.md     # 从笔记中提炼的关键信息
  ├── quiz.md         # 从测验中提炼的关键信息
  ├── kb.md           # 从知识库使用中提炼的关键信息
  ├── book.md         # 从活书阅读中提炼的关键信息
  ├── partner.md      # 从伙伴对话中提炼的关键信息
  └── cowriter.md     # 从Co-Writer中提炼的关键信息
        ^
        | 引用
        v
L1 原始轨迹 (Raw Traces)
  data/user/workspace/memory/trace/
  ├── chat/2026-07-20.jsonl
  ├── notebook/2026-07-20.jsonl
  └── ...
```

#### L1 轨迹（Trace）

**格式**：JSONL（每行一个 JSON 事件）

**事件类型**：
- `message`：用户/AI 的消息
- `tool_call`：工具调用
- `tool_result`：工具返回结果
- `session_start` / `session_end`：会话开始/结束

**示例**：
```json
{"type": "message", "role": "user", "content": "什么是特征值？", "timestamp": "2026-07-20T10:00:00Z"}
{"type": "tool_call", "tool": "rag", "args": {"query": "特征值"}, "timestamp": "2026-07-20T10:00:02Z"}
{"type": "tool_result", "tool": "rag", "result": "特征值是...", "timestamp": "2026-07-20T10:00:03Z"}
```

#### L2 摘要（Curated Facts）

**格式**：Markdown 文档，带脚注引用

**示例**：
```markdown
# Chat Memory

## 学习偏好
- 用户更喜欢用几何直觉理解线性代数概念 [^1] <!--m_abc123-->
- 用户对特征值计算的步骤容易出错 [^2] <!--m_def456-->

[^1]: chat:session_001
[^2]: chat:session_002
```

#### L3 综合（Synthesis）

**格式**：Markdown 文档，引用 L2 条目

**示例**：
```markdown
# 用户画像

## 学习风格
- 偏好几何直觉理解 [^1]
- 需要更多的计算练习 [^2]

[^1]: L2/chat.md §学习偏好
[^2]: L2/chat.md §薄弱点
```

**关键属性**：

| 属性 | 类型 | 说明 |
|:---|:---|:---|
| entry_id | string | 条目唯一标识（如 `m_abc123`） |
| surface | string | 来源面板（chat / notebook / quiz / kb / book / partner / cowriter） |
| level | string | 记忆层级（L1 / L2 / L3） |
| content | string | 内容 |
| citations | list | 引用链（L3引用L2, L2引用L1） |
| created_at | datetime | 创建时间 |
| updated_at | datetime | 更新时间 |

**生命周期**：
- L1：每次对话自动记录（追加）
- L2：由 Memory Consolidator 定期从 L1 提炼（可配置频率）
- L3：由 Memory Consolidator 定期从 L2 综合（可配置频率）
- 编辑：用户可手动编辑/删除 L2 和 L3 的任何条目
- 清除：用户可清除全部或部分记忆

> 类比：Memory 就像"学生的成长档案"——L1 是课堂录音（原始记录），L2 是老师批注的要点（提炼），L3 是学期评语（综合画像）。---

### 实体 8：Partner（伙伴）

**源码位置**：`deeptutor/services/partners/`

**定位**：有独立人格、频道、知识库的持久化 AI 伙伴。可以在 IM 平台上独立运行，也可以作为子代理被咨询。

**关键属性**：

|:---|:---|:---|

| channels | list[Channel] | 激活的 IM 频道 |
| kb_ids | list[string] | 关联的知识库 |
| skill_ids | list[string] | 关联的技能 |

| memory | Memory | 独立的记忆空间 |

**Channel 子结构**：

| 属性 | 类型 | 说明 |

**生命周期**：

- 对话：通过 IM 或 Web 与用户交互
- 停止/删除：停止 Partner 运行

**存储方式**：文件系统（`data/partners/<id>/`），JSON 配置 + Markdown Soul。

> 类比：Partner 就像你"雇佣的 AI 助教"——它有自己的人格（SOUL.md）、自己的"电话号码"（IM 频道）、自己的"教材"（知识库），可以独立工作，也可以被你随时叫来帮忙。---

## 12.3 实体关系详解（ER 图）

### 核心关系链路

```
User
 |
 +-- 1:N --> Session
 |              |
 |              +-- 1:N --> Message
 |              +-- 1:N --> Question (会话中产生的题目)
 |
 +-- 1:N --> KnowledgeBase
 |              |
 |              +-- 1:N --> Document
 |              +-- 1:N --> IndexVersion
 |
 +-- 1:1 --> Memory
 |              |
 |              +-- 1:N --> L1Trace
 |              +-- 1:N --> L2Entry
 |              +-- 1:N --> L3Entry
 |
 +-- 1:N --> Notebook
 |              |
 |              +-- 1:N --> NotebookRecord
 |
 +-- 1:N --> Book
 |              |
 |              +-- 1:N --> Chapter
 |                            |
 |                            +-- 1:N --> Block
 |
 +-- 1:N --> Partner
 |              |
 |              +-- 1:1 --> Memory (独立)
 |              +-- 1:N --> Channel
 |
 +-- 1:N --> Skill
 |
 +-- 1:N --> Subagent
```

### 跨实体关系

| 关系 | 说明 |
|:---|:---|
| Book <<-->> KnowledgeBase | Book 由多个 KB 编译而来 |
| Book <<-->> Notebook | Book 可以引用 Notebook 内容 |
| Book <<-->> Question | Book 可以引用 Question Bank |
| Question --> Session | 题目在某个会话中产生 |
| Question --> Notebook | 题目可以被收藏到 Notebook |
| Session --> Subagent | 会话中咨询子代理 |
| Partner --> KnowledgeBase | Partner 绑定知识库 |
| Partner --> Skill | Partner 绑定技能 |
| Subagent --> Partner | Partner 可以作为子代理 |

## 12.5 设计原则

### 1. 文件优先，数据库辅助

大部分数据以人类可读的文件格式存储（Markdown、JSON、JSONL），只有高频读写的会话数据使用 SQLite。这带来几个好处：

- **可调试**：出问题时可以直接打开文件看
- **可迁移**：复制文件夹即可迁移全部数据
- **可版本控制**：可以用 Git 管理数据

### 2. 引用链可追溯

Memory 的三层引用链（L3 -> L2 -> L1）是设计核心。这个模式也体现在其他实体间：

- Book 的每个 Block 可以追溯到源 KB 文档
- Question 可以追溯到产生它的 Session
- NotebookRecord 可以追溯到源 Session

### 3. 隔离与共享的平衡

| 数据 | 隔离范围 | 说明 |
|:---|:---|:---|
| Session | 用户 | 每个用户看到自己的对话 |
| Memory | 用户/Partner | 用户和 Partner 记忆隔离 |
| KnowledgeBase | 可共享 | 管理员可共享给其他用户 |
| Skill | 可共享 | 管理员可分配给其他用户 |
| Partner | 用户 | 每个用户管理自己的 Partner |

### 4. 版本化与不可变

- KnowledgeBase 索引是版本化的（`version-1/`, `version-2/`）
- L1 轨迹是追加的（JSONL 格式）
- 旧版本索引不会被删除（直到手动清理）

## 12.6 一句话总结

> DeepTutor 的 10 个核心实体构成了一个以 User 为中心、以 Session 为主交互线、以 KnowledgeBase 和 Memory 为双翼的数据模型。每个实体有清晰的边界和生命周期，实体之间通过引用链而非数据复制来关联，保证了数据的一致性和可追溯性。
