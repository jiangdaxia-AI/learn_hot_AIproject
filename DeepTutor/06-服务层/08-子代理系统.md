# 08 — 子代理系统（Subagent）

> **源码位置**：`deeptutor/services/subagent/`（13 个文件）
> **阅读对象**：产品经理 / 运营 / 非技术人员
> **目标**：看懂 DeepTutor 如何让用户的本地 AI 编程工具（Claude Code、Codex）变成自己的"外包员工"

---

## 一句话概括

子代理系统是 DeepTutor 的"外包管理系统"。它让 DeepTutor 可以调用用户本地安装的 AI 编程工具（如 Claude Code、Codex），让这些工具帮 DeepTutor 完成复杂的编程任务——比如写代码、调试、运行测试。DeepTutor 只负责"派活"和"验收"，实际的编码工作交给子代理去做。

---

## 生活化比喻

> 子代理系统就像**项目经理的"外包团队"**：
> - 项目经理（DeepTutor）接到一个任务，判断需要程序员来写代码
> - 项目经理从外包团队名单（registry）中选一个合适的程序员（Claude Code 或 Codex）
> - 派活（consult）：把需求发给程序员，程序员开始干活
> - 实时汇报（stream）：程序员每写一行代码、每跑一个测试，都实时汇报进度
> - 验收（result）：程序员交活，项目经理检查结果

---

## 一、整体架构

子代理系统由 13 个文件组成，分三层：

```
┌─────────────────────────────────────────────────────┐
│                   接口层                              │
│  base.py  — 子代理的"驾驶证"（定义所有子代理必须会的技能）│
│  types.py — 子代理的"汇报模板"（事件格式、结果格式）     │
├─────────────────────────────────────────────────────┤
│                   实现层                              │
│  claude_code.py — Claude Code 子代理                │
│  codex.py       — Codex 子代理                       │
│  partner.py     — 合作伙伴子代理                      │
│  registry.py    — 子代理"花名册"（注册所有可用的子代理） │
├─────────────────────────────────────────────────────┤
│                   支撑层                              │
│  config.py    — 子代理配置（超时、最大 token 等）      │
│  process.py   — 子代理进程管理（启动、监控、终止）      │
│  sessions.py  — 会话管理（子代理的"工作记录"）         │
│  models.py    — 模型选择（用哪个 AI 模型）             │
│  images.py    — 图片处理（子代理生成的图片）            │
│  claude_models.py — Claude 专用模型配置               │
│  __init__.py  — 模块入口                              │
└─────────────────────────────────────────────────────┘
```

## 二、base.py —— 子代理的"驾驶证"

**源码路径**：`deeptutor/services/subagent/base.py`

### 为什么需要统一的接口？

不同的 AI 编程工具（Claude Code、Codex）各自有不同的命令行参数、不同的输出格式、不同的启动方式。如果 DeepTutor 直接跟每个工具打交道，代码会非常混乱。

统一接口就像"驾驶证"——不管你是开奔驰还是开宝马，只要你有驾照，就说明你会开车。`SubagentBackend` 就是这个驾照，它定义了两个所有子代理必须会的基本操作：

| 操作 | 大白话 |
|------|--------|
| `detect()` | 检查这个工具是否安装在本机上——"你能干活吗？" |
| `consult()` | 派一个任务给这个工具，实时接收它的进度汇报——"帮我做这个，随时汇报进度" |

### 大白话理解

就像你去餐厅，服务员不需要知道每个厨师的具体做法。只要知道"这个厨师会做川菜、那个厨师会做粤菜"，就能根据客人的需求分配任务。`SubagentBackend` 就是餐厅的"厨师技能档案"。

## 三、types.py —— 子代理的"汇报模板"

**源码路径**：`deeptutor/services/subagent/types.py`

子代理在干活过程中，会不断发送"状态汇报"。这些汇报分 7 种类型：

| 事件类型 | 大白话 | 例子 |
|---------|--------|------|
| text | 子代理正在输出文字 | "我来分析一下这个问题..." |
| reasoning | 子代理正在思考 | "首先需要检查数据库连接..." |
| tool | 子代理正在调用工具 | "执行命令: ls -la" |
| tool_result | 工具执行完毕 | "命令执行成功，返回 3 个文件" |
| log | 进度日志 | "正在安装依赖..." |
| result | 最终结果 | "任务完成，这是代码" |
| error | 出错了 | "连接超时，请重试" |

### 大白话理解

就像外卖骑手接单后，APP 上会显示"骑手已到店→正在取餐→正在配送→即将送达"。每个状态更新都是一条"事件"。子代理系统用同样的方式，让用户实时看到 AI 编程工具在做什么。

---

## 四、registry.py —— 子代理"花名册"

**源码路径**：`deeptutor/services/subagent/registry.py`

DeepTutor 当前支持 3 种子代理：

| 子代理 | 大白话 | 使用场景 |
|--------|--------|---------|
| Claude Code | Anthropic 的命令行 AI 编程工具 | 用户安装了 Claude Code，想让它帮忙写代码 |
| Codex | OpenAI 的命令行 AI 编程工具 | 用户安装了 Codex，想让它帮忙写代码 |
| Partner | 合作伙伴集成 | 通过 API 连接第三方 AI 服务 |

### 大白话理解

花名册就像一个"外包团队通讯录"——项目经理（DeepTutor）需要程序员时，先翻通讯录看看有哪些人可用。`registry.py` 就是这个通讯录，它记录了所有可用的子代理及其联系方式。

---

## 五、claude_code.py / codex.py —— 具体的子代理实现

**源码路径**：`deeptutor/services/subagent/claude_code.py`、`codex.py`

每个子代理实现负责：

1. **检测安装**：检查本机是否安装了对应的 CLI 工具
2. **启动进程**：用正确的命令行参数启动子代理
3. **解析输出**：把子代理的原始输出（JSON 流）转换成标准的 SubagentEvent
4. **管理会话**：支持对话恢复（上次没干完的活可以接着干）

### 大白话理解

就像不同的外包公司有不同的入职流程、不同的汇报格式。但不管你用哪家外包公司，最终都是"派人干活→汇报进度→交付结果"。Claude Code 和 Codex 是两个不同的外包公司，但都遵循同样的"外包协议"。

---

## 六、支撑模块

| 模块 | 大白话 |
|------|--------|
| config.py | 子代理的"工作规则"——超时多久、最多用多少 token |
| process.py | 子代理的"考勤管理"——启动、监控、超时自动终止 |
| sessions.py | 子代理的"工作记录"——每次派活的完整记录 |
| models.py | 子代理的"工具选择"——用哪个 AI 模型来干活 |
| images.py | 子代理的"截图功能"——生成的图片怎么处理 |

---

## 七、对产品/运营的一句话总结

> 子代理系统让 DeepTutor 可以"雇佣"用户本地的 AI 编程工具作为外包员工。DeepTutor 负责管理和协调，子代理负责具体的编码工作。用户不需要知道背后是 Claude Code 还是 Codex 在干活——只要任务完成了就行。
