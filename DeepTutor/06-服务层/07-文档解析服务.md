# 07-文档解析服务（Document Parsing Service）

> Understand-Anything 知识图谱: 26 节点, 25 边, 7 层
> 把 PDF/Word/PPT 变成 AI 能"读懂"的文字——DeepTutor 的文档解析服务就像一位专业的档案管理员，不管什么格式的文件，都能拆解成结构化的内容和清晰的文字。

## 1. 整体概述

文档解析服务是 DeepTutor 的"文件翻译层"。用户上传各种格式的文档（PDF、Word、PPT、Excel、HTML、图片等），这个服务负责把它们"拆解"成 AI 能理解的文本和结构。它不仅能提取纯文本，还能识别表格、公式、图片、排版布局等复杂结构。

**核心设计理念：**
- **引擎可插拔：** 支持 5 种解析引擎，用户可以根据需求切换
- **内容寻址缓存：** 同一个文件用同一个引擎解析，只解析一次，第二次直接读缓存
- **统一输出格式：** 不管底层用什么引擎，最终输出都是统一的 `ParsedDocument` 结构

**核心文件：**

| 文件 | 路径 | 职责 |
|------|------|------|
| `service.py` | `deeptutor/services/parsing/service.py` | 解析服务入口，`ParseService` 类 |
| `base.py` | `deeptutor/services/parsing/base.py` | 解析引擎的接口契约 |

## 2. 数据模型（types.py）

*文件：`deeptutor/services/parsing/types.py`*

### 2.1 `ParsedDocument`（解析后的文档）

*文件位置：types.py，第 23-50 行*

```python
@dataclass(frozen=True)
class ParsedDocument:
    markdown: str                              # Markdown 格式的文本（一定有）
    blocks: Optional[list[dict[str, Any]]] = None  # 结构化内容块（可选）
    asset_dir: Optional[Path] = None           # 提取出的图片等资源目录
    source_hash: str = ""                      # 源文件的哈希值
    parser_signature: str = ""                 # 解析引擎的"指纹"
    engine: str = ""                           # 使用的引擎名称
    workdir: Optional[Path] = None             # 缓存工作目录
```

**业务含义：** ParsedDocument 是文档解析的"最终交付物"。它包含了两种粒度的内容：

- **`markdown`（粗粒度）：** 所有引擎都能输出的 Markdown 格式文本。这是最低公共标准——不管用什么引擎，至少能拿到文字内容。
- **`blocks`（细粒度）：** 结构化的内容块列表，包含每个块的类型（文本/表格/图片/公式）、位置、内容等。目前只有 MinerU 引擎原生输出这个格式，Docling 引擎会映射转换。

**`has_structure` 属性（第 47-49 行）：**
- **业务做什么：** 判断是否有结构化内容块
- **大白话解释：** 快速检查"这个解析结果有没有详细的版面结构信息"

### 2.2 `ParserError`（解析错误）

*文件位置：types.py，第 16-20 行*

```python
class ParserError(RuntimeError):
    """解析失败时抛出的异常"""
```

**业务含义：** 当解析失败时（引擎缺失、模型未就绪、配置错误），抛出这个异常。它携带用户可读的错误信息，前端可以直接展示给用户。

**大白话解释：** 这是"解析失败通知单"——告诉用户哪里出了问题，应该怎么解决。

## 3. 解析引擎接口契约（base.py）

*文件：`deeptutor/services/parsing/base.py`*

### 3.1 `ReadinessReport`（就绪报告）

*文件位置：base.py，第 19-27 行*

```python
@dataclass(frozen=True)
class ReadinessReport:
    ready: bool       # 是否可以立即执行解析
    reason: str = "ready"  # 机器可读的原因码
    message: str = ""      # 用户可读的提示信息
```

**业务含义：** 在真正执行解析之前，先检查引擎是否"准备好了"。有些引擎需要下载本地模型（如 MinerU、Docling），如果模型还没下载，就不能立即开始解析。

**`reason` 的可能值：**
- `"ready"`：可以立即使用
- `"models_missing"`：本地模型未下载
- `"cli_missing"`：命令行工具未安装
- `"not_configured"`：未配置

**大白话解释：** 这是"开工前检查"——工具准备好了吗？模型下载好了吗？如果没准备好，告诉用户缺什么。

### 3.2 `Parser`（解析器协议）

*文件位置：base.py，第 30-76 行*

```python
@runtime_checkable
class Parser(Protocol):
    name: str                    # 引擎名称
    needs_local_models: bool     # 是否需要下载本地模型

    def resolve_config(self) -> Any: ...
    def supported_formats(self) -> frozenset[str]: ...
    def signature(self, config) -> ParserSignature: ...
    def is_ready(self, config) -> ReadinessReport: ...
    def parse(self, source_path, workdir, *, config, on_output) -> None: ...
```

**业务含义：** 这是所有解析引擎的"统一合同"。每个引擎必须实现这 6 个方法。

**方法详解：**

**`resolve_config(self)`：**
- **业务做什么：** 从系统设置中加载该引擎的配置
- **大白话解释：** 去"设置中心"读取自己的配置（模型版本、语言、模式等）

**`supported_formats(self)`：**
- **业务做什么：** 返回该引擎支持的文件格式列表
- **输出：** `frozenset`（如 `{".pdf", ".docx", ".pptx"}`）
- **大白话解释：** 告诉系统"我能处理哪些类型的文件"

**`signature(self, config)`：**
- **业务做什么：** 生成该引擎当前配置的"指纹"
- **输出：** `ParserSignature` 对象
- **大白话解释：** 给当前配置拍一张"照片"——如果配置变了，"照片"也会变，缓存就会失效，需要重新解析

**`is_ready(self, config)`：**
- **业务做什么：** 检查引擎是否准备好执行解析
- **输出：** `ReadinessReport`
- **大白话解释：** 启动前的自检——工具和模型都就绪了吗？

**`parse(self, source_path, workdir, *, config, on_output)`：**
- **业务做什么：** 执行文档解析，把结果写入工作目录
- **输入：** `source_path`（源文件路径）、`workdir`（输出目录）、`config`（引擎配置）、`on_output`（可选的回调函数，用于实时输出进度）
- **关键约定：** 引擎必须输出 `<stem>.md`（Markdown 文件），可选输出 `<stem>_content_list.json`（结构化内容）和 `images/`（提取的图片）
- **大白话解释：** 开始干活——把文件拆解成文字和结构，放到指定的文件夹里

## 4. 解析配置指纹（signature.py）

*文件：`deeptutor/services/parsing/signature.py`*

### 4.1 `ParserSignature`（解析器指纹）

*文件位置：signature.py，第 17-49 行*

```python
@dataclass(frozen=True)
class ParserSignature:
    engine: str                          # 引擎名称
    engine_version: str                  # 引擎版本
    params: tuple[tuple[str, str], ...]  # 影响输出的配置参数
```

**业务含义：** ParserSignature 是解析配置的"数字指纹"。它只包含那些真正影响解析结果的配置字段（如引擎版本、模式、语言），不包含像 API token 这样的无关字段。当同一个文件用相同的指纹解析时，可以直接读缓存，不用重新解析。

**`hash(self)`（第 32-40 行）：**
- **业务做什么：** 生成指纹的 SHA256 哈希值
- **输出：** 16 位十六进制字符串
- **大白话解释：** 给配置拍一张"数字照片"——生成一个唯一的哈希值，相同的配置产生相同的哈希

**`build(engine, engine_version, params)`（第 42-49 行）：**
- **业务做什么：** 构建 ParserSignature 实例
- **关键逻辑：** 对参数按键排序，确保顺序不影响哈希值
- **大白话解释：** 按规则生成指纹——参数按字母排序，确保 `{a:1, b:2}` 和 `{b:2, a:1}` 产生相同的哈希

## 5. 内容寻址缓存（cache.py）

*文件：`deeptutor/services/parsing/cache.py`*

### 5.1 缓存系统设计

**缓存目录结构：**
```
parse_cache/
  └── <hash[:2]>/          # 用哈希前 2 位做分片
      └── <source_hash>/    # 源文件的哈希
          └── <signature>/   # 解析配置的哈希
              ├── manifest.json       # 缓存清单（存在 = 缓存有效）
              ├── <stem>.md           # Markdown 输出
              ├── <stem>_content_list.json  # 结构化内容（可选）
              └── images/             # 提取的图片（可选）
```

**核心设计原则：**
- **内容寻址：** 缓存键 = 文件内容哈希 + 解析配置哈希。同一个文件即使用不同的文件名上传，只要内容一样就能命中缓存
- **原子性：** `manifest.json` 最后写入，它的存在 = 缓存有效。如果解析中途崩溃，manifest 不存在，下次会重新解析
- **引擎隔离：** 不同引擎的解析结果存在不同的签名目录下，互不干扰

### 5.2 核心函数

**`source_hash_from_path(path)`（第 36-43 行）：**
- **业务做什么：** 计算文件内容的 SHA256 哈希值
- **关键设计：** 哈希的是文件**内容**（bytes），不是文件名。所以即使用户把同一个文件改名后重新上传，也能命中缓存
- **大白话解释：** 给文件内容拍一张"指纹照"——不管文件叫什么名字，只要内容一样，指纹就一样

**`lookup(cache_root, source_hash, sig_hash)`（第 54-57 行）：**
- **业务做什么：** 在缓存中查找是否已有解析结果
- **输出：** 缓存目录路径（命中）或 `None`（未命中）
- **大白话解释：** 翻翻档案柜，看看这个文件用这个配置解析过没有

**`reserve(cache_root, source_hash, sig_hash)`（第 60-70 行）：**
- **业务做什么：** 预留缓存目录（清空之前不完整的缓存）
- **关键逻辑：** 如果目录存在但没有 manifest（上次解析崩溃了），先清空再重用
- **大白话解释：** 在档案柜里腾出一个空位——如果之前有烂尾的档案，先清理掉

**`write_manifest(workdir, meta)`（第 73-81 行）：**
- **业务做什么：** 写入缓存清单，标记缓存为"已完成"
- **关键设计：** manifest 最后写入，确保"半成品"不会被当作"成品"使用
- **大白话解释：** 档案整理完毕，贴上"已完成"标签

**`cleanup_failed(workdir)`（第 84-90 行）：**
- **业务做什么：** 清理解析失败的缓存目录
- **大白话解释：** 解析失败了，把半成品清理掉，别占着位置

**`find_content_dir(workdir)`（第 93-123 行）：**
- **业务做什么：** 在缓存目录中找到实际的输出内容目录
- **关键逻辑：** 不同引擎输出目录结构不同——MinerU 可能把结果放在 `auto/` 或 `hybrid_auto/` 子目录下，这个函数会智能定位
- **大白话解释：** 在档案夹里找到真正的"正文"——不同引擎存放位置不同，这里统一查找

**`load_ir(workdir)`（第 151-178 行）：**
- **业务做什么：** 从缓存目录加载解析结果
- **输出：** `(markdown, blocks, asset_dir)` 三元组
- **关键逻辑：** 加载 Markdown 文件、结构化内容 JSON、图片目录；对图片路径做绝对化处理（相对路径 → 绝对路径）
- **大白话解释：** 从档案柜里取出档案——文字、结构、图片，全部拿出来

## 6. 解析服务入口（service.py）

*文件：`deeptutor/services/parsing/service.py`*

### 6.1 `ParseService`（解析服务）

*文件位置：service.py，第 28-129 行*

```python
class ParseService:
    def __init__(self, cache_root: Optional[Path] = None) -> None:
        ...
```

**业务含义：** ParseService 是文档解析的"总服务台"。所有需要解析文档的地方都通过它来调用。它负责缓存管理、引擎选择、解析执行。

**`active_engine(self)`（第 43-46 行）：**
- **业务做什么：** 返回当前活跃的解析引擎名称
- **大白话解释：** 告诉调用方"现在默认用哪个引擎"

**`parse(self, source_path, *, engine, on_output)`（第 48-129 行）：**
- **业务做什么：** 解析文档（核心方法）
- **输入：**
  - `source_path`：要解析的文件路径
  - `engine`：指定引擎（可选，不指定则用默认引擎）
  - `on_output`：可选的回调函数，用于实时输出解析进度
- **输出：** `ParsedDocument`

**执行流程（大白话解释）：**

1. **文件存在性检查（第 62-64 行）：** 先确认文件还在不在，"文件找不到"直接报错
2. **选择引擎（第 66-67 行）：** 如果用户指定了引擎就用指定的，否则用系统默认的
3. **格式兼容性检查（第 70-76 行）：** 检查这个引擎能不能处理这种文件格式。比如 MinerU 只能处理 PDF，如果用户上传了一个 Word 文件，就提示换引擎
4. **计算缓存键（第 78-79 行）：**
   - 计算源文件的哈希值（`source_hash`）
   - 计算引擎配置的哈希值（`parser_signature`）
5. **缓存查找（第 82-94 行）：** 先去缓存里找——如果之前解析过了，直接返回缓存结果
6. **引擎就绪检查（第 96-98 行）：** 如果缓存没命中，检查引擎是否准备好了（模型是否下载、工具是否安装）
7. **执行解析（第 100-129 行）：**
   - 预留缓存目录
   - 调用引擎的 `parse()` 方法执行解析
   - 加载解析结果
   - 验证内容不为空（"引擎产出了空气"）
   - 写入缓存清单
   - 返回 ParsedDocument
8. **失败清理（第 127-129 行）：** 如果解析失败，清理缓存目录，不让"半成品"污染缓存

**`get_parse_service()`（第 135-140 行）：**
- **业务做什么：** 获取全局单例的 ParseService
- **大白话解释：** 获取唯一的档案管理员

## 8. 引擎详解

### 8.1 Text-only 引擎（纯文本提取）

*`engines/text_only/engine.py`*

**业务含义：** 最基础的解析引擎。使用 Python 标准库和轻量依赖（如 `python-docx`、`openpyxl`）提取文件中的纯文本。不保留任何排版、表格、图片等结构。

**大白话解释：** 最朴素的"抄写员"——不管什么格式，只把里面的文字抄出来，不关心排版。

### 8.2 MinerU 引擎（高保真解析）

*`engines/mineru/engine.py`*

**业务含义：** 目前最强悍的解析引擎。能识别 PDF 中的复杂排版、表格、公式（LaTeX）、图片、页眉页脚等。支持本地 CLI 模式和云端 API 模式。

**特色能力：**
- 表格识别和结构化提取
- 数学公式识别（转 LaTeX）
- 版面分析（自动识别标题、正文、图片区域）
- 输出结构化 `content_list` JSON

**大白话解释：** 最专业的"档案拆解师"——不仅能读文字，还能认出表格、公式、图片，甚至知道哪个是标题、哪个是正文。

### 8.3 Docling 引擎（结构化转换）

*`engines/docling/engine.py`*

**业务含义：** IBM 开源的文档转换工具。支持 PDF、Office、HTML、图片等多种格式。自动下载模型，使用深度学习进行版面分析。

**大白话解释：** 聪明的"文件翻译官"——自动识别文档结构，把 PDF/Word 转成有格式的 Markdown。

### 8.4 markitdown 引擎（轻量通用）

*`engines/markitdown/engine.py`*

**业务含义：** 微软开源的轻量级文档转换工具。支持极广的格式范围（PDF、Word、PPT、Excel、图片、音频、HTML、CSV、JSON、XML、ZIP 等），无需下载模型，开箱即用。

**大白话解释：** 万能的"文件转换器"——什么格式都能转，不需要额外配置，但精度不如 MinerU。

### 8.5 PyMuPDF4LLM 引擎（轻量 PDF）

*`engines/pymupdf4llm/engine.py`*

**业务含义：** 基于 PyMuPDF 的轻量 PDF 解析器。无需 GPU 和模型下载，适合低配机器。支持 PDF 和电子书格式。

**大白话解释：** 轻便的"PDF 阅读器"——不需要 GPU 就能把 PDF 转成 Markdown，还能提取图片。

## 9. 数据流总览

```
用户上传 PDF 文件 "微积分讲义.pdf"
        │
        ▼
   ParseService.parse(source_path="微积分讲义.pdf")
        │
        ├─ 文件存在性检查
        ├─ 确定引擎 (默认 MinerU)
        ├─ 格式兼容性检查 (MinerU 支持 .pdf ✓)
        │
        ├─ 计算 source_hash (文件内容的 SHA256)
        ├─ 计算 parser_signature (引擎配置的 SHA256)
        │
        ├─ 缓存查找 ─────────────────────────────┐
        │  lookup(cache_root, source_hash, sig)  │
        │  │                                      │
        │  ├─ 命中 → 直接返回 ParsedDocument      │
        │  │    └─ load_ir() → markdown + blocks  │
        │  │                                      │
        │  └─ 未命中 ↓                            │
        │                                         │
        ├─ 引擎就绪检查                            │
        │  is_ready() → ReadinessReport           │
        │  │                                      │
        │  ├─ ready=True → 继续                   │
        │  └─ ready=False → 抛出 ParserError       │
        │                                         │
        ├─ 预留缓存目录                            │
        │  reserve() → 清理旧的半成品               │
        │                                         │
        ├─ 执行解析                                │
        │  parser.parse(source_path, workdir)     │
        │  │                                      │
        │  ├─ MinerU 引擎:                         │
        │  │   ├─ 版面分析 (识别标题/正文/表格)     │
        │  │   ├─ 表格识别 → 结构化提取            │
        │  │   ├─ 公式识别 → LaTeX 渲染            │
        │  │   ├─ 输出 <stem>.md                   │
        │  │   ├─ 输出 <stem>_content_list.json    │
        │  │   └─ 输出 images/                     │
        │  │                                      │
        │  └─ 其他引擎: 各自实现                    │
        │                                         │
        ├─ 加载解析结果                            │
        │  load_ir() → (markdown, blocks, images) │
        │                                         │
        ├─ 验证内容非空                             │
        │                                         │
        ├─ 写入缓存清单                            │
        │  write_manifest() → manifest.json       │
        │                                         │
        └─ 返回 ParsedDocument ───────────────────┘
           │
           ├─ markdown: "## 第一章 微积分基础\n..."
           ├─ blocks: [{type: "text", ...}, {type: "table", ...}]
           ├─ asset_dir: Path("images/")
           └─ engine: "mineru"
```

## 10. 一句话总结

文档解析服务是 DeepTutor 的"万能文件翻译器"——它支持 5 种解析引擎，能把 PDF、Word、PPT 等各种格式的文件拆解成结构化的文字和内容，并且通过智能缓存机制，同一个文件只解析一次，让 AI 能快速"读懂"用户上传的任何文档。
