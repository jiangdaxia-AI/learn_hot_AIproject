# 内置工具集

> Understand-Anything 知识图谱: 26 节点, 25 边, 7 层
> 复杂度：`moderate`

## 一句话说明

DeepTutor 给 AI 配备的“瑞士军刀”。每个工具都是一项独立能力：查知识库、搜网页、运行代码、读/写记忆、管理笔记本、调用 GitHub、向用户提问等。AI 在对话中会根据需要选择合适的工具调用。

## 业务价值

教学场景不是单纯聊天。学生/教师会提出各种各样的问题：

| 用户诉求 | 对应工具 | 为什么需要 |
|----------|----------|-----------|
| “根据教材第 3 章回答” | `rag` | 答案必须基于教材，不能胡编 |
| “这道题怎么做？”配图是几何题 | `geogebra_analysis` | 识别图形并生成可交互几何图 |
| “帮我算一下这个公式” | `code_execution` | AI 口算不可靠，用代码验证 |
| “我上周问过的那题” | `read_memory` / `list_notebook` | 记住用户历史，保持连续性 |
| “把这段话存到错题本” | `write_note` | 把聊天内容沉淀为学习资料 |
| “这个知识点最新进展是什么？” | `web_search` / `paper_search` | 教材之外的知识补充 |
| “你确定吗？” | `reason` | 让 AI 做独立推理，提高可信度 |
| “稍后再提醒我复习” | `cron` | 定时任务，学习规划 |

## 核心设计思想

1. **工具是 Agent 能力的延伸**：没有工具，AI 只能“空口说白话”；有了工具，AI 可以查、可以算、可以记。
2. **每个工具独立可测试**：`get_definition()` 描述工具怎么用，`execute()` 描述具体做什么。
3. **按需挂载**：不是每次对话都把所有工具塞给 AI，而是由聊天管道根据场景动态挂载。

## 源码视角

### 文件 `deeptutor/tools/builtin/__init__.py`

这是所有内置工具的“大本营”。每个工具都是一个类，继承自 `BaseTool`，必须实现两个方法：

- `get_definition()`：告诉 AI 这个工具叫什么名字、有什么用、需要什么参数。
- `execute()`：真正执行工具逻辑。

下面逐个解读关键工具。

---

### `BrainstormTool` — 头脑风暴

**源码位置**：`deeptutor/tools/builtin/__init__.py:42`

#### 作用

当用户说“帮我列几个思路”“我想不出方案”时，AI 调用这个工具进行头脑风暴，给出多个可选方向。

#### `get_definition()`

定义工具名 `brainstorm`，参数：

- `topic`：要 brainstorm 的主题（必填）
- `context`：背景信息（可选）

#### `execute()` 执行流程

1. 从参数里取出 `topic` 和 `context`
2. 调用 `deeptutor.tools.brainstorm.brainstorm()` 函数
3. 把返回结果包装成 `ToolResult` 交给 AI

> 大白话：AI 不会自己空想，而是调用一个专门的“头脑风暴函数”，这个函数内部会构造 prompt 发给 LLM，让 LLM 列出多个备选方案。

---

### `RAGTool` — 知识库检索

**源码位置**：`deeptutor/tools/builtin/__init__.py:77`

#### 作用

从用户上传的教材/知识库里，找到与问题最相关的段落。这是 DeepTutor“基于教材回答”的核心。

#### `get_definition()`

- 工具名 `rag`
- 参数：
  - `query`：要检索的问题
  - `kb_name`：知识库名字（必须是用户已挂载的知识库）

#### `execute()` 执行流程

1. 校验 `query` 和 `kb_name` 非空
2. 调用 `rag_search(query, kb_name, ...)`
3. 返回结果时带上 `sources`：
   - `type: "rag"`
   - `query`：实际查询语句
   - `kb_name`：知识库名

> 业务意义：AI 回答“根据教材第三章……”时，底层就是先调用 `rag` 找到相关段落，再组织语言回答。`sources` 让答案可溯源。

---

### `WebSearchTool` — 网页搜索

**源码位置**：`deeptutor/tools/builtin/__init__.py:126`

#### 作用

当教材里找不到答案，或者需要最新信息时，去互联网搜索。

#### `execute()` 执行流程

1. 拿到 `query`
2. 在后台线程执行 `web_search()`（避免阻塞主循环）
3. 提取 `answer` 和 `citations`（引用来源）
4. 把每条引用整理成 `sources`：
   - `type: "web"`
   - `url`
   - `title`

> 业务意义：让 AI 回答“2026 年高考政策”这类教材里没有的内容，同时每条信息都标注来源，避免误导。

---

### `CodeExecutionTool` — 代码执行沙箱

**源码位置**：`deeptutor/tools/builtin/__init__.py:166`

#### 作用

让学生/AI 写的 Python/C/C++ 代码在隔离沙箱里运行，验证答案。

#### 支持的语言

```python
_LANGUAGES = {
    "python": ("main.py", "python3 {src} {stdin}"),
    "c":      ("main.c", "cc {src} -O2 -o prog && ./prog {stdin}"),
    "cpp":    ("main.cpp", "c++ -std=c++17 -O2 {src} -o prog && ./prog {stdin}"),
}
```

#### `execute()` 执行流程

1. 读取 `code`、`language`、`stdin`、`timeout`
2. 把语言别名（如 `py`、`python3`）统一映射成标准名
3. 校验语言是否支持
4. 为每次调用生成独立运行目录，避免互相覆盖
5. 把代码写入文件
6. 如果有 `stdin`，写入 `stdin.txt`
7. 组装编译/运行命令
8. 调用沙箱服务执行
9. 收集程序输出和生成的文件（artifact）
10. 返回运行结果：
    - `content`：stdout/stderr + artifact 描述
    - `success`：是否运行成功
    - `metadata`：exit_code、命令、运行目录、artifact 列表等

> 业务意义：数学、编程、物理题需要“算出来”而不是“猜出来”。沙箱隔离保证安全性，每个调用独立目录保证并发安全。

---

### `ReasonTool` — 独立推理

**源码位置**：`deeptutor/tools/builtin/__init__.py:342`

#### 作用

让 AI 对复杂子问题做一次“深度思考”。相当于让 AI 把难题拆出来单独想一遍，再给出结论。

#### `execute()` 执行流程

1. 读取 `query` 和 `context`
2. 调用 `deeptutor.tools.reason.reason()`
3. 返回 LLM 的推理结果

> 业务意义：有些问题直接回答容易出错，比如多步推理题。`reason` 工具让 AI 先内部思考，再输出最终答案。

---

### `PaperSearchToolWrapper` — 学术论文搜索

**源码位置**：`deeptutor/tools/builtin/__init__.py:380`

#### 作用

在 arXiv 上搜索学术论文，适合学生做研究、写论文时使用。

#### `execute()` 执行流程

1. 接收 `query`、`max_results`、`years_limit`、`sort_by`
2. 调用 `ArxivSearchTool().search_papers()`
3. 如果没找到或网络错误，返回友好提示
4. 把论文标题、作者、摘要、URL 整理成可读文本
5. 返回每条论文的引用来源

---

### `GeoGebraAnalysisTool` — 几何图像分析

**源码位置**：`deeptutor/tools/builtin/__init__.py:460`

#### 作用

学生上传几何题图片后，AI 识别图中的几何元素，并生成 GeoGebra 命令，方便可视化。

#### `execute()` 执行流程

1. 读取 `question` 和图片 `image_base64`
2. 如果图片不是 `data:image/...` 格式，自动补全前缀
3. 创建 `VisionSolverAgent`
4. 调用 `agent.process(question_text, image_base64)`
5. 提取约束条件、几何关系、GeoGebra 命令
6. 返回结构化的分析结果

> 业务意义：几何题“看图”是关键能力。这个工具把图像理解和动态几何工具结合起来，让学生不仅能看，还能动手拖动验证。

---

### `ReadSourceTool` — 读取附件源

**源码位置**：`deeptutor/tools/builtin/__init__.py:569`

#### 作用

当 AI 需要查看用户附件的完整内容时使用。比如用户上传了一份笔记、历史会话、题库条目。

#### `execute()` 执行流程

1. 校验 `source_id`
2. 从 `source_index`（聊天管道注入的附件索引）查找对应内容
3. 返回完整文本

> 业务意义：用户附件可能很长，AI 不能每次都用上全部内容。`read_source` 让 AI 按需读取，节省 token。

---

### `ReadMemoryTool` / `WriteMemoryTool` — 读写长期记忆

**源码位置**：`deeptutor/tools/builtin/__init__.py:633` / `:663`

#### 作用

- `read_memory`：读取用户的长期记忆（学习偏好、薄弱点、目标等）
- `write_memory`：当用户明确表达偏好时，写入长期记忆

#### `WriteMemoryTool.execute()` 执行流程

1. 校验操作类型 `op`（`add` 或 `edit`）
2. 校验 `text` 非空
3. 创建一条 `TraceEvent`（记忆变更审计）
4. 调用 `store.write_preference()` 写入 L3 记忆
5. 返回写入结果

> 业务意义：没有记忆，AI 每次对话都从零开始。`read_memory` 让 AI 记住学生，`write_memory` 让学生主动告诉 AI “以后请用简单语言解释”。

---

### `WebFetchTool` — 网页抓取

**源码位置**：`deeptutor/tools/builtin/__init__.py:756`

#### 作用

用户给出具体 URL 时，抓取网页内容并转为 Markdown。

#### `execute()` 执行流程

1. 校验 URL
2. 调用 `fetch_url_as_markdown()`
3. 如果失败返回错误
4. 成功返回 markdown 内容、标题、URL

### `ListNotebookTool` / `WriteNoteTool` — 笔记本管理

**源码位置**：`deeptutor/tools/builtin/__init__.py:820` / `:870`

#### 作用

- `list_notebook`：列出用户的笔记本或某个笔记本里的记录
- `write_note`：新建或编辑笔记

#### `WriteNoteTool` 两种模式

- `append`：新增一条笔记，默认保存最近聊天记录
- `edit`：修改已有笔记，需要 `record_id`

> 业务意义：错题本、学习笔记是学生的重要资产。AI 可以把对话中的关键内容自动沉淀下来。

### `AskUserTool` — 向用户提问

**源码位置**：`deeptutor/tools/builtin/__init__.py:1059`

#### 作用

当 AI 不确定用户意图时，暂停对话，弹出一个选择题卡片让用户选择。用户回复后，Agent 循环继续。

#### `execute()` 执行流程

1. 把 `questions` 数组整理成结构化 payload
2. 返回 `ToolResult`，其中 `pause_for_user` 字段携带问题
3. 聊天管道检测到 `pause_for_user` 后暂停，等用户回复

> 业务意义：避免 AI 瞎猜。比如用户说“帮我推荐本书”，AI 可以先问年级、学科、目标。

## 工具挂载策略

源码末尾有几组关键常量：

| 常量 | 含义 |
|------|------|
| `BUILTIN_TOOL_TYPES` | 所有已注册的内置工具 |
| `USER_TOGGLEABLE_TOOL_NAMES` | 用户可以在设置里开关的工具 |
| `CONFIGURABLE_BUILTIN_TOOL_NAMES` | 聊天管道自动挂载的工具 |
| `TOOL_ALIASES` | 工具别名，兼容不同叫法 |

### 用户可开关的工具

```python
USER_TOGGLEABLE_TOOL_NAMES = (
    "brainstorm",
    "web_search",
    "paper_search",
    "reason",
    "geogebra_analysis",
    "imagegen",
    "videogen",
)
```

这些属于“体验增强”类工具，不是每次都用得上，用户可以自己决定是否开启。

### 自动挂载的工具

```python
CONFIGURABLE_BUILTIN_TOOL_NAMES = (
    "rag", "code_execution", "read_source", "read_memory",
    "write_memory", "read_skill", "list_notebook", "write_note",
    "web_fetch", "github", "exec", "load_tools", "cron", "ask_user",
)
```

这些是基础教学能力，由系统根据上下文自动挂载。

## 总结

内置工具集是 DeepTutor 的“能力仓库”。每个工具都解决一个具体教学场景：

- **查**：`rag`、`web_search`、`paper_search`
- **算**：`code_execution`
- **看**：`geogebra_analysis`
- **记**：`read_memory`、`write_memory`、`list_notebook`、`write_note`
- **问**：`ask_user`
- **管**：`cron`、`github`、`read_skill`、`load_tools`

AI 在对话中会根据问题类型，动态调用合适工具，从而把“聊天”升级为“能做实事的教学助手”。
