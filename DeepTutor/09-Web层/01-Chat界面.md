# Chat 界面 — DeepTutor 的"对话大脑"

## 一句话说明

DeepTutor 的核心对话页面，学生在这里与 AI 老师进行多轮对话。它不只是"打字聊天"，而是一个集成了**多种教学能力模式**、**上下文引用系统**、**实时流式响应**、**分支对话**和**可追溯思考过程**的智能教学终端。

---

## 业务价值

- **核心教学入口**：所有教学对话的发生地，学生在这里提问、做测验、做深度研究、让 AI 生成数学动画。
- **多能力模式切换**：同一界面支持从"自由聊天"到"深度解题""出题""深度研究""数学动画""可视化"等不同教学模式，学生不需要切换页面。
- **上下文感知**：学生可以引用教材章节、历史对话、错题本、知识库、记忆档案作为当前对话的上下文，AI 的回复会更精准。
- **透明可解释**：学生可以看到 AI 的"思考过程"（Trace），理解 AI 为什么这么回答，增强信任感。
- **分支对话**：支持编辑已发送消息来"分叉"对话，尝试不同的提问方式，每条分支独立可回溯。

## 核心组件详解

### 1. Chat 主页 (`page.tsx`)

**作用**：Chat 页面的顶层编排器，负责把所有子组件串起来，管理会话生命周期。

**场景**：学生打开 DeepTutor 后默认进入这个页面，开始与 AI 对话。

**关键功能**：
- **会话管理**：通过 URL 中的 `sessionId` 参数标识当前会话，支持新建会话（无 sessionId）和恢复历史会话。
- **能力配置**：当学生切换到"出题"或"可视化"等需要额外配置的能力时，自动在右侧面板展示配置卡片。
- **文件附件处理**：支持拖拽/粘贴上传文件，自动分类（图片、PDF、Office 文档等），在发送前预览。
- **上下文引用管理**：管理当前会话引用的教材章节、历史对话、错题本条目、知识库等。
- **流式通信**：通过 WebSocket 与后端保持实时连接，接收 AI 的流式响应。

**源码路径**：`web/app/(workspace)/home/[[...sessionId]]/page.tsx`（第 1-1600+ 行）

---

### 2. 消息列表 (`ChatMessages.tsx`)

**作用**：渲染对话历史中的每一条消息，是用户"看到"的聊天记录。

**场景**：每次发送消息后，消息列表实时更新；加载历史会话时，展示完整对话历史。

**子组件**：

#### 2.1 用户消息 (`UserMessage`)

**路径**：`ChatMessages.tsx` 第 859-1115 行

**交互**：
- **消息气泡**：右对齐，圆角矩形，灰色背景，显示用户发送的文本。
- **能力标签**：气泡上方显示当前使用的教学模式（如"Deep Solve""Quiz Generation""Deep Research"）。
- **上下文引用树**：气泡下方折叠展示该消息引用的教材、知识库、历史对话、记忆档案等。
- **编辑（分支）**：鼠标悬停时显示编辑按钮，点击进入编辑模式，修改后发送会创建对话分支。
- **分支导航**：当某条消息有多个分支时，显示 `< 2/3 >` 导航器，学生可以切换查看不同分支的回复。
- **复制**：鼠标悬停时显示复制按钮。

**比喻**：用户消息就像学生在课堂上举手提问，气泡上的标签标注了"这是数学题"还是"这是阅读理解"——老师（AI）会根据标签用不同的方式回答。

#### 2.2 AI 回复 (`AssistantMessage`)

**路径**：`ChatMessages.tsx` 第 277-513 行

**交互**：
- **思考过程（Activity）**：回复上方显示 AI 的"思考过程"——调用了什么工具、搜索了什么、推理了多久。流式回复时实时展开，完成后折叠。
- **多模态渲染**：根据回复类型自动切换渲染方式：
  - **普通聊天**：Markdown 渲染，支持公式、代码高亮、表格。
  - **深度研究**：显示大纲编辑器 + 研究阶段卡片 + 最终报告。
  - **出题模式**：显示测验卡片（QuizViewer），学生可以直接答题。
  - **数学动画**：显示交互式数学动画（MathAnimatorViewer）。
  - **可视化**：显示图表/数据可视化（VisualizationViewer）。
- **追问卡片（AskUserOptions）**：当 AI 需要学生澄清时，显示选项按钮或文本输入框。
- **生成文件卡片**：AI 生成的图片/视频/代码文件以卡片形式展示，点击可在右侧预览。
- **操作按钮**：鼠标悬停时显示复制、朗读、重新生成、删除按钮。
- **费用统计**：每次回复底部显示消耗的 token 数和费用。

**比喻**：AI 回复不只是"说一段话"，如果学生问"给我出几道题"，AI 的回复里直接嵌入了可交互的答题卡；如果学生问"帮我研究一下光合作用"，AI 会展示研究计划、分阶段搜索、最终形成报告——就像老师不只是口头回答，而是拿出教具、布置练习、展示研究成果。

#### 2.3 深度研究合并

**路径**：`ChatMessages.tsx` 第 1179-1227 行

深度研究是两轮对话：第一轮 AI 提出研究大纲，学生确认后，第二轮 AI 执行研究。但视觉上这两轮被**合并成一个气泡**——学生看到的是"大纲编辑 → 研究过程 → 最终报告"的连续流程，不会感到"被切成两段"。

### 3. 输入框 (`ChatComposer.tsx`)

**作用**：消息发送的"控制台"，学生在这里输入文字、附加文件、选择能力模式、配置上下文。

**路径**：`web/components/chat/home/ChatComposer.tsx`（第 1-1060 行）

**场景**：所有对话的起点。学生在这里打字、粘贴图片、拖拽文件、切换教学模式。

**交互区域（从上到下）**：

#### 3.1 上下文引用区

**路径**：`ChatComposer.tsx` 第 601-617 行

显示当前消息附加的所有上下文引用，以折叠树的形式呈现：
- 📚 **教材章节**：引用某本教材的某几页
- 📓 **笔记本**：引用错题本中的记录
- 💬 **历史对话**：引用之前的某段对话
- 🤖 **Agent 对话**：引用子 Agent 的对话历史
- 📋 **题库**：引用题库中的题目
- 👤 **角色**：当前使用的教学角色
- 🧠 **记忆**：引用学生的记忆档案

每个引用项都可以单独删除。这就像学生在提问前"翻到课本第几页、拿出上次的错题本、提醒老师上次说过什么"。

#### 3.2 文本输入域 (`ComposerInput`)

**路径**：`web/components/chat/home/ComposerInput.tsx`（第 1-549 行）

**交互**：
- **自动伸缩**：随着输入内容增多，文本框自动增高（最小 28px，空状态时 64px）。
- **@ 提及**：输入 `@` 触发 Agent 选择器，可以召唤子 Agent 协助。
- **/ 命令**：输入 `/persona` 快速切换教学角色。
- **Enter 发送**：按 Enter 发送（中文输入法组合输入时不会误触发）。
- **粘贴上传**：支持粘贴图片自动作为附件。

#### 3.3 文件附件预览区

**路径**：`ChatComposer.tsx` 第 650-743 行

上传的文件以缩略图卡片形式展示，图片显示预览，文档显示类型图标+文件名+大小。

#### 3.4 底部工具栏

**路径**：`ChatComposer.tsx` 第 754-1055 行

从左到右：
- **能力选择器**（Capability）：下拉菜单，选择当前教学模式。包含"Chat""Deep Solve""Quiz Generation""Deep Research""Math Animator""Visualize""Mastery Path"，以及"More Capabilities"（Agent-loop 驱动的高级模式）。
- **上下文添加按钮**（+）：弹出空间菜单，添加教材、笔记本、历史对话、Agent 对话、题库、角色、记忆等上下文。
- **Agent 选择器**：选择当前轮次要调用的子 Agent。
- **知识库选择器**：选择当前会话使用的知识库范围。
- **角色选择器**：选择 AI 的教学角色/人格。
- **模型选择器**：选择当前对话使用的 LLM 模型。
- **语音输入按钮**：点击开始录音，自动转文字填入输入框。
- **发送/停止按钮**：流式回复时显示停止按钮（带旋转动画），否则显示发送按钮。

**比喻**：输入框就像学生的"万能提问台"——上面可以贴参考资料（上下文引用），中间写字（文本输入），下面有各种设置旋钮（能力模式、模型、角色），最后按下发送键。

### 4. 思考过程面板 (`TracePanels.tsx`)

**作用**：展示 AI 回复背后的"思考过程"，让 AI 的推理透明化。

**路径**：`web/components/chat/home/TracePanels.tsx`（第 1-2540+ 行）

**场景**：每次 AI 回复时，Trace 面板实时展开在回复上方，展示 AI 正在做什么。回复完成后，Trace 折叠，学生可以点击展开回顾。

**展示内容**：
- **推理轮次**：AI 进行了几轮工具调用，每轮调用了什么工具（搜索、代码执行、知识库检索等）。
- **工具调用详情**：每个工具调用的参数和返回结果。
- **阶段标签**：如"理解问题 → 分解 → 搜集证据 → 生成结果"。
- **耗时统计**：每个阶段花费的时间。
- **子 Agent 活动**：如果调用了子 Agent，展示子 Agent 的实时输出。

**对于深度研究**，Trace 更丰富：
- **理解阶段**：AI 复述和澄清研究问题。
- **分解阶段**：将大问题拆成子问题。
- **证据收集**：逐个搜索子问题，展示搜索词和结果摘要。
- **报告生成**：整合所有证据，撰写最终报告。

**比喻**：Trace 就像"老师备课过程的录像"——学生不仅看到最终的讲解，还能看到老师查阅了哪些资料、如何组织思路、纠正了哪些错误。这建立了对 AI 的信任。

## 上下文引用系统

**作用**：让学生在发送消息时附带各种"参考资料"，AI 会基于这些资料给出更精准的回答。

**工作原理**：每次发送消息时，前端将当前选中的所有上下文引用打包成一个 `requestSnapshot`，连同消息文本一起通过 WebSocket 发送给后端。后端在生成回复时会参考这些上下文。

**引用类型**：

| 引用类型 | 选择器组件 | 数据含义 |
|---------|-----------|---------|
| 教材章节 | BookReferencePicker | 指定教材的哪些章节/页面 |
| 笔记本 | 笔记本选择器 | 错题本/笔记本中的记录 |
| 历史对话 | HistorySessionPicker | 之前的某段对话 |
| Agent 对话 | MyAgentsPicker | 子 Agent 的对话历史 |
| 题库 | QuestionBankPicker | 题库中的题目 |
| 角色 | PersonaPicker | AI 的教学角色 |
| 记忆 | MemoryPicker | 学生的记忆档案 |

**源码**：选择器组件位于 `web/components/chat/` 目录下，每个选择器是一个独立的弹窗/抽屉组件。

## 流式响应机制

**作用**：AI 的回复不是"一次性返回"，而是像打字一样逐字出现，给学生实时反馈。

**原理**：
1. 前端通过 WebSocket 连接到后端
2. 发送消息后，后端通过 WebSocket 推送 `StreamEvent` 事件流
3. 事件类型包括：`content`（文本片段）、`tool_call`（工具调用）、`tool_result`（工具结果）、`result`（最终结果）、`error`（错误）
4. 前端实时更新消息内容，直到收到 `result` 事件标记该轮结束

**源码**：WebSocket 连接管理在 `web/context/UnifiedChatContext.tsx`（第 1-1900+ 行），事件流处理在 `ChatMessages.tsx` 和 `ChatComposer.tsx` 中。

## 分支对话（Branching）

**作用**：学生可以"编辑已发送的消息"，创建对话的"平行宇宙"。

**场景**：学生问了一道题，AI 回答了。学生觉得问题问得不够好，点击编辑，重新措辞，再次发送。AI 会生成新的回复，但原来的回复不会丢失——学生可以通过 `< 1/2 >` 导航器在两个分支间切换。

**实现**：
- 编辑消息时，前端发送 `editMessage` 请求，后端创建新的分支。
- `buildVisiblePath` 函数（`web/lib/message-branches.ts`）根据当前选中的分支构建可见的消息路径。
- 分支导航器 `BranchNavigator`（`ChatMessages.tsx` 第 781-819 行）提供切换 UI。

## 辅助功能

### 朗读（TTS）
- **路径**：`ChatMessages.tsx` 中 `PlayAudioButton` 组件（第 631-779 行）
- **交互**：点击 AI 回复旁的喇叭图标，将文本转为语音播放。
- **自动播放**：首次手动播放后弹出提示"是否自动播放后续回复？"，确认后该会话所有新回复自动朗读。

### 语音输入
- **路径**：`ChatComposer.tsx` 中 `useVoiceRecorder` hook（第 349-354 行）
- **交互**：点击麦克风按钮开始录音，自动转文字填入输入框。

### 复制与重新生成
- **复制**：一键复制 AI 回复的全部文本。
- **重新生成**：对同一条用户消息，让 AI 重新生成回复。

## 总结

Chat 界面是 DeepTutor 的"教学驾驶舱"。它把 AI 对话从"一问一答"升级为"多模式教学 + 上下文感知 + 过程透明 + 分支探索"的完整教学体验。学生在这里不只是和 AI 聊天，而是在与一个配备了教材、错题本、搜索工具、代码执行器和数学动画引擎的"AI 教师团队"互动。
