# 核心流程：出题与评分

> 涉及模块：AgentCoordinator → 题目工具 → grading.py → mastery.py → LearningScheduler

## 业务场景

一位物理教师想给"牛顿第二定律"这个知识点出几道练习题，学生做完后系统自动批改，并根据答题结果调整后续练习。


## 涉及的核心模块

| 步骤 | 模块 | 作用 |
|------|------|------|
| 1-2 | AgentCoordinator + LLM | 根据知识点生成题目 |
| 3 | 知识库 | 存储生成的题目 |
| 5 | grading.py | 自动评分 |
| 6 | classify_error() + LLM | 错误分类和深度诊断 |
| 7 | mastery.py | 计算掌握度 |
| 8 | LearningScheduler | 安排复习和学习路径 |

## 关键设计决策

1. **LLM 出题而非模板**：不同知识点的题目千差万别，用 LLM 出题更灵活、更自然
2. **三种题型不同评分策略**：选择题精确匹配、简答题模糊匹配、开放题关键词匹配
3. **错误诊断两层**：先快速判断 blank/wrong，再 LLM 深度分析
4. **掌握度不是简单平均**：recency-weighted + confidence cap，更科学

```
教师/学生请求出题
    │
    ▼
AgentCoordinator 接收出题请求
    │
    ├── 模式1: 基于知识点出题
    │   ├── 输入: 知识点列表
    │   ├── 查询知识库获取相关教材内容
    │   ├── LLM 生成题目（题型、难度、题干、答案）
    │   └── 返回题目列表
    │
    ├── 模式2: 基于考试要求出题
    │   ├── 输入: 考试类型、年级、科目
    │   ├── 查询知识库获取对应教材
    │   ├── LLM 生成模拟试卷
    │   └── 返回试卷
    │
    └── 模式3: 自适应出题
        ├── 输入: 学生历史答题数据

```

### 详细步骤说明

**Step 1: 出题请求解析**

`AgentCoordinator` 解析出题请求，提取：
- 出题模式（知识点 / 考试 / 自适应）
- 目标知识点（可选）
- 题目数量
- 难度要求
- 题型偏好（选择 / 填空 / 简答 / 编程）

**Step 2: 知识库检索**

根据出题模式，从知识库检索相关教材内容：
- 知识点模式：检索对应知识点的教材章节
- 考试模式：检索对应年级/科目的全部教材
- 自适应模式：检索学生薄弱知识点相关的教材

**Step 3: LLM 生成题目**

将检索结果和出题要求拼接成 Prompt，发送给 LLM：

Prompt 包含：
- 教材内容（作为出题依据）
- 出题要求（题型、难度、数量）
- 输出格式（JSON Schema）
- 示例题目（Few-shot）

LLM 返回的题目结构：
- `question_text`：题面
- `question_type`：题型
- `correct_answer`：正确答案
- `explanation`：解析
- `knowledge_points`：关联知识点
- `difficulty`：难度（1-5）
- `hints`：提示列表

**Step 4: 题目验证**

生成的题目需要验证：
- 答案正确性：用 LLM 二次验证
- 难度合理性：检查难度是否在要求范围内
- 格式完整性：检查 JSON 结构是否完整
- 去重：与已有题目比较，避免重复

**Step 5: 题目入库**

验证通过的题目：
- 保存到题库
- 关联知识点
- 设置元数据（创建时间、来源等）

### 学生答题评分流程

```
学生查看题目
    │
    ▼
学生提交答案
    │
    ▼
grade_answer() 评分
    │
    ├── 选择题 → 精确匹配
    ├── 填空题 → 模糊匹配 (>85%)
    ├── 简答题 → 关键词匹配 (>60%)
    ├── 编程题 → 代码执行
    └── 开放题 → LLM 评估
    │
    ▼
如果正确 → 更新掌握度 (+positive)
    │
    ▼
如果错误 → classify_error() 分类
    │
    ├── NOT_ATTEMPTED → 知识点盲区
    ├── WRONG_APPLICATION → 理解偏差
    ├── PARTIAL → 需要强化
    └── MISCONCEPTION → 需要重新学习
    │
    ▼
compute_mastery() 更新掌握度
    │
    ▼
生成反馈
    │
    ├── 正确 → 鼓励 + 扩展
    └── 错误 → 针对性讲解 + 提示
    │
    ▼
学习调度器更新学习路径
    │
    ▼
返回评分结果给前端
```

### 出题与评分的数据流

**出题时涉及的数据**：
- 知识库 → 教材内容
- 题库 → 已有题目（去重）
- 用户配置 → 难度偏好、题型偏好

**评分时涉及的数据**：
- 答题记录 → 写入 Notebook
- 掌握度 → 更新 MasteryRecord
- 学习路径 → 更新调度器

**评分后的影响**：
- 掌握度变化 → 影响后续出题难度
- 错误类型 → 影响学习路径调整
- 答题历史 → 影响间隔重复调度



### 出题质量保障

**题目质量检查**：
1. 答案可验证性：每道题必须有明确的正确答案
2. 难度一致性：同批次的题目难度应该相近
3. 知识点覆盖：确保覆盖指定的知识点
4. 无歧义：题目表述清晰，不存在歧义

**题目反馈机制**：
- 学生可以标记"题目有问题"
- 教师可以手动审核和修改题目
- 系统根据答题数据自动调整题目难度标签
- 低质量题目（所有人都答错或都答对）自动标记

### 总结

出题与评分是 DeepTutor 教学闭环的核心环节。从出题到答题到评分到反馈，每个步骤都经过精心设计，确保：
- 题目有针对性（基于学生薄弱点）
- 评分有依据（基于明确规则或 LLM 评估）
- 反馈有价值（指出错误原因和改进方向）
- 数据可追踪（每次答题都记录，用于优化学习路径）
