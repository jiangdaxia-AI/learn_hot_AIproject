# 核心流程：上传教材到可问答

> Understand-Anything 知识图谱: 26 节点, 25 边, 7 层
> 涉及模块：KnowledgeRouter → RAG 服务 → Embedding 服务 → 文档解析服务

## 业务场景

一位数学教师想把《高等数学》PDF 教材上传到 DeepTutor，让学生能基于这本教材提问。"第三章第五节的公式怎么推导？"——学生问完后，AI 应该从教材中找到对应内容来回答，而不是瞎编。

## 端到端流程

```
┌─────────────────────────────────────────────────────────────┐
│  Step 1: 教师上传 PDF                                        │
│  教师打开知识库管理页面                                       │
│  点击"新建知识库"→ 输入名称"高等数学"                         │
│  拖拽 PDF 文件到上传区域                                      │
│  前端调 POST /knowledge_bases → 创建知识库                   │
│  前端调 POST /knowledge_bases/{id}/files → 上传文件          │
└──────────────────────┬──────────────────────────────────────┘
                       ↓
┌──────────────────────────────────────────────────────────────┐
│  Step 2: API 层接收并存储原始文件                             │
│  KnowledgeRouter.upload_files()                              │
│  ├─ 验证文件类型（PDF/DOCX/MD/TXT）                          │
│  ├─ 保存到 raw/ 目录（原始文件存储）                          │
│  ├─ 创建上传任务（task_id）                                   │
│  └─ 返回"上传成功，正在处理..."                               │
└──────────────────────┬──────────────────────────────────────┘
                       ↓
┌──────────────────────────────────────────────────────────────┐
│  Step 3: 后台异步处理                                         │
│  DocumentAdder 后台任务启动                                   │
│  ├─ 读取 raw/ 目录下的文件                                    │
│  ├─ 调用文档解析服务（Parsing）                                │
│  │   ├─ PDF → PDF 解析器（MinerU / Docling）                  │
│  │   ├─ DOCX → DOCX 解析器                                    │
│  │   └─ MD → Markdown 解析器                                  │
│  ├─ 输出：纯文本                                               │
│  └─ 更新进度：解析完成                                         │
└──────────────────────┬──────────────────────────────────────┘
                       ↓
┌──────────────────────────────────────────────────────────────┐
│  Step 4: 文本切块（Chunking）                                  │
│  ├─ 把纯文本切成小块（每块约 512 tokens）                      │
│  ├─ 相邻块之间有 50 tokens 重叠（避免切断上下文）              │
│  ├─ 保留每块的来源信息（文件名、页码）                        │
│  └─ 更新进度：切块完成，共 N 块                                │
└──────────────────────┬──────────────────────────────────────┘
                       ↓
┌──────────────────────────────────────────────────────────────┐
│  Step 5: 向量化（Embedding）                                   │
│  ├─ 调用 Embedding 服务                                        │
│  ├─ 把每个文本块转成向量（一串数字，代表语义）                  │
│  ├─ 例如 "牛顿第二定律" → [0.12, -0.34, 0.56, ...]             │
│  └─ 更新进度：向量化完成                                       │
└──────────────────────┬──────────────────────────────────────┘
                       ↓
┌──────────────────────────────────────────────────────────────┐
│  Step 6: 存入向量数据库                                        │
│  ├─ 把向量和原文一起存入向量索引                               │
│  ├─ 默认用内存索引（开发环境）                                 │
│  ├─ 生产环境可配置 ChromaDB / Pinecone                        │
│  └─ 更新进度：索引完成                                         │
└──────────────────────┬──────────────────────────────────────┘
                       ↓
┌──────────────────────────────────────────────────────────────┐
│  Step 7: 知识库就绪                                            │
│  ├─ 知识库状态变为 "ready"                                     │
│  ├─ 前端显示"知识库已就绪，共 N 个文档，M 个文本块"            │
│  └─ 学生可以在聊天中选择这个知识库提问                          │
└──────────────────────────────────────────────────────────────┘
```

## 检索阶段流程

```
┌──────────────────────────────────────────────────────────────┐
│  Step 8: 学生提问                                              │
│  学生在聊天界面选择知识库"高等数学"                             │
│  输入问题："第三章第五节的公式怎么推导？"                       │
│  前端通过 WebSocket 发送消息                                   │
└──────────────────────┬──────────────────────────────────────┘
                       ↓
┌──────────────────────────────────────────────────────────────┐
│  Step 9: Agent 决定调用 RAG 工具                               │
│  AgentLoop 分析用户意图                                        │
│  → 判断需要从知识库检索信息                                    │
│  → 调用 RAGTool.execute(query="第三章第五节的公式怎么推导？")   │
└──────────────────────┬──────────────────────────────────────┘
                       ↓
┌──────────────────────────────────────────────────────────────┐
│  Step 10: RAG 服务检索                                         │
│  RAGService.query(kb_name="高等数学", query="...")            │
│  ├─ 把问题向量化                                              │
│  ├─ 在向量数据库中进行语义搜索                                 │
│  ├─ 找到最相似的 Top-5 文本块                                  │
│  └─ 返回检索结果（带来源信息）                                 │
└──────────────────────┬──────────────────────────────────────┘
                       ↓
┌──────────────────────────────────────────────────────────────┐
│  Step 11: LLM 生成回答                                         │
│  Agent 把检索结果作为上下文传给 LLM                             │
│  System Prompt: "基于以下教材内容回答用户问题..."               │
│  + 检索到的 Top-5 文本块                                       │
│  + 用户问题                                                    │
│  ↓                                                            │
│  LLM 生成回答："根据《高等数学》第三章第五节，该公式推导如下..." │
│  ↓                                                            │
│  前端展示回答 + 引用来源标签                                   │
└──────────────────────────────────────────────────────────────┘
```

## 涉及的核心模块

| 步骤 | 模块 | 作用 |
|------|------|------|
| 1-2 | KnowledgeRouter | API 层接收文件、创建知识库 |
| 3 | 文档解析服务 | PDF/DOCX → 纯文本 |
| 4 | RAG 服务（Chunking） | 文本切块 |
| 5 | Embedding 服务 | 文本 → 向量 |
| 6 | RAG 服务（Indexing） | 向量存入索引 |
| 8-9 | AgentLoop + RAGTool | Agent 决定调用 RAG |
| 10 | RAG 服务（Query） | 语义检索 |
| 11 | LLM 服务 | 生成最终回答 |

## 时间估算

- 小型 PDF（<50 页）：约 30 秒 - 1 分钟
- 中型 PDF（50-200 页）：约 1-3 分钟
- 大型 PDF（>200 页）：约 3-10 分钟

前端通过 WebSocket 接收实时进度更新，教师可以看到"解析中... → 切块中... → 向量化中... → 完成"。

### 详细步骤说明

**Step 1: 文件接收**

教师在前端选择文件并上传。前端通过 `/knowledge_bases/{kb_id}/upload` 接口上传文件。支持：
- 单文件上传
- 批量上传
- 文件夹上传（保留目录结构）
- 拖拽上传

文件保存到 `data/knowledge_bases/{kb_name}/raw/` 目录。

**Step 2: 文档解析**

`DocumentParser` 服务检测文件类型并选择合适的解析器：

| 文件类型 | 默认解析器 | 备选解析器 |
|----------|-----------|-----------|
| PDF（学术论文） | MinerU | PyPDF2, pdfplumber |
| PDF（一般文档） | Docling | PyPDF2, pdfplumber |
| DOCX | Docling | python-docx |
| Markdown | markdown-it | 内置解析 |
| TXT | 直接读取 | - |

**Step 3: 文本切块**

切块策略影响检索质量：

- **语义切块**：按段落和标题层级切分，保持语义完整性
- **固定大小切块**：每块 500-1000 字符
- **重叠窗口**：相邻块重叠 200 字符，防止语义断裂
- **元数据保留**：每块保留来源文件名、页码、章节标题

**Step 4: 向量化与索引**

向量化过程：
1. 每个 chunk 通过 Embedding 模型转换为向量（通常 768 或 1536 维）
2. 向量存储在向量数据库中
3. 构建索引以支持快速检索

支持的 Embedding 模型：
- OpenAI text-embedding-3-small/large
- Cohere embed-v3
- Jina embeddings
- 本地模型（通过 Ollama）

**Step 5: 状态更新与通知**

处理完成后：
- 知识库状态从 `processing` 变为 `ready`
- 更新统计信息（文档数、chunk 数、总大小）
- 通过 WebSocket 通知前端
- 前端刷新知识库列表

### 关键设计决策

**为什么用后台任务而非同步处理**：
- 大文件解析可能需要几分钟
- 同步处理会阻塞 API 响应
- 后台任务支持进度追踪

**为什么支持多种解析器**：
- 不同文档类型需要不同的解析策略
- 学术 PDF 需要保留公式和表格
- Office 文档需要保留格式信息

**为什么切块有重叠**：
- 防止关键信息正好落在切块边界
- 提高检索召回率
- 代价是存储空间增加约 20%



### 异常处理

**上传失败**：
- 网络中断：支持断点续传
- 文件过大：前端限制 + 后端校验
- 格式不支持：返回友好提示，列出支持的格式

**解析失败**：
- 加密 PDF：提示用户解除密码保护
- 扫描版 PDF：提示需要 OCR 处理
- 损坏文件：跳过并记录日志

**处理超时**：
- 大文件处理设置超时时间
- 超时后自动重试
- 3 次重试失败后标记为 error

### 性能数据

| 文件大小 | 解析时间 | 向量化时间 | 总处理时间 |
|----------|---------|-----------|-----------|
| 1MB PDF | ~10s | ~5s | ~15s |
| 10MB PDF | ~60s | ~30s | ~90s |
| 50MB PDF | ~5min | ~2min | ~7min |

以上为估算值，实际时间取决于硬件配置和选择的 Embedding 模型。

### 多知识库管理

**知识库切换**：
- 学生可以在聊天界面切换知识库
- 不同知识库对应不同教材/科目
- 切换后，RAG 检索自动切换到新知识库

**知识库共享**：
- 教师可以把自己的知识库分享给其他教师
- 支持只读共享和编辑共享
- 共享知识库的更新自动同步


### 常见问题排查

**问题：上传后知识库一直显示"处理中"**
- 可能原因：后台任务卡住或失败
- 排查方法：查看日志中的 `run_upload_processing_task` 执行记录
- 解决方案：重新触发处理或手动重启任务

**问题：检索结果不准确**
- 可能原因：文档切块策略不合适、Embedding 模型不匹配
- 排查方法：检查切块大小、重叠窗口、Embedding 模型配置
- 解决方案：调整切块参数、更换 Embedding 模型、重新索引

**问题：大文件上传失败**
- 可能原因：文件大小超过限制、网络超时
- 排查方法：检查前端和后端的文件大小限制
- 解决方案：拆分大文件、调整超时时间、使用断点续传

### 最佳实践

1. **文档准备**：上传前确保文档质量好（非扫描版、格式规范）
2. **命名规范**：使用有意义的文件名和知识库名称
3. **分批上传**：大量文档分批上传，避免同时处理
4. **定期更新**：教材更新后及时同步知识库
5. **测试检索**：上传后用几个问题测试检索效果
