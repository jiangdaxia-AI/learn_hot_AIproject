## 一句话定位

jcode 是一个用 Rust 编写的下一代终端 AI 编码代理。不像 IDE 插件，它住在终端里——你给它任务描述，它自主规划、调用工具、读写文件，直到完成。

## 目标用户

独立开发者: 终端里快速实现功能、修 bug
技术负责人: 代码审查、自动化重构
开源维护者: 处理 issue、review PR，多会话并发
学习者: 理解代码库、画出架构图

## 核心痛点与解决方案

1. AI 记不住: 三级记忆系统(L1/L2/L3)，跨会话记住偏好
2. 大项目搜不动: 本地 ONNX 向量嵌入，语义搜索整个代码库
3. 单 Agent 能力有限: Swarm 多 Agent 协调，分工协作
4. 模型被锁定: 8+ Provider，一行配置切换
5. 资源占用大: Rust 原生编译，单会话 27.8MB
6. 终端体验差: 全功能 TUI，Markdown/Mermaid 渲染

## 技术栈

Rust: 主力语言，1100 个 .rs 文件
Tokio: 异步运行时，支撑并发 Agent
Ratatui: 终端 UI 框架
ONNX Runtime: 本地向量嵌入引擎
Tree-sitter: 代码语法解析
SQLite: 本地数据持久化

## 核心设计理念

1. 一切在终端: 不依赖 IDE，命令行即全部
2. 多 Agent 协作: Swarm 模式让多个 Agent 像团队一样工作
3. 本地优先: 嵌入和搜索在本地完成，数据不出本机
4. Provider 无关: 通过统一的 Provider 抽象层，支持任意 LLM
5. 极致性能: Rust 编译为原生二进制，启动快、内存小

## 四、技术栈全景

### 4.1 核心语言：Rust

jcode 几乎 100% 用 Rust 编写。为什么选 Rust？

- **性能**：Rust 编译为原生机器码，没有垃圾回收器（GC）的停顿，启动极快
- **内存安全**：Rust 的所有权系统在编译时保证内存安全，不会有内存泄漏或悬垂指针
- **资源效率**：Rust 程序的内存占用极低，这对多会话场景至关重要

白话解释：Rust 就像是一个超级严格的质检员，在你写代码的时候就检查出所有内存问题，而不是等程序崩溃了才发现。代价是写起来更难，但换来的是运行时的极致性能。

## 五、项目规模与架构层次

jcode 的代码组织非常清晰，按照功能分为 **7 个架构层次**：

### 第 1 层：入口层（Entry Layer）

**模块**：CLI 命令分发

这是 jcode 的大门。当你输入 jcode 命令时，这一层负责解析你的意图：
- 你想打开交互式界面？路由到 TUI
- 你想直接运行一条命令？路由到 Agent
- 你想启动服务器？路由到 Server 模式

### 第 2 层：应用编排层（App Orchestration Layer）

**模块**：应用核心

这是 jcode 的大脑中枢。它负责管理所有子系统的生命周期：启动 Agent、初始化会话、连接 TUI 界面、处理通知、管理更新。所有模块都通过这一层协调工作。

### 第 3 层：Agent 层（Agent Layer）

**模块**：Agent 运行时、Swarm 蜂群协调、计划引擎

这是 jcode 的灵魂所在。Agent 运行时是一个循环引擎：
1. 接收你的指令
2. 调用 AI 模型分析
3. 决定需要什么工具
4. 执行工具调用
5. 返回结果
6. 重复直到任务完成

**Swarm 蜂群协调**让多个 Agent 同时工作，**计划引擎**负责把复杂任务拆解成可执行的步骤。

### 第 4 层：TUI 界面层（Terminal UI Layer）

**模块**：TUI 终端界面、桌面应用

这是你看到的界面。jcode 的终端 UI 支持：
- Markdown 渲染（代码高亮、表格、列表）
- Mermaid 图表渲染（比传统方案快 1800 倍）
- 信息小部件（只在屏幕空白处显示，不占主空间）
- 侧边栏（实时显示文件内容、diff 对比）
- 千帧级渲染（你的显示器刷新率都追不上）

### 第 5 层：工具层（Tool Layer）

**模块**：工具核心、模糊搜索、PDF 处理

jcode 内置 **30+ 工具**，涵盖：
- 文件操作（读写、搜索、替换）
- 代码执行（运行 shell 命令、脚本）
- 浏览器自动化（Firefox 控制）
- Git 操作
- 网络请求
- 代码搜索（Agent Grep：不仅搜文本，还返回函数列表、结构信息）

### 第 6 层：服务层（Service Layer）

**模块**：多 Provider 体系、记忆系统、会话管理、上下文压缩、向量嵌入

这是 jcode 的核心竞争力所在：
- **记忆系统**：自动提取、存储、检索对话记忆
- **上下文压缩**：长对话自动总结，保留关键信息
- **向量嵌入**：本地 ONNX 模型，语义搜索和记忆检索
- **会话管理**：多会话隔离、历史浏览、跨工具会话导入

### 第 7 层：基础设施层（Infrastructure Layer）

**模块**：配置管理、认证系统、日志系统、构建系统、遥测系统、导入系统

支撑整个系统运行的基础设施。

## 为什么用 Rust

Rust 是 jcode 选择的技术栈，原因很明确:
1. 性能: 直接编译为机器码，没有运行时开销
2. 内存安全: 编译期检查内存错误，不会出现野指针和内存泄漏
3. 并发: Tokio 异步运行时，轻松处理多 Agent 并发
4. 单二进制: 编译后是一个独立可执行文件，无需安装依赖
5. 跨平台: 一套代码编译到 macOS/Windows/Linux
6. 生态: crates.io 上有丰富的库，Tree-sitter/Ratatui 等都是 Rust 生态的明星项目

对于需要高效编程工具的开发者来说，jcode 提供了一个轻量、快速、可定制的选择。

## 七、核心设计理念

### 7.1 性能至上（Performance First）

jcode 的设计哲学是把性能榨到极致。这不是一句口号，而是贯穿整个代码库的指导思想：

- **用 Rust 替代 TypeScript**：几乎所有竞品都用 TypeScript/JavaScript，jcode 是唯一用 Rust 的
- **自定义渲染引擎**：Mermaid 图表渲染比传统方案快 1800 倍
- **自定义滚动实现**：绕过终端原生的滚动限制
- **自定义终端**：作者甚至自己写了一个终端（Handterm），只为解决原生终端的滚动限制

白话解释：作者认为，AI 编程工具的性能瓶颈不在 AI 模型本身，而在工具链。AI 模型已经很快了，但工具启动慢、渲染慢、内存占用大，拖了后腿。jcode 的目标是让工具本身零感知延迟。

### 7.2 多 Agent 协作（Swarm First）

jcode 不是一个 AI + 一个你的模式，而是一群 AI + 一个你的模式。

Swarm 架构的核心思想：
- **蜂后（Coordinator）**：接收你的指令，分解任务，分配工作
- **工蜂（Worker Agents）**：并行执行子任务，互相通信
- **自动冲突解决**：当 Agent A 修改了 Agent B 正在读的文件，系统会自动通知并协调
- **深度蜂群模式**：Agent 可以继续派生子 Agent，形成多级协作树

### 7.3 人脑式记忆（Memory as a Graph）

jcode 的记忆系统不是简单的保存对话记录，而是模仿人脑的关联记忆：

- **自动提取**：每轮对话后，系统自动提取关键信息
- **向量存储**：每条记忆被编码为向量（一组数字），存储在图中
- **语义检索**：新对话时，系统自动搜索最相关的记忆
- **级联激活**：找到一条记忆后，沿着关联边找到更多相关记忆
- **自动整理**：Ambient 模式会定期整理记忆，合并重复、删除过时、标记冲突

### 7.4 无限定制（Self-Development）

jcode 的自我开发模式是一个独特的设计：你可以让 jcode 修改自己的源代码。

这意味着：
- 你可以让 jcode 学会新的工具或技能
- 你可以让 jcode 改变自己的行为模式
- 你可以让 jcode 修复自己的 bug
- 整个过程自动编译、测试、热加载

白话解释：其他 AI 工具像是成品菜，你只能吃固定的菜单。jcode 让你可以进厨房自己炒菜，想加什么调料加什么调料。

### 7.5 Provider 中立（Provider Agnostic）

jcode 不绑定任何 AI 模型提供商。你可以用：
- 你已有的订阅（Claude Pro、ChatGPT Plus、Copilot）
- 你自己的 API Key
- 本地运行的模型（完全离线）
- 任何兼容 OpenAI API 的服务

这种设计意味着你永远不会被锁定在某一家 AI 公司。

### 7.6 离线优先 + 本地智能

jcode 的向量嵌入引擎运行在本地（ONNX 模型），不需要联网。记忆系统完全在本地运行。这意味着：
- 你的代码和数据不会离开你的机器
- 在网络受限的环境中也能用
- 记忆检索没有网络延迟

### 7.7 终端原生（Terminal Native）

jcode 认为终端才是开发者的家。它不依赖浏览器、不需要 Electron、不启动图形界面。这带来一系列好处：
- 在 SSH 远程服务器上无缝运行
- 可以和 tmux、screen 等终端复用器配合
- 可以在 CI/CD 流水线中运行
- 启动快、资源少

## 八、功能模块详解（用大白话）

### 8.1 Agent 运行时：AI 的大脑循环

Agent 运行时是 jcode 最核心的模块。你可以把它想象成一个思考-行动循环：

1. **思考**：AI 分析你的指令，决定下一步做什么
2. **行动**：调用工具（读文件、运行命令、搜索代码等）
3. **观察**：查看工具返回的结果
4. **重复**：直到任务完成

这个循环会一直运行，直到 AI 认为任务完成，或者你手动中断。

### 8.2 Swarm 蜂群：让多个 AI 一起干活

如果你有一个大任务（比如重构整个认证模块），一个 AI 从头做到尾会很慢。Swarm 模式的做法是：

1. **分解**：主 Agent 把任务拆成子任务（改数据库层、改 API 层、改前端、写测试）
2. **派发**：每个子任务派给一个子 Agent
3. **并行**：子 Agent 同时工作，互不阻塞
4. **协作**：Agent 之间可以互相发消息、通知文件变更
5. **汇总**：主 Agent 收集所有结果，做最终整合

### 8.3 记忆系统：让 AI 记住关于你的一切

jcode 的记忆系统有三层：

**第一层：自动记忆**
- 每轮对话后，系统自动提取你觉得重要的信息
- 比如用户偏好 pnpm 而不是 npm、项目使用 PostgreSQL 数据库
- 这些记忆被编码为向量，存储在本地

**第二层：语义检索**
- 新对话开始时，系统自动搜索与当前话题最相关的记忆
- 比如你问数据库怎么连，系统会检索到这个项目用的 PostgreSQL
- 这些记忆被自动注入到 AI 的上下文中，不需要你手动提醒

**第三层：记忆整理**
- Ambient 模式会定期检查记忆：有没有重复的？有没有过时的？有没有冲突的？
- 自动合并、删除、标记，保持记忆库的整洁

### 8.4 上下文压缩：长对话不爆内存

每轮对话都会消耗 AI 的上下文窗口（context window，可以理解为 AI 的短期记忆容量）。对话太长，上下文窗口满了，AI 就会忘记最开始的对话。

jcode 的上下文压缩技术：
- 自动检测对话是否过长
- 将早期对话总结为简短的摘要
- 保留关键信息，丢弃冗余内容
- 确保 AI 始终能看到最重要的上下文

### 8.5 计划引擎：让 AI 先想清楚再做

很多 AI 工具是走一步看一步的。它不知道整个任务有多大，只是闷头干活。jcode 的计划引擎会先让 AI 制定一个完整的执行计划，然后按计划一步步执行。

这就像盖房子：有图纸再施工，比边盖边想要靠谱得多。

### 8.6 浏览器自动化：让 AI 操作网页

jcode 内置了浏览器自动化工具，通过 Firefox Agent Bridge 实现：
- 可以打开网页、截图、点击按钮、填写表单
- 可以提取网页内容进行分析
- 可以在 Web 应用中进行端到端测试

### 8.7 会话导入：从其他工具无缝迁移

你不必从零开始。jcode 支持从以下工具导入会话：
- Claude Code
- Codex CLI
- OpenCode
- pi

如果你的 Claude Code 崩溃了，可以无缝切换到 jcode，从上次中断的地方继续。

## 十、技术亮点深挖

### 10.1 为什么 Rust 是关键竞争力

在 AI 编程工具领域，语言选择不是喜好问题，而是战略决策。

**竞品都用的 TypeScript/JavaScript**：
- 优点：开发快，生态丰富
- 缺点：启动慢（需要加载 Node.js 运行时），内存占用大（V8 引擎 + GC），单线程模型受限

**jcode 用的 Rust**：
- 优点：启动极快（原生二进制），内存占用极低（无 GC），真正的并发
- 缺点：开发门槛高，编译慢

jcode 作者选择了更难的路，但换来了不可逾越的性能壁垒。竞品如果想追上 jcode 的性能，几乎需要重写整个代码库。

### 10.2 自定义 Mermaid 渲染器

jcode 作者自己写了一个 Mermaid 渲染器（mermaid-rs-renderer），比传统方案快 1800 倍。

传统方案：用浏览器或 Node.js 渲染 Mermaid，转换为图片，在终端显示
jcode 方案：Rust 原生渲染，直接输出到终端

为什么这很重要？在 AI 编程场景中，AI 经常需要输出架构图、流程图、时序图来帮助理解代码结构。如果每次渲染图都要等一秒，体验会很差。jcode 做到了几乎瞬间。

### 10.3 Agent Grep：为 AI 优化的代码搜索

jcode 的 Agent Grep 不是普通的 grep。它会在搜索结果中附加：
- 文件中的函数列表
- 每个函数的位置偏移
- 文件结构概览

这样 AI 不需要额外读取文件就能大致了解文件内容，大幅节省了上下文窗口的消耗。

### 10.4 Claude 缓存感知

jcode 对 AI 模型的底层行为有深入理解。比如 Claude 的缓存机制：

- Claude 会在 5 分钟内保持上下文缓存（省 tokens）
- 超过 5 分钟，缓存过期，下次调用会多花很多 tokens
- jcode 的 UI 会主动提醒你缓存过期，甚至告诉你是否有意外的缓存丢失

这种对细节的关注，体现了 jcode 作为工程师的工具的产品哲学。

## 十二、总结：jcode 的独特价值

### 12.1 三个关键词

1. **性能**：不是快一点，是快一个数量级
2. **协作**：不是一个 AI，是一群 AI 协同工作
3. **记忆**：不是每次都从零开始，是越用越了解你

### 12.2 与竞品的本质差异

大多数 AI 编程工具是 AI 模型 + 聊天界面。jcode 是 AI 模型 + 操作系统。

聊天界面只能做一件事：你问，AI 答。操作系统可以管理多个进程、协调资源、记住状态、自动化任务。

jcode 的野心不是做一个更好的聊天框，而是成为**开发者与 AI 协作的操作系统**。

### 12.3 适合谁？

- 如果你每天在终端里工作超过 4 小时，jcode 可能是你今年最重要的工具
- 如果你需要同时管理多个技术任务，jcode 的 Swarm 模式会改变你的工作方式
- 如果你对 AI 工具的性能和定制化有极致要求，jcode 是目前唯一的选择
- 如果你需要在远程服务器上使用 AI 编程助手，jcode 是原生方案

### 12.4 不适合谁？

- 如果你更喜欢图形界面，jcode 的终端 UI 可能不适合你
- 如果你只需要简单的代码补全，IDE 内置的 Copilot 已经够用
- 如果你在 Windows 上主要用 WSL 之外的工具，jcode 的 Windows 支持还在完善中
