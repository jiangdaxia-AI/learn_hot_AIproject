# 03-09 · 安全与护栏 — 深度剖析

> **文件数**：src/lib/auth/ + src/lib/guardrails/ + src/server/authz/ | **认证**：5 种方式 | **护栏**：4 种防护

---

## 定位

安全层是 OmniRoute 的"门禁系统"。它确保：只有授权的人能访问、每个请求都在配额内、AI 不会输出危险内容。

> 来源：src/lib/auth/、src/lib/guardrails/、src/server/authz/assertAuth.ts

---

## 生活化比喻

> 安全层像**高档写字楼的安保系统**：
> - 门禁卡（API Key）——刷卡进门
> - 访客登记（OAuth 2.0）——临时授权进入
> - 安检门（AuthZ Pipeline）——检查是否携带违禁品
> - 监控摄像头（审计日志）——记录所有出入
> - 楼层权限（护栏）——普通访客不能进机房

## 一、5 种认证方式

| 方式 | 大白话 | 适用场景 |
|------|--------|---------|
| **API Key** | 像门禁卡，刷卡就能进 | 程序调用 API |
| **OAuth 2.0** | 像微信扫码登录，第三方授权 | 绑定第三方 AI 服务 |
| **CommandCode Auth** | 像验证码，输入代码验证 | Codex 设备码认证 |
| **Keychain 导入** | 像从钥匙串导入钥匙（Zed 客户端） | macOS 用户 |
| **Dashboard Login** | 像网站登录，输入用户名密码 | 管理控制台 |

> 来源：src/lib/auth/、src/lib/oauth/、src/lib/db/commandCodeAuth.ts

## 三、CommandCode Auth — 5 步设备码认证

### 问题

Codex 这类工具不能直接弹出浏览器让你登录，需要一种"设备码"方式——工具显示一个验证码，你在浏览器输入验证码，完成授权。

### 解决方案

CommandCode Auth 实现了完整的设备码认证流程：

### 内部算法：5 步状态机

```
步骤 1：创建待处理会话
  - createPendingCommandCodeAuthSession()
  - 状态：PENDING（等待中）
  大白话：生成一个验证码，显示给用户

步骤 2：用户输入验证码
  - 用户在浏览器输入验证码
  - 状态：RECEIVED（已接收）
  大白话：用户确认授权

步骤 3：消耗密钥
  - consumeCommandCodeAuthSecret()
  - 状态：CONSUMED（已消耗）
  大白话：验证码只能用一次，用完作废

步骤 4：获取安全状态
  - getCommandCodeAuthSessionSafeStatus()
  大白话：检查授权是否成功

步骤 5：返回 Token
  - 返回 Access Token 给工具
  - 工具用 Token 调用 API
  大白话：工具拿到"门禁卡"，可以正常使用了
```

> 来源：src/lib/db/commandCodeAuth.ts

## 四、4 种护栏

| 护栏 | 大白话 | 实现 |
|------|--------|------|
| 速率限制 | 限制每个用户/提供商每秒能发多少请求 | guardrails/ 模块 |
| 内容过滤 | 检查 AI 的输出是否包含危险内容 | guardrails/ 模块 |
| 配额管理 | 限制每个提供商每月能用多少 token | ProviderPlan 配额维度 |
| 审计日志 | 记录所有 API 调用，谁在什么时候做了什么 | audit/ 模块 |

> 来源：src/lib/guardrails/、src/lib/audit/、src/lib/db/providerPlans.ts
