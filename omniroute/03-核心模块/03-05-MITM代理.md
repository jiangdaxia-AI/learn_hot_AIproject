## 定位

MITM 代理是 OmniRoute 的"隐形拦截器"。它不需要你安装任何插件——你正常使用 Codex/Cursor/Windsurf 等 AI 编程工具，MITM 代理在后台悄悄拦截请求，替换成 OmniRoute 管理的提供商，让你用免费额度或自己的 API Key。

> 来源：src/mitm/inspector/httpProxyServer.ts L35 HttpProxyServerHandle

---

## 生活化比喻

> MITM 代理像**机场的航班中转服务**：
> - 你的航班（AI 请求）本来直飞目的地（直接连 OpenAI），但中转站（MITM）自动帮你换乘更便宜的航班（用 OmniRoute 的提供商）
> - 你全程不需要做任何操作，登机牌（API 请求格式）不变
> - 中转站还帮你省了机票钱（用免费额度或批量折扣）

## 一、HttpProxyServerHandle — 代理服务器

### 问题

AI 编程工具（Codex/Cursor/Windsurf）直接连接各自的 AI 服务器，用户无法控制用哪个提供商。

### 解决方案

MITM 代理在本地启动一个 HTTP 代理服务器，拦截所有发往 AI 服务器的请求，替换为 OmniRoute 管理的提供商。

### 内部流程：6 步拦截

```
编程工具发送 API 请求
  │
  ▼
步骤 1：startHttpProxyServer() — 启动代理
  - 默认端口：DEFAULT_PORT
  大白话：在本地启动一个"拦截站"，监听所有流量

步骤 2：请求到达 → 匹配目标
  - 检查请求的域名（host）是否在拦截列表中
  - 比如：api.openai.com → 匹配
  大白话：看看这个请求是不是发给我们关心的 AI 服务

步骤 3：提取请求信息
  - 请求路径、请求体、请求头
  大白话：拆开"信封"，看看里面写的什么

步骤 4：替换提供商
  - 原始请求 → OpenAI API → 替换为 OmniRoute 管理的提供商
  大白话：把"寄给 OpenAI"改成"寄给 OmniRoute"

步骤 5：转发请求
  - 通过 OmniRoute 的 SSE 代理发送
  大白话：用 OmniRoute 的"快递通道"发出

步骤 6：返回结果
  - 结果原路返回给编程工具
  大白话：把回复原样送回，工具完全不知道被拦截了
```

> 来源：src/mitm/inspector/httpProxyServer.ts

## 三、关键设计决策

| 设计决策 | 大白话 |
|----------|--------|
| 透明代理 | 编程工具完全不知道被拦截，不需要改任何代码 |
| 目标描述符模式 | 新增一个 AI 工具只需写一个配置文件 |
| 根证书安装 | 代理需要安装根证书才能解密 HTTPS 流量 |
| 手动开启 | 代理默认关闭，用户主动开启，避免意外拦截 |
