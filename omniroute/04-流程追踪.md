## 场景 1：用户通过 API 发送聊天请求

**用户视角：** 你是一个开发者，写了一个 Python 程序调用 OmniRoute 的 API。你发送"帮我写一首关于夏天的诗"，2 秒后收到一首完整的诗。你完全不知道背后发生了 10 个步骤——提供商选择、故障转移、压缩——OmniRoute 全自动处理了。

### 完整时序图

```
你的程序          OmniRoute网关      代理引擎          提供商A        提供商B
  │                   │                 │                 │              │
  │ POST /v1/chat     │                 │                 │              │
  │──────────────────▶│                 │                 │              │
  │                   │ 12步安检        │                 │              │
  │                   │ (验证身份/配额)  │                 │              │
  │                   │───────────────▶│                 │              │
  │                   │                 │ Combo选择       │              │
  │                   │                 │────────────────▶│              │
  │                   │                 │  限流！❌        │              │
  │                   │                 │◀────────────────│              │
  │                   │                 │ 故障转移        │              │
  │                   │                 │─────────────────────────────▶│
  │                   │                 │  成功！✅                     │
  │                   │                 │◀─────────────────────────────│
  │                   │                 │ 压缩回复        │              │
  │                   │◀────────────────│                 │              │
  │◀──────────────────│                 │                 │              │
  │ 收到诗 (耗时 ~2-3秒)                                              │
```

### 流程步骤

1. 你的程序发送 HTTP POST 到 OmniRoute（格式和 OpenAI 兼容）
2. 网关进行 12 步安检：验证身份、检查请求大小、CSRF 防护、CORS 处理
3. 代理引擎通过 Combo 选择最优提供商（按优先级/成本）
4. 向首选提供商 A 发送请求
5. 提供商 A 返回限流错误（429 Too Many Requests）→ 触发故障转移
6. ComboCooldownRetry 决定切换到提供商 B：计算冷却时间，选择下一个提供商
7. 向提供商 B 发送请求 → 成功返回
8. 压缩引擎压缩回复内容（RTK + Caveman）
9. 结果返回给你的程序
10. 用量记录写入数据库（token 数、费用、耗时）

## 场景 2：MITM 拦截 Codex 请求

**用户视角：** 你在 VS Code 里用 Codex 写代码。按下 Tab 键，AI 自动补全了一行代码。你完全不知道这个补全不是来自 OpenAI 的服务器，而是来自你配置的 OmniRoute 提供商（比如 Claude）。整个过程对 VS Code 完全透明，Codex 以为自己连的是 OpenAI。

### 完整时序图

```
VS Code (Codex)     MITM代理           OmniRoute引擎     你的提供商(Claude)
  │                   │                   │                    │
  │ API请求→api.openai │                   │                    │
  │──────────────────▶│                   │                    │
  │                   │ 匹配目标(Codex)    │                    │
  │                   │ 提取请求体         │                    │
  │                   │──────────────────▶│                    │
  │                   │                   │ 替换提供商         │
  │                   │                   │ (OpenAI→Claude)   │
  │                   │                   │──────────────────▶│
  │                   │                   │◀──────────────────│
  │                   │◀──────────────────│                    │
  │◀──────────────────│                   │                    │
  │ 收到补全代码                                                  │
```

### 流程步骤

1. VS Code 的 Codex 插件发送 API 请求到 api.openai.com
2. MITM 代理拦截请求，匹配到 Codex 目标
3. 提取请求体（prompt、参数）
4. 转发给 OmniRoute 引擎，引擎替换提供商为 Claude
5. Claude 返回结果
6. 结果原路返回给 VS Code
7. VS Code 完全不知道被拦截了，正常显示补全

## 场景 3：Combo 自动故障转移

**用户视角：** 你配置了一个 Combo（提供商组合），包含 OpenAI 和 Claude，优先级 OpenAI > Claude。你发了一个请求，OpenAI 返回"余额不足"，系统自动切换到 Claude。你收到的回复完全正常，不知道发生了切换。

### 完整时序图

```
你的程序          OmniRoute          OpenAI            Claude
  │                   │                 │                 │
  │ POST /v1/chat     │                 │                 │
  │──────────────────▶│                 │                 │
  │                   │ Combo选择OpenAI │                 │
  │                   │────────────────▶│                 │
  │                   │ 402 余额不足 ❌  │                 │
  │                   │◀────────────────│                 │
  │                   │ 熔断器检查      │                 │
  │                   │ 非临时故障→跳过  │                 │
  │                   │ Combo切换到Claude               │
  │                   │────────────────────────────────▶│
  │                   │ 200 OK ✅                        │
  │                   │◀────────────────────────────────│
  │◀──────────────────│                 │                 │
  │ 收到回复 (完全正常)                                              │
```

### 流程步骤

1. 你的程序发送请求
2. Combo 选择 OpenAI（优先级第一）
3. OpenAI 返回 402 Payment Required（余额不足）
4. 熔断器判断：这是"非临时故障"（不是网络问题），不可重试，直接跳过
5. Combo 切换到 Claude（优先级第二）
6. Claude 返回成功
7. 结果返回给你的程序
8. 用量记录：标记为"使用了 Combo 故障转移"
